## 目标

把已经归档但尚未接入的 Kenney Topdown Shooter 素材转为可复现的运行时资产，并完成以下视觉替换：

1. 战场地面、边界和低干扰环境细节使用位图素材。
2. 玩家替换为与俯视战场一致的 Kenney 幸存者形象，同时保留现有八把真实武器贴图和枪口逻辑。
3. 集装箱、废弃卡车、围墙、油桶、面粉桶和地雷改用位图主体。
4. 玩家子弹、敌方投射物、弹药、生命、道具和武器掉落改用位图主体。
5. 保持现有碰撞、伤害、对象池、掉落、关卡配置和场景流不变。

## 背景与已确认事实

1. Kenney Topdown Shooter 原始 ZIP、人物 PNG、许可证和瓦片图集已经位于
   `src/assets/downloaded/characters/kenney-topdown-shooter/`，许可证为 CC0 1.0。
2. 前一个 agent 已把 ZIP 中 526 张 `PNG/Tiles/tile_*.png`、瓦片表和完整 tilesheet 解压到工作区，但没有运行时引用，也没有执行文档。
3. 当前玩家使用 Ghostbyte 身体、持枪手臂和真实武器三层组合；武器枪口对齐已经通过历史 headless 验收。
4. 当前地面、障碍物、场景物、子弹和掉落物主体仍由 Phaser Graphics/Arc 程序绘制。
5. 工作区另有玩家、感染体和敌方投射物整体降速改动。本轮不回滚、不重新设计该数值，只在运行时验收时记录影响。
6. `npm run typecheck` 当前因测试文件缺少 Node 类型而失败；本轮需要恢复最小静态检查基线。

## 视觉方案

### 视觉主张

使用 Kenney 俯视像素素材统一战场材质和实体轮廓，保留项目现有低饱和灾后色调与漫画 HUD。正式战斗对象必须比地面和非碰撞细节拥有更高对比度，不能因为素材数量增加而降低危险预警、子弹和掉落物的可读性。

### 内容计划

1. 地面与边界：草地、泥地、混凝土和道路瓦片按关卡主题铺设；围墙位图形成世界边界。
2. 玩家与武器：使用 `Survivor 1/survivor1_hold.png` 作为朝右基准，真实武器继续叠在双手之间。
3. 战术主体：油桶、面粉桶、地雷、集装箱、废弃卡车和混凝土围墙使用独立透明 PNG。
4. 战斗反馈：子弹、敌方投射物和掉落物使用小尺寸位图；HUD 与危险区域继续使用现有高对比程序表现。

### 交互主张

1. 玩家移动只使用克制的呼吸/步幅缩放，不伪造不存在的方向动画。
2. 开火继续使用现有武器挤压和枪口闪光，枪口位置必须跟随新人物握持点重新校准。
3. 掉落物保留轻微悬浮和临近消失闪烁，标签只承担数量或 `NEW` 状态。

## 范围

1. 新增可重复执行的 Kenney 场景素材处理脚本。
2. 从原始 ZIP/瓦片中选择、裁剪和规范化运行时地面、装饰、场景物资源。
3. 生成缺失的同风格集装箱、废弃卡车、围墙、医疗箱、弹药箱和投射物透明 PNG。
4. 新增集中式环境素材键与类型映射，接入 Preload 最近邻采样。
5. 修改 `BattlefieldRenderer`、`Player`、`Obstacle`、`Prop`、`Pickup`、`Bullet` 和 `EnemyProjectile` 的视觉实现。
6. 更新资源台账、README 和自动化校验。

## 不做项

1. 不调整关卡波次、伤害、掉落概率、碰撞尺寸和场景物坐标。
2. 不改变感染体素材和行为系统。
3. 不新增 Phaser 之外的运行时依赖。
4. 不制作角色方向动画、分武器持枪动画或新的玩法系统。
5. 不删除前一个 agent 的未提交速度改动和已解压原始素材。
6. 不执行 `npm run build`。

## 操作步骤

1. 建立资产清单和稳定输出命名，脚本只读取已归档 ZIP 或解压目录。
2. 处理地面、装饰和场景物瓦片；用固定像素色板补齐卡车、围墙和战斗小图标。
3. 新增 `EnvironmentAssetManager`，集中维护纹理键、实体映射和最近邻过滤。
4. 调整 Preload 与 `GameAssetManager`，替换玩家源图并加载环境资产。
5. 按实体逐项替换主视觉，保持原物理体、对象池和生命周期接口不变。
6. 更新配置/素材完整性测试，解决现有 Node 类型检查阻塞。
7. 运行素材脚本、`npm test`、`npm run typecheck` 和 `git diff --check`。
8. 启动开发服务器，检查主菜单、三关、无尽、武器库、怪物图鉴和设置；重点截图三关与无尽战场。

## 实施建议

1. 原始资源和运行时资源分层：完整包保留在 `downloaded`，游戏只导入 `processed/environment` 中的白名单。
2. 运行时不加载 526 张散图或整张 1988 x 1470 图集，只加载实际使用的小型 PNG。
3. 位图替换只替换主体，阴影、预警圈和状态闪烁可以继续由 Phaser 图元承担。
4. 玩家新图朝右，人物旋转基准改为 0；武器贴图同样朝右，避免额外方向偏移。
5. 场景装饰采用固定种子和低密度白名单，保证截图可复现且不遮挡出生点。

## 潜在风险分析

| 风险 | 影响 | 控制方式 |
| --- | --- | --- |
| 新人物握点与武器错位 | 枪械贴在身体或子弹不从枪口射出 | 统一把握点收口到 `WeaponAssetManager`，逐把检查正右和斜向 |
| 位图尺寸与碰撞体不一致 | 玩家看到可通过区域却被阻挡 | 障碍物仍按关卡配置尺寸设置显示和 AABB |
| 地面素材对比度过高 | 子弹、掉落和危险区难以辨认 | 地面统一降低亮度/饱和度，实体不继承该 tint |
| 大量散图增加请求与维护成本 | 预加载复杂、资源漂移 | 只输出并导入运行时白名单，不直接扫描全目录 |
| 自定义卡车/围墙偏离 Kenney 风格 | 场景产生拼贴感 | 复用 Kenney 色板、硬边像素和无抗锯齿形状，浏览器截图复核 |
| 前置速度改动影响验收 | 误把数值手感问题归因于美术 | 视觉验收和可玩性结论分开记录，不在本轮改速度 |

## 优化方案

1. 所有纹理键通过类型化映射暴露，实体不散落文件路径。
2. 处理脚本对输出尺寸、透明通道和非空内容做校验，保证重复执行结果一致。
3. 后续正式关卡可继续扩展白名单，不需要修改实体类。
4. 如果资源数量继续增长，再把环境散图合并为 atlas；当前数量不足以证明 atlas 复杂度必要。

8. 场景实体与碰撞体保持一致，HUD、Boss 预警、出生预警和掉落物不被背景遮挡。
