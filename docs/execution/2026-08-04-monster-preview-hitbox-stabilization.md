# 怪物图鉴预览与 Boss 命中框稳定化执行文档

> 日期：2026-08-04  
> 状态：代码实施完成，浏览器截图待补  
> 关联范围：怪物图鉴预览、感染体视觉碰撞关系、ODDBLOT 图鉴肖像候选

## 1. 目标

1. 图鉴中的所有感染体精灵严格收敛在预览安全框内，母体与猎杀者不得遮挡档案名称、摘要和属性文字。
2. 锁定 `hunter_boss`、`matriarch_boss` 的显示缩放、碰撞半径和碰撞圆纵向中心关系，消除瞄准可见身体却无法命中的区域。
3. 收口 ODDBLOT 肖像候选：本轮不接入运行时，不提交派生肖像；删除未接线配置和仅执行原样解压的处理脚本，避免形成“代码存在即已生效”的误判。
4. 同步资源台账和既有肖像执行文档，使当前代码、资产状态和长期方案一致。

## 2. 范围

本轮包含：

1. 复核 `MonsterPreviewLayout`、`MonsterLibraryScene`、`zombieVisuals`、`Zombie` 与感染体配置之间的调用链。
2. 将图鉴边界校验从外层预览底板收紧到内部安全框。
3. 为视觉配置增加碰撞圆纵向偏移，并在实体生成时应用。
4. 根据源帧实际非透明像素边界校准两个放大复用 Boss 的碰撞半径和偏移。
5. 删除未接线的 `monsterPortraits.ts` 与 `process_monster_portraits.py`。
6. 更新 ODDBLOT 候选状态、授权说明和长期 Pack 2 建议。
7. 在 `1280 x 720` 画布进入怪物图鉴，检查普通感染体、猎杀者与母体的预览边界。

本轮不包含：

1. 不购买或接入 SmallScaleInt Pack 2。
2. 不替换战斗场景中的感染体精灵。
3. 不修改敌人生命、速度、伤害、能力、掉落和关卡编排。
4. 不重做怪物图鉴整体布局、文案或交互结构。
5. 不执行 `npm test`、`npm run typecheck` 或 `npm run build`，除非用户另行明确授权。

## 3. 视觉与交互方案

### 3.1 视觉主张

保留现有“封锁区感染体档案”构图。预览精灵只作为档案证物出现，必须服从内部安全框，不能越过档案文字与属性区的阅读层级。

### 3.2 内容结构

维持“左侧感染体索引 -> 右侧名称与摘要 -> 预览与属性 -> 出现关卡、掉落和处置建议”的既有顺序，不增加新面板。

### 3.3 交互主张

保留当前条目切换时的短距离位移和淡入，不新增循环动画。缩放修正不得造成切换时布局抖动。

## 4. 操作步骤

1. 用源 PNG 的 alpha 边界核对猎杀者与母体实际可见范围，而不是把整张含透明留白的帧尺寸直接当成身体范围。
2. 将两个 Boss 的可见范围换算到运行时缩放，确定能够覆盖身体的最小圆半径与纵向中心。
3. 在 `ZombieVisual` 中登记纵向碰撞偏移，在 `Zombie.spawn` 中统一应用。
4. 调整 `hunter_boss` 与 `matriarch_boss` 半径，并用测试固化缩放、半径和偏移关系。
5. 将图鉴预览边界断言改为内部安全框，确保数学约束与实际文字留白一致。
6. 删除未被任何模块引用的肖像配置和不满足派生要求的脚本。
7. 更新资源台账与 2026-07-31 肖像执行文档，明确 ODDBLOT 只保留在忽略目录。
8. 启动本地开发服务，进入怪物图鉴并截取普通感染体、猎杀者、母体画面进行目视检查。

## 5. 实施建议

1. 碰撞圆偏移属于美术映射参数，放在 `ZombieVisual` 而不是玩法配置，避免把透明留白差异混入敌人数值定义。
2. 半径仍保留在 `ZombieDef`，因为它同时影响物理分离、接触伤害与投射物命中。
3. 测试必须使用已核实的非透明像素边界，防止再次把透明留白误判为“打不到的身体”。
4. ODDBLOT 四张静态正面插画与当前俯视像素战场风格不同，且不足以为 18 类感染体建立独立身份；本轮不因许可可用就强行接入。
5. Boss 独立视觉身份继续以 SmallScaleInt Top-Down Zombie Pack 2 或同等级八方向资源为长期方案。

## 6. 潜在风险分析

1. **碰撞半径增大**：可能改变 Boss 与玩家、障碍物和敌群的接触距离。通过只调整视觉明显超出旧圆的两个 Boss，并保留速度、伤害和技能数值控制影响。
2. **偏移方向错误**：Arcade Body 的 offset 与精灵 origin 使用不同坐标语义。通过浏览器调试绘制/探针和源像素换算双重确认。
3. **图鉴数学正确但画面仍压字**：摘要文本会动态换行。内部安全框顶部必须为摘要保留稳定间距，并以真实画布截图确认。
4. **删除候选代码导致后续重做成本**：ODDBLOT 的来源、授权、哈希和视觉结论保留在忽略目录及执行文档中；未来重新立项时可以恢复，但不会伪装成当前能力。
5. **工作区已有大量未提交改动**：本轮只修改明确列出的调用链文件，不整理或覆盖其它现有修改。

## 7. 优化方案

1. 后续若接入统一肖像资源，应采用固定画布、alpha 裁切和显式焦点配置，不再复用战斗精灵的缩放参数。
2. 若未来需要更精确的非圆形 Boss 命中区，再单独设计攻击判定与移动碰撞分离方案；本轮不扩展为复合碰撞体。
3. 将正式 Boss 素材接入与 Boss 技能、碰撞和图鉴预览作为同一 Goal 验收，避免继续使用放大着色占位图长期累积欠账。

## 8. 验证方式

本轮执行的验证：

1. 调用链审阅：预览缩放、视觉配置、实体碰撞和图鉴渲染引用一致。
2. 数学复核：猎杀者与母体的已知非透明边界被碰撞圆完整覆盖。
3. 改动范围检查：ODDBLOT 运行时配置和处理脚本不再存在引用。
4. 浏览器冒烟：怪物图鉴可打开，普通感染体、猎杀者和母体预览不越过安全框且不遮挡文字。
5. 截图检查：`1280 x 720` 下画面非空、文字与预览无重叠。

建议但需用户另行授权的命令验证：

1. `npm test`：预计 10-30 秒，验证图鉴布局、配置完整性和碰撞关系测试。
2. `npm run typecheck`：预计 10-30 秒，验证新增视觉字段与调用链类型一致。
