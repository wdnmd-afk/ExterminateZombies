# 首页武器库入口与获取说明执行文档

## 目标

1. 在主菜单增加清晰可点击的“武器库”入口，并提供键盘快捷入口。
2. 新增独立武器库场景，使用已经下载的透明像素枪械素材展示沙漠之鹰、MP5、M4A1、SPAS-12、AK-47 与后续重火力。
3. 鼠标移动到任意武器行时，右侧详情区同步展示该武器的获取方式。
4. 获取方式严格来自当前真实游戏状态和僵尸掉落配置；尚未进入玩法的武器明确标记为“当前版本不可获得”。
5. 不改变现有武器数值、掉落概率、关卡流程或存档结构。

## 范围

预计涉及：

1. `src/scenes/MainMenuScene.ts`：增加武器库按钮和快捷键。
2. `src/scenes/WeaponLibraryScene.ts`：新增武器库场景。
3. `src/config/weaponLibrary.ts`：维护展示顺序、素材帧和获取方式类型。
4. `src/config/weapons.ts`：将当前泛化名称规范为实际武器名称，不修改数值和 ID。
5. `src/scenes/PreloadScene.ts`：预加载枪械精灵表和沙漠之鹰补充图。
6. `src/constants.ts`：增加场景 key。
7. `src/main.ts`：注册新场景。
8. `docs/execution/2026-07-28-homepage-weapon-library.md`：记录实施与验证结果。

明确不涉及：

1. 不新增 AK-47、Barrett M82、RPG-7、M79 的伤害、弹药或掉落逻辑。
2. 不修改 `GameState`、`WeaponManager`、`GameScene`、关卡波次和僵尸掉落概率。
3. 不增加新的存档字段，不把单局拾取状态错误地当作永久解锁状态。
4. 不执行全量构建。

## 已确认的获取链路

当前运行时代码已经确认：

1. `pistol` 是每局初始武器，对应本轮展示的沙漠之鹰。
2. `smg` 由快速僵尸以 `8%` 概率掉落，对应 MP5。
3. `rifle` 由坦克僵尸以 `14%`、巨型坦克以 `22%` 概率掉落，对应 M4A1。
4. `shotgun` 由爆炸僵尸以 `12%`、毁灭爆破者以 `28%` 概率掉落，对应 SPAS-12。
5. AK-47、Barrett M82、RPG-7、M79 当前只有素材，没有 `WeaponDef` 或掉落表条目，因此只能显示为后备武器，不能宣称存在尚未实现的获取途径。

## 视觉与内容方案

### 视觉主张

武器库采用“战地军械档案”风格：黑灰操作台、奶白文字和唯一警戒黄色强调，透明像素枪械作为右侧唯一主视觉锚点。

### 内容规划

1. 顶部：武器库标题、当前列装/后备数量和返回入口。
2. 左侧：连续的武器索引列表，不使用卡片墙；每行只展示编号、名称、分类和状态。
3. 右侧：当前悬停武器的大图、基础战斗参数和“获取方式”。
4. 底部：鼠标悬停与 ESC 返回提示。

### 交互主张

1. 场景进入时标题、索引和详情区依次淡入上移。
2. 武器行悬停时轻微右移并切换黄色标记，不做夸张缩放。
3. 详情切换时枪械图轻微缩放回弹，获取说明短暂淡入，强化“当前查看项”的反馈。

## 操作步骤

1. 建立武器库展示配置：
   - 明确每个条目的显示名、分类、状态和素材帧。
   - 可用武器关联准确的 `WeaponId`。
   - 获取方式使用 `initial`、`enemyDrop`、`unavailable` 三种明确状态。
2. 从 `ZOMBIES` 的真实掉落表动态生成敌人名称与概率，避免在 UI 中复制一套容易漂移的数据。
3. 在预加载场景加载：
   - `640 × 640`、`5 × 5` 的 128px 枪械精灵表。
   - 沙漠之鹰补充图。
4. 新增武器库场景：
   - 设置最近邻纹理过滤，避免像素枪械发糊。
   - 创建武器索引、详情面板、参数与获取说明。
   - 支持鼠标悬停和 ESC 返回。
5. 调整首页二级操作区，把“无尽模式 / 武器库 / 键位设置”排成同一行；快捷键改为 `1` 关卡、`2` 无尽、`3` 武器库、`4` 设置。
6. 注册新场景，并确保所有场景继续调用统一高清适配函数。
7. 执行类型检查与浏览器局部交互验证。

## 实施建议

1. 保留 `pistol`、`smg`、`rifle`、`shotgun` 作为稳定业务 ID，仅修改面向玩家的名称。
2. 获取说明通过配置类型和真实掉落表组合生成，禁止自由文本复制概率。
3. 武器详情只展示当前已有的伤害、弹匣、射击模式和弹药类型，不添加未定义的射程等级或稀有度。
4. 未来新增真实武器时，先补齐 `WeaponDef` 与掉落链路，再把武器库条目从 `unavailable` 切换为可获得状态。

## 潜在风险分析

1. 沙漠之鹰来自独立素材图，像素密度与主枪械表不同，需要使用准确裁切区和整数缩放。
2. 枪械精灵表包含透明留白，视觉居中不能只依赖武器实体像素边界；需要在详情区逐项微调显示缩放。
3. 首页原二级操作区宽度有限，增加第三个按钮后需要同步缩短文案，避免高分辨率纹理下发生拥挤。
4. 当前武器是单局拾取而非永久收藏，武器库不能使用本地存档伪造“已解锁”状态。
5. 素材纹理如未设置最近邻过滤，在非整数缩放下会再次出现模糊感。

## 优化方案

1. 武器列表使用连续行和共享详情区，避免为每把武器重复创建完整说明面板。
2. 只预加载两张来源图，武器通过精灵表帧复用，控制资源请求和显存占用。
3. 详情文本对象复用并通过 `setText` 更新，不在每次悬停时创建新对象。
4. 获取概率从配置实时读取，后续平衡调整无需同步修改 UI 文案。
5. 所有动画保持在约 `90–220ms`，避免影响鼠标快速扫过列表时的响应。

## 验证方式

1. `npm run typecheck` 必须通过。
2. 启动开发服务器，确认首页可见“武器库”按钮，点击和数字 `3` 均能进入。
3. 确认数字 `4` 仍能进入键位设置，首页其它按钮和关卡选择不受影响。
4. 武器库中逐项悬停，确认右侧名称、图片、参数和获取方式同步更新。
5. 核对 MP5、M4A1、SPAS-12 的敌人名称与概率和 `zombies.ts` 完全一致。
6. 核对 AK-47 与重火力明确显示当前不可获得，不出现虚构关卡或概率。
7. 确认枪械纹理透明、边缘清晰，没有线性采样模糊。
8. 按 ESC 或点击返回入口可回到主菜单，浏览器控制台无未处理异常。
