# 2026-09-09 构筑可见性与环境连锁 Goal 草案

> 文档类型：候选 Goal 执行文档
> 状态：已接线，待命令、浏览器和真人验收；不代表 R2 Goal 已完成
> 上位约束：`PROJECT_MASTER_PLAN.md` D-001、D-002、D-009；P2 切片为 `config/verticalSlice.ts` 中的 `level_2`
> 关联记录：`docs/execution/2026-09-09-combat-fun-roadmap.md`、`docs/execution/2026-09-09-combat-baseline-audit.md`

## 1. 目标

让局内强化从“单张卡的数值选择”变成玩家能读懂的构筑路线，并让 `level_2` 的环境物真正提供一次可观察、可重复验证的连锁机会。

Goal 通过时：

1. 玩家能看出三条首批流派：爆炸连锁、标记猎杀、弹链爆发。
2. 抽卡时能看到当前已投入的武器层数和已起步流派进度。
3. `level_2` 的广播站、油桶和敌群组合能形成“聚群 → 引爆 → 清场/换位”的战术动作。
4. 这些信息和收益不会改变无尽模式既有火力过载、存档结构或十关批量生产范围。

## 2. 背景与已确认决策

1. G2-7 已有 51 张行为化强化卡；现有 `effects` 字段已经包含击杀爆炸、命中标记和弹链追加等真实机制签名。
2. R2-1 的实际缺口是可见性，不是卡牌数量；当前卡池三种签名互斥，并分别有 6、8、8 张卡支撑。
3. R2-3 需要让第二次及之后的抽卡知道当前投资方向，避免玩家靠记忆把强化摊平。
4. `AreaEffectFactory` 的环境连锁判定是“起爆物爆炸半径 + 目标碰撞半径”；配置分析必须复用同一公式。
5. P2 约束要求先冻结 `level_2`，其余关卡不在本批次批量改坐标或增加文案。

## 3. 当前首版设计

### 3.1 流派

| 流派 | 真实签名字段 | 卡池数量 | 玩家操作含义 |
| --- | --- | ---: | --- |
| 爆炸连锁 | `setKillExplosion` | 6 | 通过击杀爆炸和密集目标制造连环清场 |
| 标记猎杀 | `setMarkOnHit` | 8 | 先标记，再持续集火高价值目标 |
| 弹链爆发 | `setAmmoChain` | 8 | 保持射击节奏，在固定间隔追加压制火力 |

流派由 `resolveCardArchetypes()` 从真实 `EnhancementDef.effects` 推导，不增加手工标签字段。卡面只显示带签名机制的流派徽标；纯数值卡不伪装成流派卡。

### 3.2 构筑摘要

抽卡页显示当前已激活强化按武器汇总的层数，并在已经起步的流派后显示 `N/3` 进度。空构筑不渲染空摘要；未知强化 id 被跳过，避免脏数据阻塞抽卡。

### 3.3 环境连锁

`level_2` 在左右广播站附近各增加一对间距 90px 的油桶。油桶爆炸半径 90px、碰撞半径 16px，连锁阈值为 106px；配置门禁要求切片至少存在一对满足该判定的可连锁场景物。

## 4. 范围

### 4.1 包含

1. 流派定义、从 `effects` 推导、卡面徽标和构筑摘要。
2. 流派数量、签名互斥、脏 id 跳过和排序稳定性的规则测试。
3. `level_2` 油桶摆位、环境连锁纯逻辑判定和 P2 配置门禁。
4. 统一验收入口中的抽卡可见性、环境实机连锁、暂停/重开和性能观察。

### 4.2 不包含

1. 不新增强化卡，不改变已有强化效果的数值和叠加规则。
2. 不扩展第 1、3-10 关环境摆位；后续批次另立 Goal。
3. 不增加新的场景物类型、存档字段或测试后门。
4. 不执行无尽模式强化频率、火力过载和高敌人数平衡调整。

## 6. 操作步骤

1. 对照 `ENHANCEMENTS` 的准确效果字段，确认三条流派推导不依赖猜测式字段兼容。
2. 静态核对卡面徽标、摘要排序、空构筑和脏 id 行为，确认不改变抽卡结算事件。
3. 静态核对环境连锁判定与 `AreaEffectFactory` 的实际半径公式一致，并确认油桶不与障碍或广播站重叠。
4. 取得测试和类型检查授权后，运行 R2 定向测试批次；不将历史 417 用例记录当作本批通过。
5. 在隔离存档中完成至少两次自然抽卡，记录卡面流派进度、当前构筑摘要和选择结果。
6. 在 `level_2` 中完成一次广播聚群和油桶连锁，记录两个油桶状态、敌群伤害、阶段推进和暂停/重开行为。
7. 由真人判断三条流派是否足够容易区分，构筑摘要是否帮助选择，以及环境连锁是否形成明确爽点。
8. 把实际结果、截图、旧值/新值和剩余风险回写本文件、路线图和统一验收入口。

## 7. 实施建议与优化

1. 流派继续从机制字段推导，避免新增卡时忘记手工登记。
2. 构筑摘要只展示已投入方向，不用三个 `0/3` 占据首屏空间。
3. 环境配置分析放在 `config/`，保持配置层不反向依赖运行时 `systems/`。
4. 先验证一对油桶和一个广播站组合，再考虑其他关卡的环境生产模板。
5. 若卡面拥挤，优先缩短徽标文案或换行，不减少卡面数值对比；若连锁过强，先调摆位和敌群到达时机并记录原因。

## 8. 潜在风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 流派签名与实际效果脱节 | 玩家被错误引导 | 只从 `EnhancementDef.effects` 推导，并用互斥和已登记 id 用例锁定 |
| 摘要文字挤压四张卡 | 选择信息变成遮挡 | 空构筑隐藏、稳定排序、限制单行内容并做宽窄视口验收 |
| 油桶连锁阈值与运行时不一致 | 配置通过但实机炸不到 | 判定式与 `AreaEffectFactory.explode` 保持同源语义，实机再验证一次 |
| 连锁清场滚雪球 | `level_2` 难度失去压力 | 本批只增加机会，不改爆炸伤害和连锁递归；由 V6 判断是否需要调敌群/摆位 |
| 其他关卡被间接改变 | P2 范围漂移 | 门禁只锁 `level_2`；其余关卡只保留 chainable 场景物，不改坐标 |

## 9. 验证方式

### V0 静态

- 真实字段、调用链、配置边界和不变项可从源码核对。
- `level_2` 成对油桶的几何阈值与运行时语义一致。

### V1/V2 命令

- `tests/enhancement-archetypes.test.ts`：流派数量、推导、互斥和脏 id。
- `tests/enhancements.test.ts`：构筑摘要聚合、排序和未知 id。
- `tests/environment-chain-rules.test.ts`：阈值、方向、非连锁物和切片机会。
- 本草案建立时未执行 `npm test`、`npm run typecheck` 或构建命令。

### V3-V6 实景与真人

1. 两次抽卡之间摘要内容与已激活卡一致，卡面徽标不会遮挡卡片信息。
2. 广播站能把基础感染体引到油桶附近，单次引爆能按预期触发相邻油桶。
3. 连锁过程暂停、重开和失败后无重复回调、残留伤害或场景物状态泄漏。
4. 真人可以说出三条流派的差别，并能指出一次环境连锁带来的位置或目标变化。
