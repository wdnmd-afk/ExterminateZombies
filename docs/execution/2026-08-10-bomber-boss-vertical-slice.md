# 2026-08-10 毁灭爆破者 Boss 战垂直切片

> 状态：已实施，V3-V5 实景验收受阻
> 关联：`PROJECT_MASTER_PLAN.md`、`docs/execution/2026-08-05-boss-art-replacement.md`、`docs/execution/2026-08-07-tank-boss-vertical-slice.md`

## 1. 目标

把第三关 `bomber_boss` 从“单阶段目标区域轰炸 + 死亡爆炸”收尾为一场具备阶段变化、远近距离互补技能和完整动作节奏的机制战：

1. 第一阶段通过目标区域轰炸迫使玩家持续移动。
2. 生命降至 50% 后进入“爆燃过载”，加快轰炸节奏并解锁近身爆燃震荡。
3. 近身震荡可以引爆战场中的可连锁场景物，使第三关的油桶和粉尘桶同时成为风险与反制工具。
4. 技能前摇接入 Kliver 攻击帧，死亡接入完整消散帧，在动画结束后再结算得分、掉落和波次。
5. 继续复用现有 HUD 阶段、战斗警报、音频和暂停时序框架。

## 2. 范围

本轮修改：

1. 为 `bomber_boss` 配置基础阶段名称和 50% 生命阶段。
2. 第二阶段缩短基础轰炸冷却/恢复，并小幅提高移动速度。
3. 第二阶段新增近身 `shockwave`，使用独立冷却和与轰炸互补的距离范围。
4. 近身震荡通过 `AreaEffectFactory` 现有连锁集合触发场景物。
5. 预加载 `kliver-attack.png` 与 `kliver-death.png`。
6. 登记 8 帧攻击动画和 16 帧死亡动画。
7. 更新配置测试、动作布局测试、素材说明、README 和项目总规划。
8. 同步怪物图鉴中的爆破者阶段能力与处置建议，避免档案描述落后于真实行为。

本轮不做：

1. 不修改 Boss 生命、基础移动速度、接触伤害、死亡爆炸、掉落或得分。
2. 不修改第三关常规波次、场景物和障碍布局。
3. 不接入 wounded 移动/攻击素材；阶段二继续使用同一移动与攻击条，避免扩展阶段视觉协议。
4. 不修改猎杀者和母体 Boss。
5. 不新增能力类型、依赖或独立 Boss AI 系统。
6. 不执行测试、类型检查或构建；需要用户明确同意后另行执行。

## 4. 操作步骤

1. 为爆破者增加“爆破封锁”基础阶段名称。
2. 配置 50% 生命进入“爆燃过载”：移动倍率 1.15，基础轰炸冷却倍率 0.78，恢复倍率 0.8。
3. 第二阶段解锁近身震荡：触发距离 0-140，轰炸最小距离保持 150，两类能力不随机争抢。
4. 震荡使用 700ms 前摇、22 点伤害、112 半径、独立 5200ms 冷却和 760ms 恢复，并允许触发可连锁场景物。
5. 将 `kliver-attack.png` 按 8 列、单帧 64×64 登记为 8 帧攻击动画。
6. 将 `kliver-death.png` 按 8 列×2 行、单帧 64×64 登记为 16 帧死亡动画。
7. 复用 `Zombie.playAbilityWindup` 和 `beginDeathAnimation`，不新增按 Boss ID 分支。
8. 扩展测试，钉住阶段阈值、能力组合和动作网格。
9. 同步素材台账、README、项目总规划和历史 Boss 美术执行记录。
10. 同步怪物图鉴简介和处置建议，明确第二阶段近身震荡与场景物连锁风险。
11. 执行调用链审阅、资源尺寸检查、`git diff --check` 和 Vite 模块转换请求。

## 5. 实施建议

1. 轰炸负责中远距离位移税，震荡只处理贴身玩家，两者必须保持距离互补。
2. 第二阶段主要提高决策密度，不增加 Boss 生命和基础伤害。
3. 震荡引爆场景物必须走已有连锁集合，防止同一油桶重复触发。
4. 攻击动画严格跟随能力前摇时长；死亡动画期间物理体和能力关闭，但实体保持 active 供波次等待。
5. Kliver 原始朝向为向下，动作条沿用移动条的 `-Math.PI / 2` 旋转方向，不重置朝向。

## 6. 潜在风险

1. **低生命节奏风险**：爆破者基础生命仅 180，第二阶段可能很快被高火力跳过，需浏览器试玩确认阶段存在感。
2. **连锁伤害风险**：震荡触发油桶后可能同时伤害 Boss 和近身玩家，必须确认不会形成无预警必杀。
3. **能力抢占风险**：轰炸与震荡距离若重叠，后解锁能力会优先执行；本轮通过 0-140 与 150-560 留出 10px 过渡带。
4. **死亡时序风险**：死亡动画共 16 帧，必须延迟结算且用生命周期令牌隔离对象池旧回调。
5. **暂停风险**：攻击前摇、危险区、战斗警报和死亡动画恢复后必须从同一剩余时刻继续。
6. **视觉风险**：攻击帧的动作幅度大于移动帧，实机中可能需要重新校准显示缩放，但本轮不改碰撞半径。

## 7. 优化方案

1. 浏览器试玩后记录轰炸命中率、震荡触发次数、第二阶段存活时间和场景物连锁收益，再调整数值。
2. 若 180 生命导致阶段无法成立，单独进入 Boss 平衡任务，不在本轮顺带提高生命。
3. wounded 素材留给未来统一的阶段视觉协议，不在单个 Boss 内建立临时字段。
4. 爆破者切片稳定后，再按同一质量门槛分别处理猎杀者和母体。

## 8. 验证方式

默认执行：

1. 配置核对：阶段阈值、倍率、技能距离、前摇、冷却、恢复和伤害参数完整。
2. 资源核对：攻击图 512×64，死亡图 512×128，布局分别为 8 帧和 16 帧。
3. 调用链审阅：配置、预加载、切帧、实体、能力系统、场景结算和 HUD 一致。
4. `git diff --check`。
5. Vite 对受影响模块和资源路径执行开发态转换请求。

待浏览器可连接后完成：

1. 第三关 Boss 第一阶段至少触发两次轰炸，确认落点、文字警报、攻击动画和伤害时点一致。
2. 将 Boss 压至 50% 以下，确认阶段公告、HUD 名称、速度和轰炸节奏变化。
3. 第二阶段近身触发震荡，确认范围预警、伤害和恢复窗口。
4. 让震荡命中油桶和粉尘桶，确认每个场景物只触发一次，Boss 与玩家按距离结算伤害。
5. 击杀 Boss，确认 16 帧死亡动画结束后才结算掉落与通关。
6. 在技能前摇和死亡动画期间暂停/恢复，确认时序不跳变。
