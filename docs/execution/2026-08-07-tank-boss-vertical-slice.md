## 1. 目标

把第二关 `tank_boss` 从“高血量追击单位 + 单次震荡”提升为第一场具备明确阶段、两种处理方式和完整死亡节奏的机制化 Boss 战：

1. 第一阶段使用近身震荡，要求玩家观察范围预警并及时拉开。
2. 生命降至阈值后进入“装甲过载”，解锁带方向预警的远距离冲锋。
3. 震荡可以触发战场中的可连锁场景物，让油桶和粉尘桶同时成为风险与反制工具。
4. 接入已经归档的 Armored Crawler 攻击、死亡帧，避免技能和死亡继续只用程序图形表达。
5. HUD 明确展示阶段，并在阶段切换时给出画面与声音提示。

## 2. 范围

本轮修改范围：

1. Boss 阶段与阶段解锁能力的配置类型。
2. `tank_boss` 第二阶段参数和冲锋能力。
3. `Zombie` 对象池实体的阶段推进、动作动画和延迟死亡流程。
4. `EnemyAbilitySystem` 的 Boss 冲锋方向预警。
5. `AreaEffectFactory` 的敌方震荡触发可连锁场景物能力。
6. `PreloadScene`、`GameAssetManager` 与视觉配置中的攻击/死亡帧加载和切帧。
7. `GameScene`、`HUDScene` 的阶段提示、Boss 状态和死亡收束。
8. 音频事件映射、资源说明与配置测试基线同步。

本轮不做：

1. 不修改第二关常规波次数量、掉落经济或解锁规则。
2. 不改造其它三个 Boss，不把攻击/死亡动画批量接到全表。
3. 不新增远程素材、依赖或独立 Boss AI 框架。
4. 不执行 `test`、类型检查或构建；需要用户明确同意后另行执行。

## 3. 操作步骤

1. 为 `ZombieDef` 增加可选的 Boss 基础阶段名称和阶段列表；阶段可配置生命阈值、移动倍率、基础能力冷却/恢复倍率及解锁能力。
2. 为巨型坦克配置 55% 生命阈值：阶段二提高追击速度、缩短震荡冷却并解锁定向冲锋。
3. 在实体层维护每个能力槽的独立冷却，确保震荡与冲锋按距离和各自节奏触发。
4. 阶段切换时保持当前攻击的既有时序，不中途取消已读条技能；下一次决策开始使用新阶段配置。
5. 将 `crawler-attack.png` 按 7 个 80x80 帧切分，将 `crawler-death.png` 按 3 列 x 5 行、共 15 个 80x80 帧切分。
6. 技能前摇播放攻击动画；死亡时停用物理和攻击，播放完整死亡动画后再结算掉落、得分和波次完成。
7. Boss 冲锋使用从起点指向锁定位置的黄色方向带；近身震荡继续使用红色范围圈。
8. 敌方震荡爆发时检查范围内可连锁场景物，通过现有爆炸链触发，避免复制伤害逻辑。
9. HUD 显示阶段编号与名称；阶段切换复用战场公告层，并增加专用声音事件和相机反馈。
10. 更新配置测试，让基础能力与阶段解锁能力接受同一套前摇、距离和参数约束。

## 4. 实施建议

1. 阶段和能力继续配置驱动，`EnemyAbilitySystem` 只负责把事件翻译成表现与伤害，不按具体 Boss ID 写完整行为树。
2. 冲锋与震荡使用互补距离：远距离优先冲锋，近距离才进入震荡，避免两个能力同时满足后随机表现失控。
3. 阶段二主要增加决策密度，不直接大幅增加生命和接触伤害；玩家应当因为新动作改变走位，而不是单纯延长输出时间。
4. 场景物触发必须走 `AreaEffectFactory` 的既有连锁集合，避免同一油桶在同一链中重复引爆。
5. 死亡动画期间 Boss 仍计为未清场，但物理体和攻击必须停用，防止结算提前或尸体继续伤人。

## 5. 潜在风险

1. **能力选择风险**：多个能力共用单一冷却会互相吞掉节奏，因此需要能力槽独立冷却。
2. **死亡竞态风险**：霰弹和爆炸可能在同一帧多次命中，死亡流程必须幂等。
3. **对象池风险**：延迟动画回调可能落到复用后的实体，必须继续使用生命周期令牌隔离旧回调。
4. **暂停风险**：技能前摇、动作动画和死亡动画在暂停/恢复后不能瞬间跳完。
5. **场景物风险**：震荡引爆油桶可能反伤 Boss，也可能伤到近距离玩家；这是设计中的风险收益，但需实机确认不会形成必杀组合。
6. **视觉风险**：攻击和死亡帧原始朝向为向下，必须沿用移动帧的旋转方向，不能重置实体朝向。
7. **节奏风险**：阶段二速度、冲锋距离和恢复窗口仍需实际试玩校准。

## 6. 优化方案

1. 本轮配置模型稳定后，其它 Boss 可逐个接入阶段和解锁能力，但不得一次性批量迁移。
2. 后续可把 Boss 公告、阶段颜色和动作素材扩展为完整的 `BossPresentation` 配置。
3. 若多个 Boss 都需要独立能力组合，再从 `Zombie` 中抽出 `BossBehaviorSystem`；只有一个切片时不提前拆层。
4. 浏览器验收后，根据冲锋命中率、震荡躲避率和油桶利用率调整参数，不用主观感觉直接堆伤害。

## 7. 验证方式

本轮默认执行：

1. 代码审阅：`levels -> WaveManager -> Zombie -> EnemyAbilitySystem/AreaEffectFactory -> HUD` 调用链完整。
2. 配置核对：阶段阈值、技能距离、前摇、恢复、冷却和动作帧布局互相一致。
3. 静态范围检查：只影响 `tank_boss` 的阶段配置，普通感染体与其它 Boss 继续使用原行为。
4. `git diff --check` 与提交边界检查。

待浏览器可连接后完成：

1. 第二关 Boss 第一阶段至少触发两次震荡，确认预警、攻击动画和伤害时点一致。
2. 将 Boss 压至 55% 以下，确认阶段公告、HUD、速度变化与冲锋解锁。
3. 分别侧闪冲锋和被冲锋命中一次，确认方向带、恢复窗口和接触伤害可读。
4. 让震荡命中油桶与粉尘桶，确认只触发一次连锁，玩家和 Boss 均按距离结算伤害。
5. 击杀 Boss，确认完整死亡动画结束后才进入结算，期间尸体不移动、不攻击。
6. 在技能前摇和死亡动画期间各暂停/恢复一次，确认时序不跳变。
