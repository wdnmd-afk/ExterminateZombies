# 像素枪械与俯视人物素材归档执行文档

## 目标

1. 从互联网下载许可证明确、可随项目再分发的枪械与人物素材，不使用 AI 生成图片。
2. 枪械首批必须覆盖沙漠之鹰、M4A1、MP5、AK-47，并为后续重火力玩法预留 Barrett M82、RPG-7、M79 等素材。
3. 人物优先选择透明背景、俯视角、带持枪或移动帧的低分辨率像素素材，同时保留一套许可证更宽松、内容完整的俯视人物备选库。
4. 所有素材保存来源、作者、许可证、下载日期和 SHA-256，确保后续接入可追溯。

## 范围

本轮只新增或整理以下目录：

- `src/assets/downloaded/weapons/`
- `src/assets/downloaded/characters/`
- `docs/execution/2026-07-28-pixel-weapons-characters.md`

本轮不修改：

- `src/config/weapons.ts` 中的数值、字段和武器 ID。
- `WeaponManager`、`Player`、`PreloadScene` 等运行时逻辑。
- 当前玩家、僵尸或武器的显示实现。
- 动画方向、帧率、锚点、碰撞体和武器类型映射。

## 操作步骤

1. 核对每个来源页的作者、附件地址和许可证标识。
2. 下载原始 PNG 或 ZIP 到对应素材包目录。
3. 对 ZIP 做安全解包，移除 `__MACOSX`、`.DS_Store`、`Thumbs.db` 等无关元数据；保留作者原始说明和许可证文件。
4. 不重绘、不改色、不放大、不做 AI 生成；保留下载到的原始像素数据。
5. 为每套素材编写 `SOURCE.md`，记录来源页、直接下载地址、内容说明、许可证和使用注意事项。
6. 对所有 PNG/GIF 执行解码、尺寸、透明通道与动画帧数检查。
7. 计算归档文件的 SHA-256，并写入对应 `SOURCE.md`。
8. 本轮仅归档候选，不把文件名直接猜测映射到现有 `pistol`、`rifle`、`smg` 等业务配置。

## 实施建议

1. 主枪械表按固定 `128 × 128` 单元格使用；正式接入前根据原图标签建立准确的帧名映射，不依靠视觉猜测。
2. 沙漠之鹰补充图和主枪械表的像素密度不同，接入时应统一显示包围盒和视觉长度，而不是直接统一缩放倍率。
3. 人物与枪械图标承担不同职责：人物持枪动画用于世界场景，128px 枪械图用于 HUD、掉落物或武器选择界面，不强行拼接成同一张角色图。
4. CC-BY 3.0 人物素材接入正式版本时，必须在游戏 Credits、项目说明或许可证页面保留作者署名和来源链接。
5. Kenney 素材作为完整度优先的备选；若最终视觉方向锁定为严格像素风，应优先使用 Ghostbyte 或 CornerLord 的人物素材。

## 潜在风险分析

1. 不同作者的像素密度、俯视角度和轮廓语言不一致，直接混用会产生拼贴感。
2. 枪械精灵表适合图标和掉落物，但不等同于人物手中的武器动画，后续可能需要独立的持枪姿态或程序旋转方案。
3. CC-BY 3.0 允许商业使用和修改，但要求署名；遗漏 Credits 会造成许可证合规风险。
4. GIF 动画虽有透明色，但引擎接入前仍需确认 Phaser 对帧拆分、色键和播放时序的处理方式。
5. 本轮不确认人物动画朝向、锚点和碰撞中心，过早接入可能造成旋转中心漂移或枪口位置错误。

## 优化方案

1. 素材先按作者与资源包隔离归档，避免同名文件覆盖和许可证混淆。
2. 后续确认最终画风后，只把选中的角色与武器加入预加载列表，避免无效资源进入首屏包体。
3. 正式接入时建立独立的素材元数据，明确帧尺寸、帧数、朝向、锚点、枪口点和推荐显示尺寸。
4. 如需统一画风，优先通过有限色板、整数倍缩放和最近邻采样处理，不使用模糊滤镜或非整数缩放。

## 验证方式

1. 所有下载返回成功，ZIP 可正常解包，文件不为空。
2. PNG/GIF 可由图像库正常解码，并记录宽高、色彩模式、透明通道和动画帧数。
3. 主枪械精灵表必须保持 `640 × 640`，具备透明通道，可按 `5 × 5` 的 `128 × 128` 网格读取。
4. 人物素材至少一套具备持手枪动画，至少一套具备自动武器动画。
5. 所有素材包具有 `SOURCE.md`，并能从 SHA-256 复核文件未被意外改写。
6. 因本轮不改 TypeScript 运行时代码，不执行高成本全量构建；仅在代码发生意外变更时补充 `npm run typecheck`。
