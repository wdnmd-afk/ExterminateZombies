# ExterminateZombies 高清适配与像素僵尸素材执行文档

## 目标

1. 在不改变现有 `1280 × 720` 逻辑坐标、物理世界和玩法数值的前提下，提高 Phaser 画布、文字纹理、边框与几何图形在高分辨率屏幕上的清晰度。
2. 保持首页、HUD、设置、结算和战斗场景使用同一套高清渲染规则，避免只修首页后其它页面继续模糊。
3. 设计并生成第一批统一像素美术语言的僵尸素材，覆盖普通、疾跑、坦克、爆炸和两类 Boss。

## 范围

### 高清适配

涉及：

1. `src/main.ts`
2. 新增 `src/systems/DisplayManager.ts`
3. `src/scenes/BootScene.ts`
4. `src/scenes/PreloadScene.ts`
5. `src/scenes/MainMenuScene.ts`
6. `src/scenes/GameScene.ts`
7. `src/scenes/HUDScene.ts`
8. `src/scenes/SettingsScene.ts`
9. `src/scenes/GameOverScene.ts`
10. `src/scenes/LevelClearScene.ts`

约束：

1. `GAME_WIDTH`、`GAME_HEIGHT` 继续表示逻辑坐标，不修改关卡坐标、玩家速度、射程、碰撞范围和 HUD 布局值。
2. 高清倍率只影响实际渲染缓冲区、摄像机映射和文字纹理分辨率。
3. 不使用 `image-rendering: pixelated` 或全局关闭抗锯齿来掩盖模糊，避免中文文字出现明显锯齿。
4. 本轮不执行 `npm run build`。

### 像素僵尸素材

第一批素材按同一像素风格生成六种战斗造型：

1. `walker`：灰绿色皮肤、破旧工作服、迟缓前倾姿态。
2. `runner`：瘦长轮廓、明显前冲姿态、亮黄破损上衣。
3. `tank`：宽肩厚重轮廓、深色工业防护服、粗壮双臂。
4. `bomber`：橙红警示色、膨胀躯干、危险容器或破损防护装备。
5. `tank_boss`：非对称重型变异、巨臂和装甲残片，轮廓显著大于普通坦克。
6. `bomber_boss`：更强烈的橙红核心、重型爆破装置和 Boss 级宽大轮廓。

生成要求：

1. 统一俯视 3/4 视角、全身构图、朝向一致。
2. 清晰像素块、有限色板、硬边阴影、强轮廓，不使用柔焦和写实渐变。
3. 不带文字、水印、地面、投影或场景背景。
4. 使用纯洋红色键控背景，避免与僵尸常用绿色冲突；生成后本地移除背景并验证透明通道。
5. 源图与游戏候选图分开保存，不覆盖仓库已有第三方素材。

原生成路径限制（已由后续下载路线替代）：本会话未启用内置 `image_gen` 工具，且本机未配置 `OPENAI_API_KEY`。

### 素材路径调整记录

用户后续明确要求停止图片生成，改为直接下载互联网现成素材。因此素材阶段调整为：

1. 不再执行 AI 生成、键控背景移除和生成图裁切。
2. 仅下载许可证明确、能够随项目再分发的像素素材。
3. 本轮选用两套 OpenGameArt CC0 素材：
   - `Zombie RPG sprites`：作者 Curt，包含 6 张四方向像素僵尸精灵表及额外造型。
   - `Zombie and Skeleton 32x48`：作者 Reemax，包含更粗壮的四方向僵尸和骷髅精灵。
4. 素材统一保存到 `src/assets/downloaded/zombies/`，每套素材同时保存来源页面、直接下载地址和许可证说明。
5. 本轮只完成下载、解包、授权记录和文件校验；不在未经用户确认的情况下映射到现有僵尸类型或替换运行时显示。

调整原因：用户选择在线下载路线，且候选素材已能覆盖多个僵尸造型，不再需要生成工具或透明背景后处理。

影响范围：素材阶段不再依赖 `OPENAI_API_KEY`，也不会产生 AI 生成源图目录。

## 操作步骤

1. 固化本执行文档，冻结逻辑坐标与素材边界。
2. 新增显示管理层：
   - 根据物理屏幕尺寸和设备像素比选择 `1×` 或 `2×` 渲染倍率。
   - 最大倍率限制为 `2×`，控制显存和填充率成本。
   - 导出实际渲染尺寸与场景配置函数。
3. 将 Phaser 画布改为高清缓冲区尺寸，同时继续由 `Scale.FIT` 适配浏览器窗口。
4. 每个场景启动时统一设置：
   - 摄像机视口为高清缓冲区尺寸。
   - 摄像机缩放倍率为高清倍率。
   - 摄像机中心对准逻辑世界中心 `(640, 360)`；2×模式下 Phaser 内部 scroll 为 `(-640, -360)`，确保逻辑左上角仍映射到画布左上角。
5. 监听场景的 `ADDED_TO_SCENE` 事件，对所有当前及后续创建的 Phaser Text 设置同倍率纹理分辨率，覆盖动态提示、爆炸拟声词和拾取文本。
6. 执行高清验证：
   - 类型检查。
   - 对比画布位图尺寸和 CSS 显示尺寸。
   - 截图检查首页、战斗 HUD 和细线边界。
   - 点击主按钮验证输入映射未偏移。
   - 检查运行时异常和基础帧率。
7. 下载已确认的 CC0 僵尸素材包和原始 PNG。
8. 解包时剔除 `__MACOSX` 等无关元数据，仅保留原始精灵图与有实际用途的附加图。
9. 为每套素材保存 `SOURCE.md` 和 CC0 许可证文本。
10. 校验 PNG 尺寸、透明通道、文件哈希和来源可追溯性。
11. 本轮仅交付下载素材，不在未经用户确认的情况下替换当前实体或制作猜测式动画切片。

## 实施建议

1. 高清渲染使用“逻辑坐标与物理缓冲区分离”的方式，现有业务代码继续以 `1280 × 720` 编写。
2. 文字清晰度通过 Phaser Text 自身的 `resolution` 提升，避免逐个页面重复填写样式字段。
3. 高清倍率在游戏启动时确定，避免运行中频繁重建 WebGL 缓冲区和文字纹理。
4. 僵尸素材先做静态角色锚点，确认轮廓、色板和视角后再扩展移动、受击、攻击、死亡帧。

## 潜在风险分析

1. `2×` 缓冲区从约 92 万像素增加到约 369 万像素，会提高 GPU 填充率和显存占用。
2. 摄像机缩放、高清视口和逻辑中心必须严格成对设置，否则会出现画面只剩局部、输入坐标偏移或 HUD 尺寸翻倍。
3. Phaser Text 使用高分辨率内部 Canvas，会增加动态文字纹理内存；短生命周期文字需要继续按现有逻辑及时销毁。
4. 像素素材由生成模型产出时，可能出现伪像素、视角不一致或轮廓细节过密，需要逐张验证，不能直接批量接入。
5. 键控背景移除可能在服装高亮处残留色边，因此僵尸主体禁止使用洋红色，并需要检查透明边缘。

## 优化方案

1. 高清倍率最高限制为 `2×`；物理屏幕不足以受益时退回 `1×`。
2. 保留 WebGL 抗锯齿，只提高缓冲区和文字纹理分辨率，不启用全局像素化。
3. 后续若低端设备性能不足，可增加用户可选的“标准 / 高清”显示设置，而不是降低所有设备质量。
4. 像素素材最终统一裁切、留白和基准点，避免不同僵尸接入后碰撞中心与视觉脚底漂移。

## 验证方式

1. `npm run typecheck` 必须通过。
2. 运行时确认：
   - 逻辑尺寸仍为 `1280 × 720`。
   - 高清设备上的画布位图尺寸为 `2560 × 1440`。
   - 摄像机缩放为 `2`，可视世界仍完整覆盖 `1280 × 720`。
3. 首页截图检查标题、任务列表、细线和按钮边缘不再明显发糊。
4. 主按钮点击后能够正确进入关卡，鼠标瞄准坐标与玩家朝向一致。
5. HUD、波次提示、拾取提示、暂停层和结算页文字尺寸不发生翻倍或错位。
6. 浏览器运行期间无未处理异常。
7. 素材生成后逐张确认：
   - PNG 具有 Alpha 通道。
   - 四角透明。
   - 主体完整且没有洋红色残边。
   - 六种僵尸在缩略尺寸下仍能靠轮廓和色彩区分。
