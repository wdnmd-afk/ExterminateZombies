## 1. 目标

在 P2 `level_2` 垂直切片中完成固定关卡的“连杀 → 即时收益 → 下一次爆发”闭环，并让玩家从阶段播报与 HUD 读到当前战斗意图。

Goal 通过时，玩家应能在一局中观察到：

1. 5/10/20/35 连杀里程碑继续沿用现有播报、音效、震屏和慢动作。
2. 固定关卡达到里程碑后，在不增加永久属性的前提下获得一次主动技能冷却收益。
3. `level_2` 的三个阶段分别显示清群、压制和备战目标，阶段目标与实际敌群组合一致。
4. 无尽模式原有的伤害火力过载规则不被改变。

成功标准是玩家能理解“为什么这次连杀值得保持”和“当前阶段要优先处理什么”，而不是单纯提高伤害或增加播报数量。

## 2. 背景与已确认决策

基线审计确认：

1. `registerKill()` 是唯一连杀入口，`KillStreakRules` 已有 5/10/20/35 里程碑。
2. `EndlessModePolicy` 只在无尽模式提供伤害火力过载；固定关卡此前没有战斗收益。
3. 当前工作区已经接入 `refundSkillCooldown()`、`LEVEL_STREAK_SKILL_REFUNDS` 和 `applyLevelStreakReward()`，但尚未运行命令或浏览器验证。
4. 当前工作区已经为 `level_2` 三个阶段接入 `WaveObjectiveDef`、播报和 HUD 短标签；测试约束其余九关保持缺省。
5. `CharacterSkillState.readyAt`、`activeUntil` 使用绝对时间，暂停和抽卡恢复必须通过既有 `shiftTimers()` 平移。

## 3. 产品决策（已确认）

### 3.1 已确认方向

固定关卡连杀奖励使用“主动技能冷却返还”，不使用伤害倍率：

| 连杀 | 返还冷却 | 作用 |
| ---: | ---: | --- |
| 5 | 800ms | 早期连杀的轻量正反馈 |
| 10 | 1500ms | 让下一次技能更快进入可用窗口 |
| 20 | 2500ms | 高压段落中的主动反打机会 |
| 35 | 3500ms | 高连杀的明显收益，但不直接增加伤害 |

规则约束：

1. 门槛与 `KILL_STREAK_MILESTONES` 精确对齐，不建立第三套计数。
2. 返还只把 `readyAt` 向 `now` 拉近，不能早于 `now`；累计返还为 8300ms，低于最短技能冷却 9000ms。
3. `activeUntil` 不变，返还不会延长已经生效的技能窗口。
4. 技能已经就绪时不显示无意义的返还提示。
5. 只在 `mode === 'level'` 生效；无尽模式继续由 `activateEndlessOverdrive()` 消费原有火力过载配置。

### 3.2 确认结论（2026-09-09）

用户已确认两项：

1. **奖励轴向**：采用 §3.1 的主动技能冷却返还，不改为伤害倍率。
2. **数值口径**：四档保持绝对毫秒 `800/1500/2500/3500`，不改为按各角色冷却的百分比。

确认前已完成的源码核准（V0，行号为确认当时状态）：

| 核准项 | 证据 |
| --- | --- |
| 四档值与累计 8300ms | `KillStreakRules.ts:72-77` |
| 最短技能冷却 9000ms（`runner` 相位疾冲） | `characters.ts:367` |
| 退还夹在 `now`、已就绪时原样返回 | `CharacterSkillRules.ts:96-101` |
| 两模式奖励轴严格互斥 | `GameScene.ts:1800-1824` 的 `mode` 门禁成对出现 |

因此 §3.1 的五条规则约束与代码实现一致，本次确认不产生数值改动。

### 3.3 确认时暴露的口径边界：绝对毫秒对各角色价值不等

`8300ms` 的上限是从**最短**冷却倒推的，因此同一条连杀链在不同角色身上收益占比不同：

| 角色 | 技能冷却 | 累计 8300ms 占比 | 5 连杀 800ms 占比 |
| --- | ---: | ---: | ---: |
| `runner` 相位疾冲 | 9000ms | 92% | 8.9% |
| `watcher` | 14000ms | 59% | 5.7% |
| `eagle_eye` | 16000ms | 52% | 5.0% |
| `bastion` | 18000ms | 46% | 4.4% |
| `breacher` | 20000ms | 41% | 4.0% |

已确认保留绝对毫秒，理由是：长冷却技能本身更强，只退更小比例是可接受的；且播报文案 `技能充能 +0.8s` 因为是绝对值才直接可读，换成百分比需要按角色换算才能显示实际秒数。

代价必须记录：5 连杀那一档在 `breacher` 身上只有 4%，可能完全感知不到，而这一档的设计意图恰是“给一次早期正反馈”。**该差异不由静态分析裁定，列为 V6 观察项**（见 §9 第 6 条）；只有拿到实机数据证明低档在长冷却角色身上确实无感，才回来讨论是否改口径，不在无数据时先改。

1. 保持返还逻辑为纯函数，避免让 HUD 或 `GameScene` 各自计算冷却。
2. 奖励提示复用 `pickupCollected`，技能状态展示继续由 `getSkillStatus()` 和 HUD 每帧刷新负责。

## 8. 潜在风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 返还在技能已就绪时不可见 | 玩家可能误以为里程碑没有奖励 | 仅在实际返还量大于 0 时播报，并在 V6 记录是否需要更明确的里程碑提示 |
| 连杀重置后再次达到门槛可重复返还 | 技能循环可能比预期频繁 | 记录每局各档触发次数；若滚雪球，优先增加每阶段一次限制或降低返还值，不能直接改成永久属性 |
| 返还值高于最短冷却 | 高连杀变成无冷却技能 | 保持累计 8300ms < 9000ms 的校验约束，并在调参时同步更新用例 |
| 阶段文案与实际敌群不一致 | 玩家形成错误目标 | 每次修改波次组合都同步检查 `objective.subtitle`，不批量复用同一句文案 |
| 暂停或抽卡期间冷却继续流逝 | 奖励节奏被系统时间污染 | 使用 `shiftSkillTimers()` 和现有 `shiftBattleTimers()`，不新建独立计时器 |
| 无尽模式误触发固定奖励 | 两套成长规则叠加导致失衡 | 保留 `mode === 'level'` 门禁，并用无尽回归场景确认 `endlessOverdrive` 不变 |
| 绝对毫秒在长冷却角色上占比过低 | 5 连杀档在 `breacher`（4%）可能完全无感，早期正反馈失效 | 已确认保留绝对毫秒（§3.3）；按角色分别记录低档可感知性，仅在实机证明无感后再讨论改口径 |

### V3-V6 实景与真人

1. `level_2` 阶段播报和 HUD 标签在宽窄视口均不遮挡战场信息。
2. 自然击杀达到 5/10 连杀后，技能冷却读数实际缩短，提示只出现一次且不重复消费。
3. 暂停、抽卡、失败和重开不会让冷却凭空消耗或遗留返还状态。
4. 无尽模式自然达到 10/20/35 连杀时仍只出现火力过载，不出现固定关卡技能返还提示。
5. 真人能说出一个连杀收益带来的具体操作变化，并能指出阶段目标是否帮助目标选择。
6. **按角色记录低档可感知性**（§3.3 的已确认代价）：至少用 `runner`（9000ms）和 `breacher`（20000ms）各跑一局，
   分别记录 5 连杀那 800ms 是否可感知。若长冷却角色确认无感，才回到 §3.3 讨论是否改百分比口径；
   不得因为静态占比数字难看就先改数值。
7. 记录每局各档（5/10/20/35）的实际触发次数，用于判定 §8「连杀重置后可重复返还」是否真的滚雪球。

### 10.3 「技能已就绪时不误播报」的实证（§3.1 规则 4）

前五轮尝试均未观测到返还，原因一致且值得记录：里程碑发生时技能已就绪，`refundCooldown`
返回 0、按设计不播报。其中第一轮 t=30545 达成 5 连杀，而技能在 t≈7000 施放、14s 冷却在
t≈21000 就已走完。**这反向验证了规则 4 本身**——已就绪时确实不产生无意义提示。

真正观测到返还的做法是：技能一就绪就立刻施放，使冷却覆盖率接近 100%，任何里程碑都必然
落在窗口内。这条经验对后续同类验收有复用价值：不要试图预测爆发时刻去对齐一次施放。
