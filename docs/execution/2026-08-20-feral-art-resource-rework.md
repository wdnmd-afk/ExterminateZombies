## 1. 目标

把当前复用 Cabbit `48×64` 三帧方向表的 `feral`，重整为与 Walker / Runner / Bomber /
Lurker / Drifter 同等级的项目生成资源链：

1. 生成与既有五类同画风、同机位、同键控底约束的四方向移动表。
2. 生成独立图鉴立绘，不从动画表截图放大。
3. 接入 Phaser 预加载、视觉布局、图鉴与资源台账。
4. 不改动 `feral` 的任何玩法数值（生命 34、速度 62、伤害 9、攻击间隔 680、半径 11、
   `dash` 能力 cooldown 2600 / dashSpeed 170 / dashDuration 310、掉落表 3 项）。

## 2. 本轮范围

沿用既有范围决定：脚本走按 id 取配置的共用管线而非专属副本；资源只做移动方向表 +
图鉴立绘，不做攻击/死亡动作表（普通感染体当前没有动作素材契约）。

不包含：修改 `feral` 玩法/AI/dash 参数、修改其它感染体素材、生产构建。

本轮与另一个会话的 Drifter 那轮**并行执行**，共享文件的处理见 §10。

| 判据 | v01 | v02 | 阈值 |

## 4. 本类特有的键控冲突：肋骨与下颌穿孔

与 Bomber 的感染囊、Lurker 的颅内组织同源，但本类的裸露面是全部感染体中最大的：
肋骨间隙与撕裂的下颌肌肉都是大面积裸露血肉。键控判据是 `floor = min(r,b)`、
`chroma = floor - g`、`|r-b| <= 96`：

- 亮粉肌肉 `(235,150,190)` 会算出 `floor=190`、`chroma=40`、`|r-b|=45`，三条全部命中，
  直接被当成背景抠掉。
- 而肋骨与撕裂下颌正是本类的识别特征，穿孔等于素材报废。

处理：提示词把裸露血肉压向暗红褐/干涸血色（深红褐 `(90,45,40)` 的 `floor` 仅 40，
远低于阈值 110，安全），负面词加上 `bright pink flesh`、`magenta muscle`、`pink viscera`。

**实测结果（独立脚本复核，与后处理脚本不同代码路径）：**

## 5. 双足约束

低伏蜷缩姿态极易被画成四足爬行，而 `crawler`（伏地）与 `stalker`（俯行猎手）已各自
占了四足生态位，撞形态会让三者在实机里无法区分。

处理：`gait` 与四级降级词表里统一写 `on TWO legs` / `two bent legs`，负面词加上
`quadruped`、`four legs on the ground`、`crawling on all fours`、`hands and knees`，
另压掉兽化附件（`werewolf`、`wolf`、`tail`、`beast fur`、`animal ears`、`metal claws`）。

量化上只能证明每格恰好 1 个连通域、侧向横躺、行间可分，**证明不了它没被画成四足**。
这一项必须目视，见 §9。

### 7.1 参考图的 3 项失败不需要修

4 项失败中有 3 项落在四视图转身参考图上（右上格含多个连通域、右上与右下格贴边）。
这张图**只作 I2I 身份锚点，不参与后处理**：`process_zombie_sprites.py` 的
`DIRECTION_KEYS` 只取 `left`/`down`/`up`，参考图仅被 `adopt_sources` 归档，
它的贴边不会进入任何运行时像素。

根因是共用骨架的缺口：Drifter 那轮给 2×2 四帧图的 `gridFor()` 补了每格留边约束，
但转身参考图的请求走的是另一条 composition，没有这条约束。修它要改
`generate_zombie_assets.mjs` 并重生成整套参考图（连带四张方向图），收益为零，
因此列为独立的管线改进项，见 §11。

### 7.2 `left` 自镜像对称度 0.491 超限的判断

与 Bomber `0.535` 被采用同性质：该阈值按瘦削直立体型标定（Walker 实测 0.216），
而本类是蜷缩低伏、双爪前伸的紧凑轮廓，水平镜像后仍有较大重叠。

支持"这确实是俯视侧面"的证据是宽高比：四帧实测 1.38 / 1.82 / 1.57 / 1.66，
成品级逐行平均 1.61，明显宽于高；已验收的 Runner 侧向为 1.50。
成品级的体型无关落差判据已经兜住了这一条（§7 表）。

### 9.1 V1 无法执行与替代核对

`npx vitest run` 在收集任何测试之前就以
`ERR_PACKAGE_PATH_NOT_EXPORTED: Package subpath './module-runner' is not defined`
失败：`vitest 4.1.10` 需要 Vite 6+ 的 `./module-runner` 导出，而 `package.json`
声明的是 `vite ^5.4.2`。这是既存依赖不兼容，不是本轮改动引入的。

替代做法是用 vite 自带的 esbuild（`node_modules/.pnpm/esbuild@0.21.3`，非顶层包）
把纯数据配置转成 CJS，在 Node 里断言。41 项全部通过，覆盖：

- Feral 纹理键、`facingMode`、`scale`、`frameRate`、`tint`、`originY`、
  `rotationOffset`、`collisionOffsetY`。
- 帧布局 `512×512`、`frameXs` `0,512,1024,1536`、行映射 `down=0/left=1/right=2/up=3`、
  `getZombieFrameSize`。
- 立绘纹理键存在且与方向表键不同；四个方向的动画键。
- 玩法数值逐项未变：生命 34、速度 62、伤害 9、攻击间隔 680、半径 11、评分 22、
  `dash` 能力四项参数、掉落 3 项。
- 缩放反推：可见/半径 `4.43`，落在已验收区间 `[4.40, 4.46]`。
- 其它感染体未被本轮改动（walker/runner/lurker/bomber 各自纹理不变、
  drifter 仍指向并行会话的新表、tank 仍用 Curt 表）。
- 旧 Cabbit 键 `game-zombie-feral-src` 不再被任何感染体当作移动视觉。

替代核对不等于 V1：它验证配置数据，不验证 `tests/` 下的业务断言。

### 9.2 本轮的工具输出可靠性问题

本会话多次出现工具输出与磁盘不一致：管道回显与文件重定向给出不同的退出码、
行被重复或字符被替换、同一数值在两次读取间不同。因此本文件内每个数字都经
独立路径复核后才写入——退出码写入文件再读、几何与空洞由单独脚本重测并附自检、
哈希用命令行现场重算。

**这不是可以省略的步骤**：本轮曾一度记录过一批未经复核的空洞数字
（"4/16 帧、39px、最差 0.0182%"），实测为 "16/16 帧、340px、最差 0.0633%"，
已按实测更正（§4）。

### 9.3 我无法验证、需要你目视的部分

本会话的图片读取工具对 PNG 无返回，**我没有看到任何一张图**。必须由你确认：

1. **是不是双足**。这是本轮最关键的一项（§5）。量化上我只能证明每格 1 个连通域、
   侧向横躺、行间可分，排除不了四足爬行。若画成四足，会与 `crawler`、`stalker`
   撞形态，需要重做 `left`/`down`/`up` 并复核 `verify` 仍通过。
2. **每一行画的是不是它该画的那个方向**。门控只能证明四行朝向彼此不同且几何稳定，
   不能证明 `left` 行画的是朝左而不是朝右、`up` 行是背面而不是正面。
3. **肋骨与撕裂下颌是否清晰可读**。这是本类的识别特征，量化上我只能证明
   "没有被抠出透明洞"，证明不了"看得出是外露肋骨"。
4. **四帧是否构成自然的低伏弹跳突进循环**，以及轮廓是否与 `runner` 区分得开——
   两者半径同为 11、可见尺寸同为 48.7px，**只能靠姿态区分**。
5. **机位一致性**。侧向宽高比 1.61 是目前最横躺的一档，同场景并列时是否违和。

`src/config/testing.ts` 的 `monsterArtReviewWave` 当前为 `true`，无尽模式第 1 波会
一屏摆出全部 18 类各 8 只（四朝向各 2 只）并钉死不动，正是用来做上述目检的。
看完把该开关改回 `false` 重开一局即可恢复正常曲线。
