# 美术资源维护台账执行文档

## 目标

1. 建立统一的美术资源维护文档 `docs/ART_ASSET_REGISTRY.md`。
2. 按资源类型记录名称、状态、用途、使用位置、本地路径、来源网站、来源链接和许可证。
3. 明确区分已接入资源、已下载未接入资源、派生资源、项目内生成资源和候选场景资源。
4. 让后续素材下载、接入、替换、署名和发布检查都有单一可追踪入口。

## 背景与已确认事实

1. 当前运行时通过 `PreloadScene` 加载玩家、感染体、武器原图和处理后 PNG。
2. `GameAssetManager` 维护玩家及感染体纹理、切帧和动画映射。
3. `WeaponAssetManager` 维护八把武器的战场纹理与显示参数。
4. `scripts/process_zombie_assets.py` 和 `scripts/process_weapon_assets.py` 负责从原始资源生成运行时派生文件。
5. 当前场景地面、障碍物、场景物和主要特效仍以 Phaser 程序化绘制为主，正式位图环境资源尚未接入。
6. 外部资源包含 CC0、CC-BY、OGA-BY 等不同授权，不能只维护文件而忽略来源和署名义务。

## 范围

本次台账覆盖：

1. 玩家、人物和感染体资源。
2. 武器与军械资源。
3. 处理后玩家战斗所用武器和感染体帧条。
4. 当前项目内程序化场景、场景物和漫画特效。
5. 已核验的场景环境候选资源及其来源页面。
6. 各类资源的当前状态和主要维护约束。

## 不做项

1. 本次不下载新的完整场景素材包到仓库。
2. 不修改 `PreloadScene`、资源管理器、实体或场景实现。
3. 不调整角色、感染体、武器和场景的显示比例或美术风格。
4. 不删除现有 ZIP、源文件、许可证或署名文件。
5. 不执行构建、类型检查或运行时冒烟；本次仅修改 Markdown 文档。

## 操作步骤

1. 汇总所有现有 `SOURCE.md`、许可证和署名文件。
2. 通过运行时导入和资源管理器确认每个素材的实际使用位置。
3. 通过处理脚本确认派生文件与原始素材之间的对应关系。
4. 为外部素材建立分类表格，并标记当前状态。
5. 为程序化视觉建立独立表格，避免将其误记为外部下载资源。
6. 为场景候选资源建立未下载清单，记录用途、来源和授权。
7. 增加新增、接入、替换和发布前的维护规则。
8. 检查全部本地路径、网页链接、许可证和运行时映射。

## 实施建议

1. 台账只记录已经从代码、资源文件或来源页面确认的事实。
2. 候选资源必须明确标记为“候选未下载”，不能计入正式项目资产。
3. 一个外部资源包只维护一条主记录；派生文件在派生资源表中引用主来源。
4. 后续新增素材时先保存原始文件、来源和许可证，再创建处理后文件和运行时映射。
5. 场景资源优先选择 CC0 和统一的 16x16 或 32x32 正交像素素材。

## 潜在风险分析

1. 现有部分资源 README 的“尚未接入”描述可能已落后于当前代码，台账状态必须以运行时导入为准。
2. 同一来源包可能同时包含人物、感染体、场景和武器，分类时需要避免重复登记造成状态漂移。
3. CC-BY、OGA-BY 和 CC-BY-SA 的署名及派生约束不同，不能统一按 CC0 处理。
4. 外部网页或下载链接未来可能失效，应同时保留本地原始文件、许可证和哈希记录。
5. 候选场景资源视角、像素密度和色板不一致，下载不代表可以直接接入。

## 优化方案

1. 使用固定状态枚举：已接入、部分接入、已下载未接入、候选未下载、项目内生成。
2. 外部资源表统一包含许可证列，发布检查时可直接筛选需要署名的条目。
3. 派生资源统一记录生成脚本，避免无法复现的手工改图。
4. 场景候选按关卡用途记录，后续可以直接建立每关资源白名单。
5. 未来接入正式场景资源后，将候选记录迁移到已下载或已接入表，不保留重复条目。

## 验证方式

1. 检查台账覆盖当前 `PreloadScene` 的全部外部图片导入。
2. 检查台账覆盖两个素材处理脚本的全部输入和输出。
3. 检查每个已下载外部资源都有来源网站、来源链接和许可证。
4. 检查候选场景资源均明确标记为未下载。
5. 检查 Markdown 表格可以正常解析，仓库内路径真实存在。
6. 检查本次 Git 差异只包含预期的 Markdown 文档。
