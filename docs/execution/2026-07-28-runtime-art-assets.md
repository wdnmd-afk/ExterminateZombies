# 关卡人物、僵尸与武器素材接入执行文档

## 目标

1. 用已经下载并完成许可证核验的真实素材替换关卡中的玩家方块、僵尸圆形和武器字母掉落物。
2. 保留现有移动、瞄准、对象池、碰撞体、伤害、掉落、拾取、动画事件和游戏数值，不通过视觉改造改变玩法结果。
3. 玩家持枪外观随当前武器切换，枪口视觉方向与子弹生成方向一致。
4. 僵尸根据实际移动方向播放正确的四方向行走动画，并用不同素材、尺寸和警示轮廓区分普通、快速、坦克、爆炸与 Boss。
5. 武器掉落在实际战场中显示沙漠之鹰、MP5、M4A1 或 SPAS-12 的真实像素图。

## 范围

预计涉及：

1. 新增 `src/systems/GameAssetManager.ts`：管理纹理 key、素材帧、四方向动画和运行时透明武器纹理。
2. 修改 `src/scenes/PreloadScene.ts`：加载玩家、僵尸和武器来源图，并在加载完成后建立运行时帧与动画。
3. 修改 `src/entities/Player.ts`：用人物精灵和真实武器图替换程序化方块/枪管。
4. 修改 `src/entities/Zombie.ts`：用方向动画精灵替换程序化圆形。
5. 修改 `src/entities/Pickup.ts`：武器掉落显示真实武器图，非武器掉落保留现有识别方式。
6. 修改 `src/scenes/GameScene.ts`：监听准确的武器切换事件，同步玩家持枪外观。
7. 更新素材来源说明和本执行文档的执行结果。

明确不修改：

1. `WeaponDef`、`ZombieDef`、关卡波次、掉落概率和弹药数量。
2. 玩家与僵尸物理半径、速度、伤害和攻击间隔。
3. `WeaponManager` 的射击、换弹、切枪和弹药逻辑。
4. 存档字段、路由/场景流程、首页和武器库交互。
5. 本轮不执行全量构建。

## 已确认的素材布局

### 玩家

- 来源：`Ghostbyte Action/Horror TopDownCharacter 48x48`，CC-BY 3.0。
- 使用文件：`Personnage_vue_dessous_bras.png`。
- 尺寸：`576 × 48`，横向 12 帧，每帧 `48 × 48`。
- 原始角色手臂朝上；作为玩家子精灵预旋转 90°，使容器零旋转时手臂朝右，与现有瞄准坐标系一致。

### 普通、快速与爆炸僵尸

- 来源：`Zombie RPG sprites`，CC0 1.0。
- 使用文件：1、2、6 号精灵表。
- 每行实际有 3 帧，帧左边界为 `1 / 47 / 93`，单帧 `31 × 36`；不能按 `31 × 36` 等距精灵表直接加载。
- 四行方向已通过逐帧检查确认：下、右、上、左。

### 坦克与坦克 Boss

- 来源：`Zombie and Skeleton 32x48`，CC0 1.0。
- 使用原图左侧前三列的粗壮僵尸，每个逻辑单元格 `32 × 64`。
- 四行方向已确认：下、左、右、上；每个方向 3 帧。
- 普通坦克与 Boss 复用原始帧，仅通过显示尺寸和警示轮廓区分，不复制或伪造新素材。

### 武器

- 来源：两套已下载 CC0 枪械素材。
- 沙漠之鹰使用来源图中已确认的独立透明侧视区域。
- SPAS-12、MP5、M4A1 使用 128px 主枪械精灵表第 8、9、15 帧。
- 主枪械表内部包含 `#dedede` / `#f4f4f4` 的纯色展示底和顶部标签。原始文件保持不变；加载后在内存 Canvas 中清除顶部标签行和这两种精确背景色，生成只供关卡显示的透明纹理。

## 视觉与交互方案

### 视觉主张

战场采用“清晰像素轮廓 + 克制战术标识”：实体本身承担识别，圆环、阴影和闪烁只用于玩家定位、爆炸警告和 Boss 等级，不重新堆叠占位几何。

### 内容规划

1. 玩家：清晰人物主体、朝向手臂、当前武器和低调定位环。
2. 僵尸：多种外观、方向行走帧、脚底阴影；爆炸类和 Boss 才显示额外警示环。
3. 掉落物：真实武器图位于战术底座上；弹药、生命和道具仍用高识别度符号。

### 交互主张

1. 玩家移动时播放 12 帧行走动画，停止时回到稳定站姿。
2. 开火时武器短促后坐和高亮，不缩放整个角色到破坏瞄准中心。
3. 僵尸根据速度主轴切换上下左右动画，爆炸类警示环使用时间函数脉冲，避免为对象池创建永久 Tween。

## 操作步骤

1. 在预加载场景导入五类来源图：玩家、普通僵尸、快速僵尸、爆炸僵尸、粗壮僵尸。
2. 新增素材管理器：
   - 统一纹理与动画 key。
   - 为非等距僵尸表增加准确帧定义。
   - 为六种僵尸类型建立四方向动画。
   - 从原始武器纹理建立运行时透明武器帧。
3. 重构玩家视觉子对象：
   - 保留同一 Container 与 Arcade Body。
   - 增加人物精灵、武器精灵、阴影和定位环。
   - 新增准确的 `setWeapon`，同步武器纹理、显示比例和枪口长度。
4. 重构僵尸视觉子对象：
   - 保留对象池、生命、攻击、速度和 Body。
   - `spawn` 时重置纹理、动画、缩放、色调和警示状态。
   - `seek` 时根据最终速度选择方向动画。
5. 重构武器掉落视觉：
   - `drop.type === 'weapon'` 时使用真实武器图。
   - 其它掉落沿用现有颜色和符号。
6. 在 `GameScene` 监听 `weaponChanged`，初始创建、拾取和切枪时同步玩家持枪图；场景销毁时解除监听。
7. 执行类型检查、素材纹理探针、三关与无尽模式运行时冒烟和截图检查。

## 实施建议

1. 所有源图继续保存在 `src/assets/downloaded/`，不覆盖、不改写。
2. 运行时武器透明化只移除已确认的精确背景色，不使用宽容色差，以免误删枪械金属高光。
3. 僵尸帧定义必须显式记录真实 x 坐标，禁止通过错误的等宽切片碰运气。
4. 动画 key 以僵尸类型和方向组成，确保对象池复用时不会沿用上一种僵尸的动画。
5. 视觉精灵使用最近邻过滤；高清显示管理继续负责 Canvas 与文字清晰度。

## 潜在风险分析

1. 玩家素材和僵尸素材来自不同作者，色板略有差异；通过一致的整数像素尺度、脚底阴影和战术环控制拼贴感。
2. 侧视枪械图用于小尺寸俯视持枪展示，不能完全等同于专门绘制的俯视枪；本轮以型号识别和真实掉落显示为优先。
3. 对象池复用时若没有重置动画、色调、缩放或可见状态，会出现上一只僵尸的视觉残留。
4. Container 旋转会同时旋转椭圆阴影，需要对玩家阴影做反向旋转保持落地感。
5. 运行时 Canvas 在 WebGL 下必须刷新纹理，否则透明化结果不会上传到 GPU。
6. CC-BY 3.0 玩家素材正式发布时必须保留 Ghostbyte_dev 署名；现有 `ATTRIBUTION.md` 已记录推荐文本。

## 优化方案

1. 动画全局只创建一次，所有对象池实体复用，不为每个实体重复生成纹理。
2. 武器透明化只在 Preload 完成后执行一次，运行时切枪仅调用 `setTexture`/`setScale`。
3. 僵尸方向只在主轴方向改变时切换动画，不每帧重新 `play`。
4. 爆炸警示脉冲由时间函数更新，不建立无限循环 Tween。
5. 保留简单阴影和环形标识，删除方块、圆形主体等重复视觉层。

## 验证方式

1. `npm run typecheck` 必须通过。
2. 验证玩家动画 12 帧、三套普通僵尸 12 帧和粗壮僵尸来源帧均成功注册。
3. 进入关卡后确认玩家不再显示蓝色方块，僵尸不再显示纯色圆形。
4. 模拟移动和鼠标瞄准，确认玩家人物、手臂、武器与枪口方向一致。
5. 触发或直接生成四种可用武器，确认玩家持枪和武器掉落图同步切换。
6. 逐个生成六类僵尸，确认方向动画、尺寸、警示环和对象池重用无残留。
7. 运行第一、二、三关和无尽模式，确认 GameScene/HUD 均激活且无未处理异常。
8. 截图检查像素边缘、实体可读性、缩放和透明背景。
9. 不执行 `npm run build`，除非用户另行明确授权。
