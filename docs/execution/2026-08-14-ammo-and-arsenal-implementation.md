## 5. 实施建议

1. 弹药选择、库存缺口和武器可用性优先写成与 Phaser 无关的纯函数。
2. `GameScene` 只编排掉落实例和存档副作用，不继续堆积概率算法。
3. 自适应掉落必须先解析成带准确 `ammoType` 和 `amount` 的固定拾取物，`Pickup` 不判断玩家状态。
4. HUD 和输入必须读取同一个武器可用性函数。
5. 主武器选择复用主菜单任务简报区和现有武器贴图，不新增独立场景。
6. 第一关强制手枪；第二关、后续关卡和无尽使用已保存的合法主武器。
7. 旧存档缺少新字段时必须明确补为 `['pistol']` 与 `'pistol'`，非法武器 ID 过滤。

## 6. 潜在风险

| 风险 | 影响 | 控制方式 |
| --- | --- | --- |
| `DropDef` 契约变化 | 配置、Pickup、测试同时类型失败 | 使用判别联合并逐个更新调用点 |
| 自适应算法多次随机 | 固定种子测试不可复现 | 随机函数显式注入，每个机会的调用顺序固定 |
| 第二关固定奖励叠加随机补给 | 弹药过量 | 第二关继续屏蔽随机武器/强化；固定弹药不进入保底计数 |
| 共享重型弹药偏向 Barrett | 高伤武器弹药过多 | 重型单次补给保持 12，完整试玩后再决定是否拆分 |
| 主菜单空间不足 | 简报、按钮和选择器重叠 | 压缩右侧纵向节奏，不改变左侧十关列表与页脚位置 |
| HUD 军械带遮挡 | 高密度战场可读性下降 | 固定附着左上既有面板，4×2 稳定尺寸，不占中央/底部 |
| 下一关/重开绕过选择 | 主武器退回手枪 | 下一关先回主菜单确认整备；失败重开读取合法偏好并显式传参 |
| 存档重置遗漏 | 清进度后仍保留武器许可 | `resetProgress` 与 `resetAll` 同步重置许可和偏好 |

## 7. 优化方案

1. 第一版不调整伤害、敌人生命和波次数量，先隔离弹药类型与数量问题。
2. 补给统计写入 `GameState.stats` 并传入结算场景，为后续平衡提供真实样本。
3. 军械槽使用已有武器贴图和短名，不重复加载新资源。
4. 重复武器超载放到独立后续 Goal，避免本轮变量失控。
5. 若 HUD 八槽实景过密，优先缩短标签和收紧间距，不隐藏空弹武器。
