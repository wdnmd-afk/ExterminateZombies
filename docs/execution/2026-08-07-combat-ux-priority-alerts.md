## 0. 实施结果（2026-08-10）

1. 新增 `src/config/combatAlerts.ts`，统一定义 `status / warning / danger` 三种语气、优先级、显示时长、空弹文案和四类 Boss 能力文案。

3. `EnemyAbilitySystem` 仅在 Boss 能力进入前摇时发送全局危险警报，普通感染体继续使用局部战场预警；警报完整时长与真实前摇一致。

5. HUD 已增加固定尺寸战斗警报带；低优先级不能覆盖高优先级危险，同 key 事件可以刷新显示时长。
6. 弹药区已增加 238px 固定宽度进度条；正常、低弹、空弹和换弹使用不同颜色，换弹期间实时显示剩余秒数。
7. 拾取 Toast 改为单实例复用；连续拾取只更新同一组底板和文字，不再创建多个重叠容器。
8. ESC 菜单或抽卡冻结期间，战斗警报与拾取 Toast 的 Tween 会暂停；解除冻结后继续剩余动画，弹药状态同步刷新。
9. 新增 `tests/combat-alerts.test.ts`，覆盖空弹文案、四类 Boss 能力映射和警报优先级规则；按项目规则本轮未执行测试。
10. 已完成调用链审阅与 `git diff --check`；Vite 对入口、HUD、GameScene、WeaponManager、EnemyAbilitySystem 和 combatAlerts 模块的转换请求均返回 200。
11. 当前会话没有可用浏览器，未完成 `1280x720` 画布截图、空弹/换弹/Boss 前摇/暂停恢复/连续拾取的实机交互验收；未执行 `npm test`、`npm run typecheck` 或构建。

## 1. 目标

把现有 HUD 从“能显示数据”校正为“能在战斗中快速判断状态”，重点解决三类问题：

1. Boss 技能前摇只有战场图形，没有稳定的文字层级提示。
2. 空弹与换弹虽然有声音和文字，但状态分散，玩家需要持续盯着弹药数字。
3. 连续拾取会创建多个同位置 Toast，造成文字和底板重叠。

## 2. 范围

本轮修改：

1. 建立共享的战斗警报数据契约与 Boss 能力文案映射。
2. 空弹时发送中优先级警报；Boss 技能前摇发送高优先级危险警报。
3. HUD 增加独立战斗警报带，低优先级事件不得覆盖正在显示的高优先级危险。
4. 弹药区增加稳定尺寸的弹匣/换弹进度条，并按正常、低弹、空弹、换弹分色。
5. 换弹时显示实时剩余秒数，而不是固定的完整换弹毫秒数。
6. 拾取 Toast 改为单实例复用；连续拾取更新同一个位置，不再叠加多个对象。
7. ESC 暂停或抽卡冻结时暂停战斗警报动画，恢复后继续剩余提示时长。

本轮不做：

1. 不增加教学弹窗、操作说明页或强制暂停引导。
2. 不修改武器伤害、弹匣容量、换弹时长和掉落概率。
3. 不调整 Boss 技能伤害、前摇或行为参数。
4. 不重做整个 HUD，不引入 UI 框架或新资源。
5. 不执行测试、类型检查或构建；需要用户明确同意后另行执行。

## 3. 操作步骤

1. 新增 `CombatAlert` 共享类型，定义 `status / warning / danger` 三种语气、数值优先级和显示时长。
2. 为 Boss 的 `shockwave / bombard / dash / ranged` 能力建立稳定文案映射；普通感染体前摇不进入全局警报层，避免高频噪声。
3. `WeaponManager` 在玩家主动尝试空弹开火时发出一次空弹警报，并公开当前换弹进度、剩余时间和总时长。
4. `GameScene` 只转出换弹状态，不复制武器计时逻辑。
5. `EnemyAbilitySystem` 在 Boss 能力进入 windup 时发出危险警报；持续时间与真实前摇一致。
6. HUD 在波次公告下方建立固定尺寸警报带：高优先级可覆盖低优先级，同级新事件可刷新，低优先级不能打断高优先级。
7. 弹药面板增加 238px 固定宽度进度条；非换弹时表示弹匣比例，换弹时表示实时进度。
8. 弹药数字按比例分色；换弹明细每帧读取剩余时间，暂停后继续使用已平移的真实截止时间。
9. 拾取 Toast 的底板、文字和容器在 `create` 时只创建一次，后续事件只更新内容并重启动画。
10. 关停 HUD 时成对移除新增监听，避免场景复用后重复响应。

## 4. 实施建议

1. 危险提示只表达已经发生的战斗状态，不显示操作教程；躲避方式仍由范围圈、方向带和实际动作传达。
2. 战斗警报、波次公告和拾取 Toast 使用三个固定区域，避免靠优先级逻辑解决物理重叠。
3. 换弹进度由 `WeaponManager` 作为唯一事实来源，HUD 不按武器配置自行倒计时。
4. 空弹警报只在玩家尝试开火时触发，弹匣为零但玩家没有操作时不持续刷屏。
5. 普通感染体技能继续依赖局部预警，只有 Boss 技能进入全局警报层。

## 5. 潜在风险

1. **提示噪声**：自动武器空弹后持续按住开火可能重复触发，必须依赖事件 key 与显示优先级限制刷新频率。
2. **暂停时序**：Boss 前摇被冻结时警报也必须冻结，否则恢复后危险圈还在，文字却已消失。
3. **布局风险**：新增进度条不能压住弹药明细或生命条，固定尺寸和坐标必须保持间距。
4. **状态漂移**：切枪会取消换弹，进度条必须立即回到新武器弹匣比例。
5. **事件泄漏**：HUD 场景反复创建时新增监听必须在 shutdown 中摘除。
6. **长文案风险**：Boss 名称与能力名称组合不得超出警报带宽度。

## 6. 优化方案

1. 后续如增加异常状态，可继续复用警报契约，但必须先证明属于战斗关键状态。
2. 可在浏览器验收后统计警报出现频率，再决定是否增加同 key 冷却；本轮不提前引入计数系统。
3. 若未来需要本地化，将能力文案映射迁入统一文案配置，不在 HUD 内散落条件分支。
4. M1-T04 数值平衡时复用换弹状态接口记录无弹时长，不重复读取私有字段。

## 7. 验证方式

默认执行：

1. 代码审阅：`WeaponManager/EnemyAbilitySystem -> GameScene events -> HUDScene` 调用链一致。
2. 静态检查：提示区域坐标不与顶部状态板、波次公告或底部拾取区重叠。
3. 生命周期检查：HUD 监听、Tween 和单实例 Toast 在场景重建时无残留。
4. `git diff --check`、Vite 模块解析与改动范围检查。

待浏览器可连接后完成：

1. 手枪打空一次，确认空弹警报、自动换弹、实时剩余时间和进度条一致。
2. 自动武器持续按住开火至空弹，确认警报不会连续叠加。
3. 换弹中切枪，确认旧换弹提示和进度立即消失。
4. 第二关 Boss 分别触发震荡与冲锋，确认危险警报与真实前摇同步。
5. Boss 前摇中按 ESC 暂停 3 秒再恢复，确认警报和危险区同时继续。
6. 连续拾取至少 3 个掉落，确认底部只存在一个 Toast，文字不会重叠。
7. 在 `1280x720` 检查顶部面板、波次公告、警报带与拾取 Toast 无遮挡。
