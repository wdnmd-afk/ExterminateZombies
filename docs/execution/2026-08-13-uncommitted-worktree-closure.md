## 3. 首轮审阅发现

1. M79 已接入一次反弹，但反射轴按弹体相对障碍中心判断；长条障碍的边缘命中可能选择错误轴。反弹后的射程仍按“枪口到当前位置”的直线距离计算，不能表示真实折线路径。
2. Boss 波次已切换独立音乐，但挂起战局返回主菜单后，`GameScene.handleWake()` 无条件切回普通战斗音乐，Boss 战恢复链路未闭环。
3. `RUNTIME_ASSET_MANIFEST.md` 与美术台账把玩家运行时素材登记为 Ghostbyte；实际 `PreloadScene` 加载 Kenney `Survivor 1/survivor1_hold.png`。Credits 因而展示了未实际加载的 Ghostbyte 署名，遗漏当前玩家的 CC0 来源说明。
4. 运行时清单把障碍外观写为 `Obstacle.ts` 程序绘制；实际纹理由 `process_environment_assets.py` 生成、`PreloadScene` 加载，`Obstacle.ts` 只负责显示与碰撞。
5. G2-6、G3-2、G3-3 和 G7-2 均缺少本轮改动后的完整命令或浏览器验证，不能以“完整完成”口径收口。

## 5. 实施建议

1. 反弹规则保持“仅障碍、最多一次”，不扩展敌人或场景物反弹，避免改变已冻结范围。
2. Boss 音乐状态由 `GameScene` 显式保存，不根据当前是否已生成 Boss 猜测，覆盖“已公告但尚未生成”的挂起窗口。
3. 资源治理以真实 import 为准；CC0 可在完整清单中保留来源，但游戏内 Credits 只突出强制署名与清单入口。
4. 当前工作区先整体通过验证，再按 G2、G3、G7 三组提交，避免在验证前机械拆分导致遗漏依赖。

## 6. 潜在风险

1. Phaser Arcade overlap 不提供可靠碰撞法线，最近 AABB 面仍是离散碰撞近似；角点命中需要 V4 实景确认。
2. M79 改为累计路径后，实际爆炸位置可能比旧实现更早到达射程上限，需要试玩判断节奏。
3. 音频文件可静态存在但仍可能被浏览器拒绝解码，V0 不能代替 V3。
4. Credits 文本变更可能在 1280 x 720 画布中溢出，必须通过浏览器截图确认。
5. 当前修改跨 20 个以上源码、测试、文档和二进制资源文件，验证失败时需按 G2/G3/G7 归属定位，不宜继续叠加新功能。

## 7. 优化方案

1. 将反弹面的选择保持为无 Phaser 依赖的纯函数，便于定向回归；`Bullet` 只负责状态与物理体更新。
2. 后续若 M79 角点体验仍不稳定，再引入上一帧位置的扫掠判定；本轮不提前扩大碰撞系统。
3. 发布前从最终构建资源图再次生成运行时清单，防止源码 import 与产物漂移。
4. G3-4 统一处理 Boss 切轨突兀、响度、循环点和多浏览器解码，不在本轮混入主观调音。
