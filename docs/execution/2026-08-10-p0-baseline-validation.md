# 2026-08-10 P0 基线固化与测试链路验收

> 状态：已完成（2026-08-11；V1-V5 客观通过，V6 不在本次范围）
> 依据：`TESTING_RULES.md`、`docs/TESTING.md`、`PROJECT_MASTER_PLAN.md` P0

## 1. 目标

按项目测试门禁完成 P0 基线验收，确认当前代码能通过自动化与类型门槛、主要场景可以真实加载和交互、第一关能从主菜单走到明确结算，并为感染体速度、武器/弹药经济、Boss 机制和局内强化留下可复核记录。

本任务验证“当前版本实际完成到哪里”，不把定向状态注入、单次随机样本或 Agent 客观检查扩大解释为正式平衡、真人手感或发布验收。

## 2. 范围

1. V1：执行全部 Vitest，记录文件数、用例数、失败信息和退出码。
2. V2：执行 `tsc --noEmit`，记录类型错误和退出码。
3. V3：冷启动并检查主菜单、资料页、设置、固定关卡、无尽与抽卡场景的加载、资源、控制台和公开状态。
4. V4：使用真实键鼠覆盖移动、瞄准、射击、换弹、切枪、暂停/恢复、掉落/强化以及 Boss/感染体客观机制。
5. V5：从主菜单真实进入第一关，持续操作到 `LevelClearScene` 或首次稳定阻塞缺陷。
6. 同步 `docs/TESTING.md`、P0 状态与本执行文档中的实际结果、证据和剩余风险。

## 3. 不做项

1. 不执行 `npm run build`，不安装或升级依赖，不新增独立 Playwright/CDP 工程。
2. 不把目标场景直达、敌人生成或生命调整写成完整关卡通过。
3. 不替真人判断手感、乐趣、难度舒适度、混音或正式画面质量。
4. 不扩充关卡、武器、感染体或系统，不进行与测试发现无关的重构。

## 4. 操作步骤

1. 记录 Node、npm、Vitest、TypeScript、Vite、测试开关、服务端口与 Browser 前提。
2. 执行 `npm test`，首次失败先保留完整输出；仅修复本轮代码或明确阻塞 P0 的真实缺陷。
3. 执行 `npm run typecheck`，按相同规则处理错误并复测。
4. 连接集成 Browser，注册控制台、页面异常、失败请求和关键响应监听，再导航到现有 Vite 服务。
5. 检查 Canvas、逻辑尺寸、主菜单和资料/设置场景；逐个固定关卡与无尽模式确认可启动。
6. 通过真实输入验收第一关基础战斗、HUD、暂停、掉落和强化；通过明确标注的定向前置覆盖难以在短流程稳定遇到的敌人与 Boss。
7. 从干净第一关重新走玩家路径，持续到通关或首次阻塞缺陷，保存基线、关键操作与最终状态证据。
8. 清理本轮按键、标签页和测试存档，保留失败首证据与结果文档。

## 5. 实施建议

1. 浏览器证据按“真实输入 -> 可见反馈 -> 公开状态探针”记录，Canvas 交互不依赖 DOM 文本定位。
2. 第一关完整流程不得使用清敌、改血、跳波或直接启动结算；定向机制用例与完整流程严格分开。
3. 随机掉落只记录本次样本；武器首获、弹药余量与强化层数不以一次结果直接调整平衡。
4. 发现失败后从干净场景复跑一次，区分稳定产品缺陷、测试脚本问题和环境问题。

## 6. 潜在风险

1. 集成 Browser 可能无法连接或无法稳定发送 Canvas 连续输入，导致 V3-V5 受阻。
2. 第一关完整流程可能耗时较长；自动输入策略若无法保证存活，不能用内部方法伪造通关。
3. 18 类感染体不可能全部在第一关自然出现，定向机制前置只能证明单体链路，不能证明关卡编排和平衡。
4. 音频自动化只能证明资源、触发和生命周期，不能证明听感。
5. 当前工作区有大量未提交修改；任何修复都必须保留既有用户改动并控制范围。

## 7. 优化方案

1. 本轮记录浏览器控制、探针和证据采集中的稳定步骤，为后续正式 E2E 选择提供输入。
2. 将过时的“8 把测试武器”“仅二/三关 Boss”等清单改为当前配置派生事实。
3. 若完整第一关暴露重复性人工成本，后续单独设计正式、可审核且不污染生产行为的测试夹具。

## 8. 验证方式与通过标准

1. V1：`npm test` 退出码 0，全部测试零失败。
2. V2：`npm run typecheck` 退出码 0，TypeScript 零错误。
3. V3：页面、Canvas 和目标场景可加载；无相关未捕获异常、`console.error` 或关键资源失败。
4. V4：真实键鼠输入产生对应状态和画面变化；定向 Boss/感染体用例完整覆盖前摇、执行或受击/死亡关键链路。
5. V5：第一关从主菜单进入，经真实战斗到达 `LevelClearScene`，且解锁状态与结算一致。
6. P0 只有在 `PROJECT_MASTER_PLAN.md` 的全部完成门槛均有证据时才能标记完成；否则记录为部分通过或受阻。
