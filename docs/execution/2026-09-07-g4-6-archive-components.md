## 1. 目标

抽取武器库和怪物图鉴重复的页面背景、标题横幅、索引列表、详情面板外壳、页脚和入场动效，统一两页的键盘导航入口。保留各自的数据读取、武器许可与编队规则、怪物预览帧和详情动画。

G6-6 的正式数量曲线仍依赖试玩与数值冻结；本批次先推进不依赖战斗平衡的 G4-6，不将模板校验通过当作批量扩关验收通过。

## 2. 已确认的现状

- Phaser 场景链：主菜单分别进入 `WeaponLibraryScene` / `MonsterLibraryScene`，两页返回主菜单并沿用菜单音乐。
- 武器库按行优先排列，已使用 `computeRowGrid()`；仅绑定 ESC，缺少键盘浏览与编队操作。
- 怪物图鉴按列优先排列，支持方向键/WASD 和 ESC；行距仍使用独立的行中心公式，盒高固定为 48。
- 图鉴当前 18 项时末行底边为 662，尚未越过实际页脚线 674；增加到 20 项时旧行距变为 47，小于 48 的盒高，会相邻叠行。不能将其描述成当前 18 项已压住页脚。
- 两页的字段、状态与调用链已经核对：`WEAPON_LIBRARY` / `MONSTER_LIBRARY` → 索引选中 → 详情展示；编队仍只由 `toggleLoadoutWeapon()` 与 `SaveManager.setWeaponLoadout()` 修改。
- `src/ui/components.ts` 已有菜单/结算按钮，本批次不改其行为，不把所有矩形都泛化成组件。

## 5. 操作步骤

1. 完成两页及其布局、预览、配置、主菜单入口和相邻公共组件的预读，确认数据与事件所有权。
2. 写入本执行文档，再实现纯布局与导航函数；继续复用 `computeRowGrid()`，不复制第三套行距公式。
3. 抽取真正重复的横幅、列表项、面板外壳、页脚和入场动效；保持动态文本引用可由原场景更新。
4. 逐页替换渲染代码，业务选择、许可、六武器上限、必带手枪、Boss 标记和预览缩放保持原函数负责。
5. 补武器库键盘浏览/确认、两页 Home/End 和对称的键盘监听清理，防止重进页面重复响应。
6. 增加当前数量、增长数量、旧公式失败证据、排列顺序、循环导航、空列表和未知按键的回归用例。
7. 静态核对调用链、布局坐标、动态引用、事件清理和改动范围；同步进度与本批次未验证事项。

## 6. 实施建议与优化方案

- 只抽展示层与纯计算，不创建跨场景业务状态或第二套 SaveManager。
- 枚举区分两种真实档案布局，避免堆叠多个互相影响的布尔参数。
- 标题、列表、详情和页脚仍返回原场景可持有的 Phaser 对象；组装进 Container 时保持前后绘制层级。
- 列表文本的垂直偏移随盒高计算，避免盒高缩小后第二行文字溢出；当前视觉不要求重做。
- 几何测试只证明不越界、不叠行，不据此声称任意数量仍清晰可读；更大内容规模需分页或滚动设计。
- 不新增依赖、不生成图片、不修改已完成的 G6-6 门禁代码。

## 7. 潜在风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 场景重新持有了错误文本引用 | 选中后详情或编队状态不更新 | 保留原字段名，逐一核对组件返回值与写入点 |
| 列优先和行优先混淆 | 键盘方向与原列表顺序不一致 | 纯函数用例分别覆盖两种排列与循环边界 |
| 导航监听未清理 | 重进页面触发多次编队操作 | 场景统一注册/移除同一函数，确认键忽略 repeat |
| 容器成员重复挂载 | 图层丢失或位移叠加 | 组件对象仅加入一次最终容器，保留入场组划分 |
| 重构扩大到业务逻辑 | 武器许可、容量、预览帧改变 | 不改选择/编队规则与预览计算，键盘复用鼠标回调 |
| 小盒高内部文字溢出 | 行间不重叠但仍不可读 | 使用比例偏移，并保留浏览器视觉验收待办 |
