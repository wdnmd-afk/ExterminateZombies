## 2. 俯视实机贴图

### 2.1 为什么必须换视角

侧视枪画进俯视游戏有两处硬伤，且互相牵制：

1. 下垂的弹匣、扳机护圈与握把在俯视空间里等于朝人物侧面**横向支出**，
   无论锚点怎么调都读成「贴了一张侧面图」。
2. 握把必须被人物的手完全盖住，这条约束反过来锁死武器缩放——上一轮手枪被压到
   `0.74`、MP5 被压到 `0.34` 才藏得住握把，而这两个值与枪本身的长短没有关系。

俯视图从上往下看不到握把与弹匣，只剩枪托、机匣、护木、枪管与装在顶上的瞄具，
两处硬伤同时消失。实测遮挡露出量从「侧视时代的 4%~11%、最深 3.7 世界像素」
变成「最深 3.5 世界像素、且每把枪都只有固定的 7px」（§5）。

### 2.2 产物与管线

| 文件 | 作用 |
| --- | --- |
| `scripts/weapon_topdown_specs.json` | 11 把枪的构图数据：沿枪身的分节、半宽、颜色角色、瞄具与供弹箱的位置 |
| `scripts/lib_weapon_draw.py` | 绘制原语（taper / ellipse / box / quad / ribs）与统一光影、描边。俯视与侧视两条管线共用，避免同一把枪的两个视角逐渐画成两种风格 |
| `scripts/process_weapon_topdown_assets.py` | 读 spec 出图，并打印 `gripX / boreY / muzzleX` 供粘贴到 `WeaponAssetManager.ts` |
| `src/assets/processed/weapons/topdown/*.png` | 产物，49x23 ~ 125x31 |

配色取自各枪**侧视图的实测主色**（逐张统计不透明像素频次），所以 AK 保留木质护木、
Barrett 保留沙色机匣、黄金 M249 保留金色、加特林保留红色面板、火焰喷射器保留橙罐与警示黄。

### 2.3 缩放统一为 0.5

`WEAPON_TOPDOWN_SCALE = 0.5`，不按枪逐个调。俯视贴图是按「实机世界像素 x 2」的
统一网格画的，各枪长短差异已经体现在贴图长度里；再按枪改缩放等于同一套像素美术
在不同武器上有不同的像素颗粒度，切枪时会看出颗粒跳变。

### 2.4 两套贴图的分工

侧视图**没有动**，继续供 HUD 槽位、战前整备、武器库预览与掉落物使用——
那些位置是平面图标，侧视轮廓最容易认出枪型。代码上分成
`GAME_WEAPON_TEXTURE_KEYS`（侧视图标）与 `GAME_WEAPON_TOPDOWN_TEXTURE_KEYS`（俯视实机），
与 `CHARACTER_TEXTURE_KEYS` / `CHARACTER_PORTRAIT_TEXTURE_KEYS` 是同一种分层理由。

## 3. 三把重火力的侧视图标重画

另外八把的侧视图是从 CC0 像素枪械表裁下来的真实美术；这三把在素材库里没有可用
的侧视原图，只能自己画。上一版 `scripts/process_heavy_weapon_assets.ps1` 用 GDI+
的十来个图元堆出来，武器库按 2.35 倍放大显示时缺陷最明显：加特林是一个黑箱子加
几条横线，金色 M249 基本是一团金色色块，火焰喷射器是圆圈加三角。

重画后三把都有了枪托、握把、扳机护圈、供弹与枪管分节：加特林有后握把、红色面板、
顶部提把、下方弹鼓、五根枪管与前端护圈；M249 有枪托、提把、斜握把、供弹箱、
散热护木与人字脚架；喷火器有燃料罐、警示条、顶部调压阀、S 形软管、握把、前握把与喷嘴。

**画幅锁定 132x48**：`weaponLibrary.ts` 的预览缩放按枪写死（三把都是 2.35），
换画幅会直接改变武器库、HUD 槽位与掉落物的显示大小。脚本对此有断言。

### 3.1 署名情况发生了变化

上一版的三张图里**含有第三方像素**：加特林合入了 Tiamalt 的 CC-BY 3.0 枪管，
金色 M249 是 Kenney `weapon_machine.png` 的重着色，喷火器采样了 TheJosh 贴图的两个像素。
重画后三张图**完全由项目绘制，不含任何第三方像素**，配色以十六进制字面量写在 spec 里。

三个素材包仍归档在仓库中，署名义务不变，但用途已降级为「型号 / 配色参考」。
已同步：`docs/ART_ASSET_REGISTRY.md` §10.1、`docs/RUNTIME_ASSET_MANIFEST.md`、
以及 Tiamalt 与 TheJosh 两份 `SOURCE.md`。

`scripts/process_heavy_weapon_assets.ps1` 已删除，而不是留着不用：留着它，
任何人重跑一次就会把更差的图覆盖回去。它同时是仓库里唯一的 PowerShell 素材脚本，
删掉后素材管线统一为 Python 与 Node。

## 4. 连带修正

1. **守望者实机精灵换代**。并行会话在本轮期间把它从 `64x64` 斜视图（带 164 个品红
   描边像素）换成 `48x48` 正俯视 v03 产物，品红残留归零。它的握枪锚点因此重测，
   由 `{ forward: 13.7, boreSide: -8.1 }` 改为 `{ forward: 13, boreSide: -1 }`——
   新图的手抬在瞄准中线上，而不是旧图那样偏在上方。
2. **人物缩放改成角色数据**。`KENNEY_SPRITE_SCALE = 1.08` 与
   `GENERATED_SPRITE_SCALE = 1.15` 移到 `characters.ts`，`CharacterDef.spriteScale`
   逐角色指定，`Player` 不再读模块常量。原因：握枪锚点也量在人物贴图上、也要乘这个
   倍率，两者必须同源，否则换素材时改了一处忘了另一处，武器会整体偏移。
3. **验收脚本的抽取器加了失败即抛错**。`scale` 从字面量改成 `WEAPON_TOPDOWN_SCALE`
   常量后，旧正则静默失配，求解脚本对着空表跑出「全部通过」。现在抽不满 11 把武器
   或 5 个角色直接抛错，并且能回填源码里的数字常量。

## 5. 验收

1. `npx tsc --noEmit`：本轮触及的文件零错误。仓库另有三类先行存在的错误
   （`letterSpacing`、`PreparationScene` 的 `setDepth`、`SettingsScene` 的 `weapon6`），
   全部落在本轮未修改的文件里。
2. `npx vitest run` 仍无法启动（`vite` 子路径 `./module-runner` 未导出），先行问题。
3. 遮挡与枪口判据（`TmpGenerate/assert-grip.mjs`，从 TS 源码读实际提交值）全部通过：
   - `muzzleX` 与贴图最右不透明列相差 ≤ 3px，且 `boreY` 在枪口列上是不透明像素；
   - 俯视图在握把列上下厚度大致对称（不对称说明 `boreY` 标错，实机上枪会偏出一侧）；
   - 枪膛线以下露在手层外面 ≤ 12px 且最深 ≤ 5 世界像素。实测 11 把均为 7px / 3.5。
   
   判据从占比改成绝对量：实测每把枪都恰好露出 7px，那是手层轮廓在取样窗口一角的
   固定切口，与枪无关；用占比会让细长的 RPG 判成 11%、粗壮的加特林判成 4%，
   同一个瑕疵得出两个结论。
4. 离线合成复核（`TmpGenerate/verify-grip.mjs`）：11 把武器 × 堡垒 / 守望者
   × 0°/90° 逐张目视，手压在枪上、枪身探出人物轮廓、枪口十字落在枪管末端。
5. 未做：浏览器实机截图验收（`npm run dev` + 目视/CDP）。

## 6. 遗留

1. **键控残留是全项目问题，不只是守望者。** 扫描 `src/assets/processed/` 下全部
   PNG，49 个文件有品红/紫溢色。判别方法：溢色像素贴在 alpha 边缘的属于键控没抠净，
   长在主体内部的很可能是本来就有的紫色美术（淤伤、Boss 能量特效）。
   
   | 文件 | 溢色像素 | 其中强溢色 | 边缘占比 | 判定 |
   | --- | ---: | ---: | ---: | --- |
   | `zombies/walker-directional-custom.png` | 68116 | 23639 | 98.2% | 键控残留，可批量去溢 |
   | `characters/portrait-watcher.png` | 6646 | 4104 | 97.4% | 键控残留，可批量去溢 |
   | `zombies/walker-portrait.png` | 2299 | 647 | 98.6% | 键控残留，可批量去溢 |
   | `zombies/crawler-directional-custom.png` | 2457 | 798 | **47.6%** | **内部占 52%，多半是真紫色美术，不要盲目去溢** |
   | 其余 45 个文件 | 各 1~2304 | — | 未逐一测 | 需分别判别 |
   
   本轮没有批量去溢，正是因为 crawler 这个反例：同一个「品红溢色」判据在不同文件上
   会得出相反结论。建议单独一轮处理，只对边缘占比 > 95% 的文件批量修，
   其余逐张过目。走影响最大的两个（`walker-directional`、`portrait-watcher`）就能
   拿掉全部溢色像素的 91%。
2. 俯视贴图目前是**静态单图**，没有开火抖动之外的枪机动画（后拉套筒、弹链滚动、
   加特林转管）。spec 语法已经支持分节，加动画帧的成本主要在运行时切帧与动画表。
3. 手枪的俯视图偏朴素——它只有 44 像素长，能放的细节有限。若要更强的辨识度，
   需要把手枪的显示长度整体调大，那会牵动手感与瞄准读数，属于设计决定。
