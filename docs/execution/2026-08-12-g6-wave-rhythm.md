## 1. 目标

把第二关「废车站」从约 3.5 分钟的原型撑到 D-002 锁定的 10-15 分钟，并且**靠密度与节奏而不是空等**填满时长。

## 2. 核心设计问题与解法

### 2.1 「3 个阶段」与「大量敌人」的结构冲突

D-002 已冻结标准关为 **3 个常规阶段 + 1 个 Boss 节点**，`validate.ts` 也在校验 `waves.length === 3`。但原来的 `WaveManager` 把「阶段」与「生成波」1:1 绑定：一个阶段 = 一次全量生成 + 一次清场判定。

于是想把总量提到 300+ 只就只有两条路：
1. 一个阶段一次放 100+ 只 → 全部同屏、平铺直叙的消耗战，正是 `FUN_FIRST_DESIGN` §1 法则 3 要避免的平直曲线。
2. 增加阶段数 → 违反 D-002 与切片白名单。

**解法：在阶段内部引入「生成段落」（`WaveSegmentDef`）。** 一个阶段由多个段落顺序执行，每个段落有自己的敌群、生成间隔、前置静默与同屏上限；但清场判定与阶段奖励仍然只结算一次。

这样：

- D-002 的 3 阶段 / 2 次保证强化 / Boss 节点结构完全不变。
- 阶段内部能做出 准备 → 积压 → 释放 → 收束 的节奏（`PROJECT_MASTER_PLAN` §5.7 正式关卡模板的要求）。
- 同屏敌人数由段落上限约束，不会一次性堆满。

### 2.2 同屏上限是密度与帧率之间的唯一闸门

`concurrentCap` 达到上限时暂停生成（不消耗队列、不跳过任何一只），直到场上敌人降到上限以下。它同时解决三件事：

1. **爽感**：屏幕持续保持饱和，而不是「先空后挤」。
2. **性能**：同屏上限即活跃实体上限，为 G6-3 的帧率压测提供确定的档位。
3. **时长**：总量由玩家清杀速度自然消化，强者快、弱者慢，而不是靠拉长静默。

切片段落上限带宽为 18-40。上限的上限写在 `P2_VERTICAL_SLICE.maxConcurrentEnemies = 40`，理由是性能预算的最低测试档位是 50 活跃敌人（`PROJECT_MASTER_PLAN` §5.15），在完成实测前不越过该档位。

### 2.3 时长必须区分「下界」与「实际」

`getWaveSpawnDurationMs` 给出的是**生成排程下界**：即使玩家瞬间清空每一只，三个常规阶段也至少要跑这么久。实际时长 = `max(生成排程, 清杀耗时)`，只能靠试玩测量。

本轮把下界设计在 **3.4 分钟**，把总量设计在 **347 只**。按 0.5-0.7 只/秒的清杀速度推算实际约 **8-11 分钟**，加 Boss 约 **10-13 分钟**。这个推算是设计假设，不是结论。

### 2.4 与设计文档 150-200 只目标的偏差

`FUN_FIRST_DESIGN` §3.3 写的目标是「150-200 只」。该数字是按**改造前**的玩家输出推算的（P0 记录：第一关 38 只用了 181 秒，约 0.21 只/秒）。G2 已把切片四把武器的输出大致翻倍，150-200 只在新数值下只能撑约 5-6 分钟，与 D-002 锁定的 10-15 分钟冲突。

**取舍：以 D-002（已确认决策）为准，把总量定在 347 只。** 348 只不是精算结果，而是「相对基线 46 只提升 7.5 倍、下界 3.4 分钟、推算 10-13 分钟」这三个约束下的一个可测起点。V6 实测后按单一旋钮（各段落 count）调整。

### 5.1 跨关不变量的重新界定（需要说明的测试改动）

原来有三条跨全部十关的不变量：阶段数只增不减、生命预算单调递进、最终关规模最大。第二关升级为正式关卡后，它的规模必然远超仍是 3 分钟原型的第 3-10 关，这三条不变量在切片与原型之间不再成立。

按 P1 冻结文档「不把现有十个原型关卡认定为十个正式关卡、P2 只把第二关计为 1 个正式关卡」的口径，把三条不变量的比较范围收敛到**原型关卡之间**，并新增一条正向断言「垂直切片规模显著超过全部原型关卡」。批量重制归 G6-6。

这是规格变化导致的测试范围调整，不是为了让测试通过而放宽断言 —— 原有的单调性在原型集合内仍被完整检查。

## 7. 剩余风险与后续项

1. **实际时长仍是推算**：下界 3.4 分钟已由代码计算确认，8-13 分钟的实际区间靠 0.5-0.7 只/秒的假设推出，必须 V6 实测。调整旋钮是各段落 `count`。
2. **同屏 40 未经帧率验证**：上限带宽是设计值，G6-3 需在 50/100/150 活跃敌人下实测；当前切片刻意压在最低档位以下。
3. **掉落经济未同轮调整**：347 只在现有掉落率下会产出约 28 个生命包与大量弹药。`FUN_FIRST_DESIGN` §6.1 明确要求「血包频繁 → 激进打」「弹药充足 → 爽快用」，因此本轮**刻意不动掉落率**，把「是否过于宽松」列为 V6 观察项，避免无依据的猜测式调参。
4. **强化包与武器掉落已被过滤**：第二关仍只保留弹药/生命/道具经济，段落改造不影响该过滤。
5. **第 3-10 关与切片的规模差距扩大**：原型关卡未动，跨关体验落差明显，归 G6-6 批量重制。
6. **G6 剩余项**：G6-2 剧本时刻系统、G6-3 帧率压测。

### 8.2 架构

```
config/scriptedMoments.ts        编排数据（触发条件 + 播报 + 动作）
systems/ScriptedMomentRules.ts   纯逻辑：触发匹配、一局一次、环形生成点与边界夹取
systems/ScriptedMomentSystem.ts  执行器：把动作落到战场
WaveManager.onSegmentStarted     新增回调，让时刻能精确定位到某个段落
GameScene                        首杀通知、每帧心跳、按坐标生成
```

三个触发类型：`firstKill`、`segmentStart{wave,segment}`（均 0 起始索引）、`healthBelow{ratio,minWave}`。三个动作类型：`props`（铺场景物）、`formation`（按坐标列队）、`ring`（以玩家为圆心环形）。

关键设计点：

1. **一局一次**。`fired` 集合拦重复；每帧心跳的 `healthBelow` 在条件持续满足时也只点燃一次，否则濒死期间会每帧刷怪。已加 10 帧循环用例锁定。
2. **环形落点必须夹进战场**。玩家贴边时未夹取的落点会跑到画布外，敌人从场外径直穿墙进来。
3. **列队必须共线**。穿透靶列的价值完全依赖共线；间距 52px 略大于分离力最小间距（40px），队形能维持一两秒的开火窗口后被自然打散 —— 这正是"机会窗口"的含义。已加共线断言。
4. **包夹不能变处刑**。半径 ≥280（玩家移速 120 px/s，至少 2 秒反应窗口）、数量 ≤6，两条都进了单测。
5. **时刻不能成为内容冻结的后门**。运行时校验强制剧本时刻生成的敌人与场景物也在切片白名单内，段落索引也必须指向真实存在的段落。
6. **`spawnZombie` 新增可选坐标**。默认仍从画布外随机一边进场，只有剧本时刻走指定坐标。

### 8.4 剩余风险

1. **濒死包夹目前只有压力没有回报**。完整的濒死机制（移速 +20%、伤害 +50%、击杀回血）属 G1-7，尚未实施。在 G1-7 落地前，这个时刻偏向惩罚而不是翻盘高光；V6 若判断过苦，可先降数量或提高触发阈值。

## 9. G6-3 实施记录

> 状态：已完成，本机 Chromium V3/V4 性能样本通过

### 9.1 测试口径

1. 复用已运行的 Vite `5173` 与 Chrome CDP `9333`，不安装依赖、不修改正式关卡配置或测试开关。
2. 进入第二关后使用开发会话按固定网格补足 `walker`，分别保持 50、100、150 个活跃实体。
3. 每档预热 3 秒、以 250ms 间隔连续采样 12 秒；记录目标/实际敌人数、最低 FPS、平均 FPS、P05 FPS 与对象统计。
4. 在 150 敌人档持续 12 秒以 90ms 周期制造 8 个伤害数字和 3 具尸体残影，验证自动降级与池上限在持续压力下而非单帧注入时仍成立。
5. 玩家生命仅在测试会话内提高到 100000，避免压力样本被 Game Over 提前终止；该前置不进入源码、存档或正式数值。

### 9.4 结论与限制

1. G6-3 在当前机器、当前 Chromium、`1280×720` 逻辑画布下通过，正式第二关段落同屏上限不超过 40，低于已验证的最低压力档。

## 10. P2 回归修正记录

### 10.1 首次完整试玩失败

G6-3 后首次用正式初始资源运行第二关，自动代理在阶段一约 36.9 秒死亡，仅持有手枪，未到达 MP5 奖励；第二次优化退避路径后存活约 87.7 秒，击杀进度持续增长但被逼到右下边界，仍未完成阶段一。两次均无运行时异常或失败请求。

### 10.2 调整方案

阶段一原配置 102 只、阶段二 135 只、阶段三 104 只。为让“手枪教学压力 → MP5 密度爆发”成立，阶段一调整为 49 只，阶段二增加 26 只、阶段三增加 27 只；三阶段常规总量不变，同屏上限仍为 40。该调整不改变白名单、奖励节点、Boss 或总量目标，只改变压力预算所在阶段。

这是对原“逐类引入”节奏的修正：首个固定武器必须在玩家仍有资源和空间时可达，自动武器、霰弹和穿透枪获得后再承担主要密度。修正后必须重新执行完整 V5，不得沿用两次失败样本作为通过证据。
