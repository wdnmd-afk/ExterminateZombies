## 1. 目标

1. 修复「17 把战场武器全部不可获得」的潜在缺陷，把武器获取从随机掉落改为关卡阶段奖励确定性交付。
2. 把「武器不走掉落」这条不变量从测试断言提升到类型层，使违反变成编译错误。
3. 落地四个已配置但缺美术、缺加载、缺掉落宿主的战术道具。
4. 按 `2026-08-27-boss-three-phase-rework.md` §10.1 的实测结论下调 Boss 血量。

## 2. 范围

1. `DropDef` 移除 `'weapon'` 变体，连带清理三处死分支与两个失效 helper。
2. `WeaponLibraryAvailability` 的 `enemyDrop` 改为 `levelReward`，图鉴获取文案改为从 `LEVELS` 派生。
3. 16 把有限弹药武器按关卡主题落位到 17 处阶段奖励节点。
4. 四个战术道具补齐后处理脚本、运行时贴图、`PreloadScene` 加载与掉落宿主。
5. 四个 Boss 血量统一 0.65 倍下调；第 1/4/8 关补保底药品奖励；普通感染体绷带掉率上调。

## 3. 不在范围

1. 不新增武器、感染体、Boss、强化卡、角色。
2. 不修改武器战斗数值、负重体系与弹药分配算法。
3. 不做 CDP/Playwright 实机试玩（本轮明确未做，见 §7）。
4. 不重测 Boss TTK；0.65 是保守推算取值，不是实测得出。

## 4. 核心缺陷：17 把战场武器全部不可获得

这是本轮的主要修复项，也是一个**被 373 个绿灯掩盖**的潜在缺陷。

### 4.1 缺陷成因

`GameScene.applyDrop()` 的注释声称「掉落表已无 weapon 条目」，但 `ZOMBIES` 里实际仍有
**20 条 `type: 'weapon'` 掉落**。这些条目命中时走不到任何有效分支，因此：

1. 玩家整局都拿不到除沙漠之鹰以外的任何武器。
2. 不抛异常、不打日志，运行时完全静默。
3. 武器库的获取文案照常显示「敌人掉落」，与实际行为相反。

### 4.2 为什么测试没有拦住

`config-integrity.test.ts` 与 `weapon-loadout.test.ts` 只断言「配置存在且自洽」：
武器有战斗配置、掉落项引用的 `itemId` 有效、编队规则正确。
这些断言在 20 条死掉落存在的情况下**全部为真**——配置确实自洽，
只是配置描述的那条获取路径在运行时不通。

> 教训：配置完整性测试能证明「配置内部一致」，不能证明「配置描述的行为真实发生」。
> 涉及获取/交付链路的不变量，要么提到类型层，要么必须有实机验证。

### 4.3 修复方式

删除 20 条死掉落与 12 行孤立注释，改为关卡阶段奖励确定性交付。
`validate.ts` 的不变量从「战场武器有敌人掉落来源」改为「战场武器有关卡奖励交付节点」：

```ts
if (entry.availability.kind === 'levelReward'
  && getWeaponRewardSources(entry.availability.weaponId).length === 0) {
  errors.push(`战场武器 ${entry.id} 没有关卡奖励交付节点`);
}
```

## 5. 实施内容

### 5.1 不变量提到类型层（`src/config/types.ts`）

`DropDef` 刻意不含 `'weapon'`：

```ts
// 这里刻意**不含** 'weapon'：武器改由关卡阶段奖励交付。
type: 'item' | 'enhancement_pack';
```

这比「用测试断言掉落表里没有 weapon」更强——任何人想重新加回武器掉落，
会先撞到编译错误，而不是等运行时静默失效。

连带清理：`monsterLibrary.ts`、`validate.ts`、`GameScene.ts` 三处死分支，
两个失效 helper，以及零引用的 `src/entities/Pickup.ts`（213 行整文件删除）。

### 5.2 武器交付节点（`src/config/levels.ts`、`src/config/weaponLibrary.ts`）

17 把武器 = **1 把初始配发**（沙漠之鹰，无限备用弹）+ **16 把关卡奖励**。
16 把武器分布在 **17 处**奖励节点上（MP5 在第一、二关各交付一次，第二次为补给）。

新增 `getWeaponRewardSources(weaponId)`，图鉴获取文案从 `LEVELS` 派生而非 `ZOMBIES`。
面板只展示首次解锁节点，补给节点折叠为「另有 N 处补给节点」，避免行数不可控。

落位遵循「武器机制与关卡主题同源」：

| 关卡 | 交付武器 | 主题匹配理由 |
| --- | --- | --- |
| 第一关 郊外 | MP5 | 首把有限弹药武器，建立军械许可 |
| 第二关 废车站 | MP5（补给）、SPAS-12、M4A1 | 废车通路近距爆破 + 中距穿透 |
| 第三关 封锁城区 | AK-47、M79 | 口径升级应对爆破者群；路障把敌人挤成直线，榴弹最优 |
| 第四关 排水渠 | 双持乌兹、AA-12 | 窄水道高速小体型群，全自动霰弹一次覆盖整条通路 |
| 第五关 检疫所 | M16A4、Barrett M82 | 猎杀者冲锋落空的窗口要求精确点射 |
| 第六关 货运场 | 加特林、黄金 M249 | 重装感染体成群，持续压制正是本关主题 |
| 第七关 塌陷街区 | 特斯拉枪、磁轨炮 | 通路碎片化，电弧连锁与穿透磁轨可跨掩体处理成串目标 |
| 第八关 研究站 | 冷冻喷射器 | 远程占比最高，减速控场比爆发更能压住四面弹幕 |
| 第九关 焚化厂 | 喷火器 | 油桶密度全场最高，燃烧扇形与连锁爆炸同源 |
| 第十关 感染源核心 | RPG-7 | 单发大范围爆炸是清母体召唤群的最后工具，提前给会让中段失压 |

### 5.3 四个战术道具（`src/config/items.ts`）

四个道具此前**配置存在但完全不可用**：缺后处理脚本、缺运行时贴图、
`PreloadScene` 漏了四处 `load.image`（渲染缺图占位且不报错）、无掉落宿主。

| 道具 | 定位 | 关键数值 | 掉落宿主 |
| --- | --- | --- | --- |
| 燃烧瓶 `firebomb` | 封路消耗 | 直伤仅 40，半径 110 地火 6s，`tickDamage` 18（高于油桶 15） | bomber 14% |
| 粉尘罐 `dust_canister` | 纯脱身 | 零伤害，硬停半径 120 内 5s；可贴脚下扔 | crawler 16% |
| 高爆包 `demo_charge` | Boss 爆发窗口 | 260 伤害（全库最高），半径仅 60，需自己补枪引爆 | tank 10% |
| 冷冻罐 `cryo_canister` | 控场 | 零伤害，半径 105 内压到 35% 移速 5s | drifter 12% |

设计取舍已写进配置注释：粉尘罐 `chainable: false`，因为它没有爆炸产出，
被连锁引爆只会白白浪费一次阻挡；冷冻罐的减速比粉尘罐的硬停更好用，
因为硬停会让僵尸在边缘堆积，减速允许边打边撤。

> **贴图坑位（已记录）**：四张图统一 `46×38`，与 `prop-mine.png` 对齐。
> 画幅比例必须等于 `PROP_VISUAL_METRICS` 的倍率比值，
> 否则 `applyVisual` 的裸 `setDisplaySize` 会静默把贴图拉扁。

### 5.4 Boss 血量与药品

四个 Boss 统一 **0.65 倍**下调，保持命中难度分档顺序不变：

| Boss | 原血量 | 新血量 |
| --- | ---: | ---: |
| `bomber_boss` 毁灭爆破者 | 3200 | 2100 |
| `hunter_boss` 猩红猎杀者 | 4200 | 2730 |
| `tank_boss` 巨型坦克 | 5200 | 3400 |
| `mother_boss` 腐化母体 | 6400 | 4160 |

**为什么是 0.65 而不是 `2026-08-27` 文档 §10.1 建议的 1700-2300**：
那个区间依赖「约 40% 实战效率」这个系数，而该文档自己声明系数未测出、不宜采信。
0.65 是统一比例，保住了「最难命中的最脆、最好命中的最厚」这条分档顺序，
也不假装知道没测到的数字。

**预期 TTK 约 26-33 秒**——比原来的实测 40.7-50.6 秒短得多，但**仍高于设计目标 12-18 秒**。
最终档位要靠真人试玩定，见 §8。

药品：第 1/4/8 关补保底药品奖励（掉落是随机的，这里给确定补给，避免窄道被贴身后无药可用）；
普通感染体绷带掉率 `0.03 → 0.06`。

## 7. 未完成项

### 7.1 实景验证全部缺失（本轮最大缺口）

本轮改动触及**获取链路、渲染加载和数值三个层面**，但没有任何浏览器验证：

1. **17 处武器奖励节点是否真的交付**——这正是本轮修复的缺陷所在，
   而修复本身仍只有命令层证据。V1 只能证明配置自洽，
   §4.2 已经说明配置自洽不等于运行时交付成功。
2. **四张道具贴图是否被正确加载和显示**——`PreloadScene` 的四处 `load.image` 是本轮新增，
   贴图比例与 `PROP_VISUAL_METRICS` 的匹配也只做了静态核对。
3. **四个道具的实际效果**——地火、硬停、高爆、减速四种区域效果均未实机确认。
4. **Boss 新血量的实际 TTK**——26-33 秒是推算值，未重测。

> 建议下一轮优先做 V3/V4，且**必须包含「从第一关走到第二关、确认 MP5 真的到手」这一条**，
> 因为它直接验证本轮修复的缺陷是否真的修好了。

### 7.2 Boss TTK 仍未收敛（需真人裁决）

设计目标 12-18 秒，`2026-08-27` 实测 40.7-50.6 秒，本轮下调后推算 26-33 秒。
三个方向仍然成立且互不排斥：

1. 继续下调血量（需要一次可复现的净场效率测量来定系数）。
2. 承认更长的战斗，把设计目标改为 26-33 秒，并重新评估阶段补给频率是否够。
3. 减少 Boss 战护卫或提高武器穿透，让实测向纸面靠拢。

这属于 TESTING_RULES §8「难度是否舒适」的范畴，Agent 不得代替结论。

## 8. 风险提示

1. **不要把本轮当作已验证基线**。命令层全绿，但获取链路、贴图加载和四个道具效果
   都只有静态证据。§4.2 的教训在本轮同样适用。
2. **0.65 倍是保守取值**，不是实测得出，也没有重测验证。
3. **道具贴图比例是隐性契约**：`applyVisual` 用裸 `setDisplaySize`，
   比例不符只会静默拉扁而不报错。后续新增道具贴图必须同步核对 `PROP_VISUAL_METRICS`。
4. 四个新道具的掉落宿主概率（10%-16%）是首版初稿，与波次节奏和携带上限的匹配未经试玩收敛。
