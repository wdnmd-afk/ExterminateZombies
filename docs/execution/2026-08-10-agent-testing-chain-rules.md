# Agent 测试链路规范编写执行记录

> 状态：已实施
>
> 日期：2026-08-10

## 1. 目标

在仓库根目录建立一份面向开发者与编码 Agent 的测试链路规范，统一回答以下问题：

1. 不同改动必须进入哪一层验证。
2. 哪些场景必须打开真实游戏并由 Agent 操作关卡或界面。
3. Browser、Playwright、Chrome DevTools Protocol（CDP）和人工试玩分别承担什么职责。
4. Phaser Canvas 项目如何采集运行时、交互、视觉和状态证据。
5. 浏览器或命令验证无法执行时，如何准确汇报未验证项与剩余风险。

## 2. 范围

本次只处理测试规范文档：

1. 新增根目录 `TESTING_RULES.md`，作为项目测试决策和 Agent 实景验收的最高级入口。
2. 保留 `docs/TESTING.md` 作为现有详细玩法清单，并在新规范中说明两者分工。
3. 不修改业务代码、测试代码、构建配置、依赖或现有用户改动。
4. 不在本次任务中实际执行 Vitest、TypeScript 检查、构建或浏览器试玩。

## 3. 项目依据

1. 项目为 Vite + TypeScript + Phaser 3 的纯前端单机游戏，正式交互位于单一 Canvas 内。
2. 游戏逻辑坐标为 `1280 x 720`，渲染缓冲区会根据设备条件使用 `1x` 或 `2x` 倍率。
3. `src/main.ts` 在开发模式暴露 `window.__GAME__`，可用于场景状态和游戏状态只读探针。
4. 当前已有 Vitest 纯逻辑测试和 `docs/TESTING.md` 中的临时 CDP 冒烟流程，但未接入正式 Playwright 端到端套件。
5. `package.json` 未直接声明 Playwright，规范不得暗示仓库已经具备可直接运行的 Playwright 项目配置。

## 4. 操作步骤

1. 建立从静态审阅、定向自动化、浏览器冒烟、Agent 实景交互、完整关卡试玩到真人主观验收的分层模型。
2. 按改动类型制定最低验证层级矩阵，明确场景、输入、碰撞、动画、音频、关卡、Boss、存档和性能改动的实景要求。
3. 建立工具选择顺序：会话内集成 Browser 优先，Playwright 用于可重复脚本，CDP 作为兼容现有仓库的降级方式，人工验收负责主观结论。
4. 针对 Canvas 限制定义输入和断言方式：键鼠事件完成真实操作，截图和像素变化证明渲染，`window.__GAME__` 只读探针证明内部状态。
5. 定义单次实景测试的准备、执行、证据采集、失败处理、清理和汇报模板。
6. 定义禁止事项，防止 Agent 用直接改状态、调用私有方法、单张截图或无证据描述冒充完整试玩。
7. 审阅新规范中的命令、场景 key、关卡参数、视口、测试开关和项目路径是否与当前源码一致。

## 5. 实施建议

1. 使用“必须 / 应 / 可以”区分强制规则、推荐规则和可选手段。
2. 规则强调最低验证层级，实际任务可按风险向上升级，不能用低层验证替代高层验收。
3. 将“Agent 实景交互”与“真人主观试玩”拆开：Agent 可以完成客观路径和视觉证据采集，但不能替代手感、听感、疲劳度和乐趣判断。
4. 跳关和状态注入只用于缩短前置时间，涉及解锁、流程或经济的需求仍必须走真实用户路径。
5. 命令执行必须继续服从全局规则：未经用户明确许可，不执行测试、类型检查或构建。

## 6. 潜在风险分析

| 风险 | 影响 | 控制方式 |
| --- | --- | --- |
| 新规范与 `docs/TESTING.md` 口径冲突 | Agent 无法判断是否能自行操作关卡 | 明确根目录规范负责决策和证据，旧文档负责详细玩法清单；主观结论仍归真人 |
| 把 Canvas 当普通 DOM 应用测试 | 定位器找不到 Phaser 对象，脚本产生假阳性 | 强制使用真实键鼠输入、画面证据和运行时探针联合判定 |
| 把 headless 冒烟写成完整试玩 | 交互、碰撞、节奏和观感问题被漏掉 | 将冒烟、实景交互、完整通关和真人主观验收拆成不同层级 |
| 规范默认要求安装 Playwright | 产生未经批准的依赖和浏览器下载 | 优先使用会话集成 Browser；独立安装或入库必须另行获得用户同意 |
| 测试探针直接改写游戏状态 | 绕开真实业务链路，验收结果失真 | 只读探针默认允许；状态注入必须标记为测试前置且不能证明完整流程 |
| 规范过重导致简单改动成本过高 | Agent 对文档或纯函数改动也启动完整试玩 | 通过变更矩阵定义最低层级，并允许无运行命令的静态审阅 |

## 7. 优化方案

1. 后续正式引入 Playwright 时，将重复出现的浏览器冒烟固化为仓库脚本和测试夹具，并回填根目录规范中的实际命令。
2. 为 Canvas 增加只在开发模式开放的稳定测试探针，避免依赖私有字段和坐标猜测。
3. 建立按任务保存的证据目录、截图命名、控制台日志和测试报告模板，减少执行记录中的自由描述。
4. 逐步将 `docs/TESTING.md` 的客观检查项转为自动化或 Agent 可重复执行的场景，将主观条目留给真人试玩。

## 8. 验证方式

本次只进行文档级验证，不运行测试、类型检查、构建或浏览器命令：

1. 对照 `package.json` 核对可用命令和直接依赖。
2. 对照 `src/main.ts`、`src/constants.ts` 和场景源码核对场景 key、开发探针与关卡启动参数。
3. 对照 `src/systems/DisplayManager.ts` 核对逻辑分辨率和高分屏渲染行为。
4. 对照 `src/systems/InputManager.ts` 与 README 核对键鼠操作方式。
5. 对照 `docs/TESTING.md` 和历史执行记录核对现有 CDP 流程、证据要求与未覆盖边界。
6. 使用 Git 差异检查确认只新增目标文档，不覆盖工作区已有改动。

## 10. 后续补充

根据用户反馈，已将“测试前提条件确认”提升为 V1-V6 启动前的强制门禁：

1. Agent 必须先通过 V0 只读调查列明环境、现有依赖、待安装工具、准确命令、文件影响、端口、数据副作用、耗时和降级方案。
2. 即使无需安装新依赖，也必须明确说明并咨询用户，得到批准后才能启动服务器、浏览器或测试命令。
3. 用户只批准部分动作时不得扩大范围；新增依赖、命令或场景时必须暂停并重新咨询。
4. 标准执行流程和结果模板已同步记录前提确认与实际授权，保证测试开始前存在明确停止点。
