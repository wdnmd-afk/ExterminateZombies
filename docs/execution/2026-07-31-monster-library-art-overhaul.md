# 怪物图鉴美术替换执行文档

> 日期：2026-07-31  
> 状态：已暂停（未接入）  
> 关联任务：使用免费外部资源替换怪物图鉴中的僵尸展示美术

## 1. 目标

在不修改战斗实体、敌人行为和关卡数据的前提下，为怪物图鉴建立独立的高细节僵尸肖像层，替换当前直接复用低分辨率运行时精灵的展示方式。

本轮需要达到：

1. 图鉴中的僵尸不再因运行时小尺寸帧被强行放大而显得粗糙。
2. 18 个图鉴条目都有已确认的肖像映射，不通过猜测字段或模糊兜底取图。
3. 肖像视觉统一、裁切稳定，不遮挡名称、属性、战术和掉落信息。
4. 外部素材来源、授权、处理方式和实际使用文件可以追溯。

## 2. 视觉与内容方案

### 2.1 视觉主张

图鉴表现为“封锁区感染体档案”：使用暗色、半写实、具有伤口和变异细节的僵尸肖像作为主视觉，保留现有漫画战报式标题与功能色，不把高细节肖像做成新的装饰卡片。

### 2.2 内容计划

1. 左侧继续承担感染体索引与威胁扫描。
2. 右侧详情区以一张稳定的大幅肖像作为视觉锚点。
3. 属性、出现场所、掉落、死亡危险和应对策略仍由真实玩法配置派生。
4. 肖像只表达感染体外观和角色气质，不复制或改写战斗数值。

### 2.3 交互主张

1. 切换条目时肖像快速淡出、轻微横移，再加载新肖像。
2. 当前选中行继续使用既有高亮，不新增多余按钮或说明文字。
3. Boss 肖像只通过尺寸、裁切和既有威胁色强调，不增加持续闪烁或循环装饰。

## 3. 范围

本轮包含：

1. 下载免费、允许个人和商业项目使用的高细节僵尸肖像资源。
2. 检查包内实际文件、许可证和是否包含 AI 生成内容。
3. 从原始资源生成图鉴专用透明 PNG，统一尺寸、留白和裁切。
4. 新增图鉴肖像资源映射，键必须使用现有 `ZombieId`。
5. 在 `PreloadScene` 加载图鉴肖像，并在 `MonsterLibraryScene` 中展示。
6. 为选中切换补充克制的肖像转场。
7. 更新资源台账与来源记录。

本轮不包含：

1. 不替换 `GameScene` 中的运行时僵尸动画。
2. 不修改敌人生命、速度、掉落、能力和关卡编排。
3. 不购买付费资源。
4. 不把授权不明确或禁止项目内使用的素材接入运行时。
5. 不为了制造 18 张“伪独立”图片而对未知素材内容进行字段或文件名猜测。

## 4. 操作步骤

1. 下载 ODDBLOT 免费半写实僵尸包，核对实际文件数量、透明背景、分辨率和包内许可证。
2. 若资源不足以覆盖图鉴角色，使用同包角色的不同裁切、水平翻转、受控色调和背景档案构图生成明确变体；每个映射在配置中显式声明。
3. 将原始包保存在本地忽略目录；仅将实际使用的处理后 PNG 与来源记录加入项目。
4. 建立 `MonsterPortraitDef` 和 `Record<ZombieId, MonsterPortraitDef>`，由类型检查保证完整覆盖。
5. 在 `PreloadScene` 使用稳定纹理键加载处理后文件。
6. 修改图鉴详情区：加载独立肖像、统一 `contain` 缩放和裁切边界，并保留现有信息层级。
7. 更新切换动画，确保连续键盘导航时旧 tween 不会叠加。
8. 新增配置完整性测试，确认所有 `ZombieId` 都有肖像定义且纹理键唯一可用。
9. 运行 `npm test` 和 `npm run typecheck`。
10. 启动开发服务器，进入怪物图鉴并生成桌面截图，检查普通、远程、重装和 Boss 条目。

## 5. 实施建议

1. 原始插画只用于图鉴，不应误导为实际战斗精灵。
2. 以统一的透明画布和背景档案层消化不同角色的姿态差异。
3. 角色差异优先通过显式素材映射、裁切和构图建立，不使用运行时随机选择。
4. 同一原图被多个配置复用时，必须通过确定性的处理参数形成可追溯变体。
5. 图鉴肖像分辨率应控制在浏览器实际需要范围内，避免把 512px 以上原图无压缩加载到每个条目。

## 6. 潜在风险分析

1. **肖像与战斗外观不一致**：图鉴会比实机精细。通过“档案肖像”定位和后续运行时美术计划说明解决，本轮不假装已替换实机。
2. **角色数量不足**：免费包可能没有 18 个独立人物。优先显式复用和确定性变体，不生成来源不明的内容。
3. **授权风险**：允许用于游戏不一定允许公开仓库分发原包。原包保留在忽略目录，只提交实际游戏使用的处理后资源和署名。
4. **图片遮挡**：高细节肖像可能压住属性信息。通过稳定肖像区域和 `contain` 约束验证。
5. **加载体积**：多张高分辨率图片会增加首屏加载。处理后资源限制尺寸并复用少量基础肖像。
6. **色调失真**：过度染色会破坏原作者细节。只使用低强度色调和档案背景，不进行强制单色化。

## 7. 优化方案

1. 将肖像映射与战斗 `ZOMBIE_VISUALS` 分离，后续替换实机资源时互不阻塞。
2. 用脚本从少量原图生成固定尺寸派生图，保证结果可复现。
3. 在图鉴测试中检查映射完整性，防止新增感染体后静默回退到旧图。
4. 仅预加载实际使用的基础肖像文件，派生构图尽量通过 Phaser 确定性完成。
5. 后续获得统一八方向资源后，可保留肖像层作为高细节档案图，不需要再次重做图鉴结构。

## 8. 验证方式

1. `npm test` 全部通过。
2. `npm run typecheck` 零错误。
3. 18 个 `ZombieId` 均有显式肖像映射。
4. 图鉴打开、鼠标选择、方向键切换和返回菜单无运行时异常。
5. 普通感染体、远程感染体、重装感染体和 4 个 Boss 的肖像无拉伸、遮挡和越界。
6. 截图中肖像区域不是空白、纯色或旧运行时小精灵的粗放放大。

## 9. 执行结果

### 9.1 实际核对

1. 已取得并核对 `.asset-candidates/oddblot-mini-zombie-pack/SOURCE.md`、原始 ZIP 哈希与包内 `Thanks!.txt`。

1. 不把 ODDBLOT 原图或派生肖像提交到仓库，原始包和预览继续保留在 Git 忽略的 `.asset-candidates/`。

3. 删除只执行原样解压、没有缩放裁切能力的 `scripts/process_monster_portraits.py`。
4. 怪物图鉴继续使用实际战斗精灵，但由 `MonsterPreviewLayout` 按内部安全框反推缩放上限。
5. Boss 独立视觉身份继续按 `2026-07-31-zombie-art-resource-sourcing.md` §9.4 推进，优先评估 SmallScaleInt Top-Down Zombie Pack 2。
