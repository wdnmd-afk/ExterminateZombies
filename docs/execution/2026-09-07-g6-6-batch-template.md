> 状态：模板与配置门禁已落代码，83 个定向用例及类型检查通过；全量回归、构建与 V3-V6 未执行，生产数值与剧本仍待后续实施
>

## 1. 批次边界

每关保留现有 `LevelDef` 数据契约，不新增关卡运行时系统。每关必须具备：

1. 独立任务简报和主题调色。
2. 三个战斗阶段，每阶段 3 个生成段落。
3. 每阶段至少 1 个可辨认的压力变化：密度、敌人角色、场景物或剧本时刻只能选一个作为主变化。
4. 标准关卡 10-15 分钟的目标下界，不能靠纯等待填充。
5. 最多在 2 个阶段结束时发放奖励；同一阶段可以组合武器、药品和强化，不能把奖励条目数误当奖励阶段数。Boss 只出现在明确的高潮关。

| --- | ---: | --- | ---: | --- |

- 新增数量优先使用低/中耐久敌人承载，不能同时扩大数量和单体生命。

## 3. 阶段模板

```ts
{
  startDelay: 2400,
  segments: [
    { enemies: [], spawnInterval: 620, leadIn: 0, concurrentCap: 18 },
    { enemies: [], spawnInterval: 500, leadIn: 1800, concurrentCap: 24 },
    { enemies: [], spawnInterval: 420, leadIn: 2200, concurrentCap: 30 },
  ],
  rewards: [],
}
```

第一段只建立方向，第二段引入本关主压力，第三段兑现一次高峰。段落之间使用 `leadIn` 制造可读的换气，不允许用空段或无敌等待拖长时间。

上述 `enemies: []` 仅用于展示字段，不能直接作为生产配置；每段必须填入已登记感染体和正整数数量后才能进入启动校验。

## 4. 剧本时刻模板

每关最多配置 2 个剧本时刻，统一使用现有 `ScriptedMomentSystem`：

| 时刻 | 触发 | 反馈 | 失败保护 |
| --- | --- | --- | --- |
| 压力转折 | 阶段 2 开始 | 事件提示 + 新敌群角色 | 不依赖特殊道具才能清场 |
| 高潮兑现 | 阶段 3 中后段 | 连杀/环境/位移反馈 | 触发失败仍可正常通关 |

剧本只能改变生成和表现，不直接调用结算、改写玩家生命或跳过波次。

## 5. 资源模板

每关环境资产登记为 `ground/rail/boundary` 三件套，优先使用现有 `BATTLEFIELD_TILE_SETS` 和主题调色派生。新增原始素材必须先补来源页、作者、许可证、哈希和 `SOURCE.md`，未登记资源不得进入生产配置。

## 10. 实施建议与优化方案

- 通用门禁只约束运行时安全和可达性，不把尚未冻结的数量区间、三阶段模板或两处剧本数量强加给全部原型关。
- 准备时间和生成间隔必须为有限正数，静默时间允许零；敌人数与同屏上限必须为正整数。
- 剧本阶段/段落索引从零开始，`healthBelow.minWave` 从一开始，必须分别核对。
- 剧本敌人只能引用普通感染体，场景物必须支持 `scenePlaceable`；坐标使用现有战场尺寸，不猜测新字段。
- 批次生产分别记录常规敌人、剧本追加敌人和 Boss 预算；剧本追加生成不受段落同屏上限约束，必须单独纳入压力验收。
- 每关独立推进后再横向对比；时长使用真实试玩记录，不用排程估算冒充 10-15 分钟验收。

## 11. 潜在风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 新门禁错误拒绝旧配置 | Boot 阶段无法进入游戏 | 保留单段写法；不强加未冻结批次指标 |
| 无限/非数值排程与数量 | 波次停滞、生成死循环或内存增长 | 提前拒绝非有限时间和非正整数数量 |
| 剧本引用错误或身份重复 | 时刻无法触发或被错误去重 | 全量检查关卡、索引、唯一 id 和动作引用 |
| 变异测试污染其他测试 | 后续基线随机失败 | 用 `try/finally` 恢复关卡与剧本数组 |
| 模板被误报为扩关完成 | 缺少真实节奏、经济与性能证据 | 分开记录模板、门禁、生产配置、V3-V6 |
