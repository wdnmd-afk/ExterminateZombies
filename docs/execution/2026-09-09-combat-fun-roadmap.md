## 1. 目标

把当前项目收敛为一款“10-15 分钟一局、持续高压、局内构筑为主”的高密度俯视角爽射游戏。

玩家在一局内应持续获得三个感受：

1. 场上始终有足够多、足够近、职责不同的可击杀目标，连续击杀不会因为出生空窗频繁中断。
2. 连杀会直接转化为火力、技能和道具优势，玩家越打得好越容易进入下一次爆发。
3. 每种武器的开火、命中、爆头、穿透、爆炸和击杀都具有清楚且好看的视觉与声音反馈，不靠堆满屏特效制造混乱。

成功标准不是单纯增加敌人、武器或粒子数量，而是让玩家在 10-15 分钟后能说出“哪一段最爽、哪把武器最有个性、这局构筑为什么不同”，并愿意立即重开一局。

### 2.1 本轮包含

- 关卡模式和无尽模式的战斗节奏、敌人密度、出生队列和同屏上限。
- 连杀计时、里程碑、连杀奖励与火力过载的统一规则。
- 武器命中反馈、击杀反馈、连锁反馈、特效层级和低性能降级策略。
- 局内强化卡的流派化改造，以及武器、角色技能、战术道具和环境的联动。
- 普通波次目标、精英组合、短暂整理窗口和 Boss 前后的节奏安排。
- 相关配置校验、逻辑测试、性能观测和浏览器人工验收入口。

- 联机、账号、排行榜、服务端和云存档。

- 不删除或降级 `PROJECT_MASTER_PLAN.md` 及其 Goal 体系。本文件只能作为某个已确认 Goal 的候选执行文档；若需要改变上位决策，必须先更新总纲中的决策记录。

## 4. 产品设计

### 4.1 单局结构

单局结构必须遵守总纲 D-002，不能把标准关的参数套用到教学关或无尽模式：

| 模式/关卡 | 硬约束 | 本路线的体验目标 |
| --- | --- | --- |
| 首次进入战斗 | 5 秒以内 | 尽快进入第一个可击杀目标 |
| 教学型关卡 | 8-10 分钟、3 个战斗阶段、1 次保证强化、无 Boss | 逐步教会移动、武器、敌人职责和一次构筑选择 |
| 标准关卡 | 10-15 分钟、3 个常规阶段、2 次保证强化 | 通过敌群组合、环境和武器轮换形成完整战斗曲线 |
| 作者化高潮关 | 在标准关卡结构上增加独立终局 Boss 节点 | 只在确认为高潮关的关卡使用 Boss，不要求每关都有 |
| 无尽模式 | 3 分钟明显压力、10 分钟高风险、15 分钟后极限挑战 | 通过章节波次、随机组合和高分目标延长复玩 |

标准关卡的战斗循环为：

1. **进入战斗**：短准备后快速出现可击杀目标，第一分钟内让玩家形成连续击杀。
2. **高压推进**：持续生成不同职责的敌人，保持玩家移动、瞄准和换武器的需求。
3. **短整理窗口**：清场或完成阶段目标后提供 10-20 秒选择强化、补给或调整装备的时间。
4. **新组合压力**：下一段引入新的敌人职责、空间限制或目标规则，而非只提高生命值。
5. **终局收束**：普通标准关在第三阶段结束后结算；作者化高潮关才进入 Boss 节点，并在 Boss 前提供一次明确补给和构筑选择。

固定关卡强调手工编排、场地互动和 Boss 剧本；无尽模式强调章节波次、随机组合、构筑叠加和最高连杀/最高波次。

### 4.2 敌人数量与组合

“数量多”定义为持续存在可处理的目标和稳定的击杀节奏，不定义为无限堆实体。

- 普通战斗段优先保证连续目标输入，避免上一批死亡后长时间等待下一批。
- 使用 `WaveSegmentDef.spawnInterval` 控制输入节奏，使用 `concurrentCap` 控制同屏复杂度。
- 敌人组合按职责搭配：脆皮群体、快速近战、远程压制、肉盾、爆炸、冲刺和召唤。
- 每一段至少有一个主要威胁和一个可快速清理的目标，避免全是高血量敌人造成“打不动”的感觉。
- 敌人总量提升优先放在分段队列和出生节奏，而不是一次性提高同屏上限。
- 关卡垂直切片先验证一个完整 10-15 分钟流程，再将规则扩展到其他关卡和无尽章节。

建议的战斗输入节奏：

| 阶段 | 体验目标 | 配置方向 |
| --- | --- | --- |
| 0-2 分钟 | 快速建立连杀 | 脆皮目标占主导，出生间隔短 |
| 2-6 分钟 | 形成武器流派 | 混入远程、爆炸和少量精英 |
| 6-9 分钟 | 制造高压选择 | 提高组合复杂度，保留快速清理目标 |
| 9-12 分钟 | 高潮前积累 | 密度提升，安排一次整理/补给窗口 |
| 12-15 分钟 | 终局收束 | 普通标准关在第三阶段结束后结算；仅作者化高潮关进入 Boss 节点，并配小规模伴随敌人避免战斗停摆 |

具体数量必须以当前关卡配置、玩家实际击杀速度和性能观测为准，不在规划阶段直接覆盖全部 10 关的数值。

### 4.3 连杀循环

- 复用 `KillStreakRules` 作为唯一连杀计数来源，默认窗口保持现有规则，后续只通过配置或已验证的规则变更调整。
- 击杀、穿透击杀、爆炸连锁击杀和环境击杀都要明确记录来源，避免同一目标重复计数。
- 连杀达到现有里程碑时触发 HUD、音频、屏幕反馈和短时奖励。
- 连杀奖励优先作用于“下一次行动”：技能充能、换弹、暴击、穿透、道具返还或短时火力提升。
- 无尽模式继续使用 10/20/35 连杀火力过载档位，固定关卡可使用较轻的局内奖励，避免关卡难度被永久滚雪球破坏。
- 受到伤害是否打断连杀沿用当前规则，任何改动必须单独记录并验证“紧张感”和“挫败感”的平衡。
- 连杀计时器应在有目标时推动追击，在出生系统短暂切段时提供足够缓冲，不能让系统性出生空窗惩罚玩家。

### 4.4 构筑方向

强化频率遵循 D-002：教学关 1 次保证强化，标准关 2 次保证强化。随机掉落、武器阶段奖励、药品和道具不自动计入保证强化；若无尽模式需要更多强化选择，必须作为独立的无尽模式决策和验收项提出，不能用“每局 6-8 次”覆盖所有模式。

每次强化选择都应改变武器行为或战斗决策。首批流派建议为：

- **暴击/爆头流**：奖励精准瞄准和高价值目标。
- **穿透清群流**：通过排线和角度获得连续击杀。
- **爆炸连锁流**：让油桶、面粉桶、地雷和击杀爆炸互相触发。
- **区域控制流**：火焰、冰冻和残留区域改变走位与敌人路径。
- **技能循环流**：通过连杀和击杀回收角色主动技能。
- **近距离爆发流**：以风险换取击退、处决和快速清场。

强化卡的描述必须能让玩家预判玩法变化。优先改造现有 `EnhancementDef.effects` 能表达的效果；需要新增效果时，先扩展类型、校验、解析和测试，再加入卡池。

### 4.5 攻击特效与反馈

特效质量是本路线的 R0 体验，不延后到内容扩充之后。

每种代表性武器先建立完整反馈链：

1. 开火：枪口火焰、后坐或能量释放、声音和抛壳。
2. 飞行：弹道、拖尾或投射物形态能够表达速度与危险。
3. 命中：按敌人材质和武器类型提供火花、血液、闪白、灼烧或冻结反馈。
4. 高价值命中：爆头、处决、穿透 3+、多杀和精英击杀需要更强反馈。
5. 击杀：尸体飞散、残留、掉落和音效形成短反馈链，但必须受池容量限制。
6. 连锁：爆炸、油桶、地雷和环境互动使用不同颜色、形状和声音，保证玩家能看懂因果关系。

视觉规范：

- 玩家、敌人、敌方危险提示和玩家攻击使用互不混淆的明度与色相层级。
- 屏幕中心保留清晰视野，强特效集中在命中点和事件发生点。
- 关键特效短、亮、脆；持续区域特效低频、低透明度，避免遮挡移动路线。
- 伤害数字、连杀文字和爆炸闪光设置并发上限、批处理和降级规则。
- `SaveManager` 的闪光、震动和可访问性设置必须贯穿所有新增反馈。
- 低性能模式优先关闭残留、减少粒子和降低屏幕震动，不关闭命中和危险信息。

## 6. 实施建议

- 以一个垂直切片作为唯一数值试验场，确认“多敌人 + 连杀 + 构筑 + 特效”同时成立后再批量改关卡。
- 优先修正反馈可读性和出生空窗，再调伤害、生命和掉落比例。
- 每次只调整一类变量：敌人密度、武器输出、连杀奖励或特效并发，避免无法归因。
- 将“爽感事件”做成配置或纯规则函数，将 Phaser 表现层限制在事件消费和对象池调用。
- 代表武器每次改动都记录职责、优势、代价和目标击杀场景，避免武器之间重新同质化。
- 所有新增特效先复用已登记资源；若需要新资源，必须同步资源清单、尺寸、许可和回退方案。

## 7. 潜在风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 敌人过多导致掉帧或输入延迟 | 爽感变成混乱和卡顿 | 用分段队列和 `concurrentCap` 控制同屏；同时统计投射物、粒子和数字峰值 |
| 连杀奖励滚雪球 | 早期优势使后半段无挑战 | 固定关卡限制奖励强度；无尽模式按档位设上限并验证 Boss TTK |
| 特效过亮遮挡敌人或危险 | 玩家无法判断受击和走位 | 先做层级、明度、持续时间和并发上限，再增加粒子数量 |
| 出生空窗打断连杀 | 玩家觉得系统不公平 | 调整 `spawnInterval`、分段 `leadIn` 和连杀窗口缓冲，记录中断原因 |
| 强化卡看似丰富但玩法相同 | 重复感增加 | 每张核心卡必须改变操作、目标优先级或环境互动，拒绝只有百分比的卡 |
| 新增事件破坏暂停/场景重启 | 卡死、重复回调、池泄漏 | 复用现有生命周期和计时平移入口，补充重启、暂停、抽卡和失败场景检查 |
| 盲目批量修改全部关卡 | 调参无法归因、回归成本高 | 先冻结垂直切片，再按模板扩展，变更记录写入本文件执行记录 |

## 8. 优化方案

### 性能

- 敌人、投射物、伤害数字、尸体残留和短时特效全部使用现有对象池或等价池化入口。
- 将表现对象与物理对象分离：物理体死亡后立即回池，残留表现使用独立轻量对象。
- 对同一帧的伤害数字、连杀文字和粒子做合并或采样，保留关键命中反馈。
- 50、100、150 活跃敌人的观测档位只在无尽模式压测（对应 G6-3 已完成的三档记录），记录帧率、池使用量和输入延迟。
  固定关卡切片的上限是 `verticalSlice.ts` 冻结的 40，切片内达不到这三档，不得为凑档位提高切片上限。
- 补齐特效池与粒子池的峰值观测：`utils/ObjectPool.ts` 无 `maxSize`，取不到空闲对象即新建，
  是目前唯一没有硬上限的显示资源（伤害数字 30、尸体 24 均有上限）。先取实测峰值，再决定是否设常量。

### 可读性

- 设置普通命中、高价值命中、敌方危险和环境连锁四类固定视觉层级。
- 使用不同形状和持续时间表达“击中、持续、即将爆炸、已触发”，不能只换颜色。
- 连杀里程碑使用短时中心播报，常驻 HUD 只显示当前连杀和剩余窗口，减少遮挡。

### 可调性

- 规则、奖励、波次、敌人组合和特效参数均通过配置或纯逻辑函数表达。
- 为垂直切片保留开发调试入口，可查看波次进度、活跃敌人数、连杀状态和特效池峰值。
- 变更记录包含旧值、新值、体验假设和验证结果，避免只记录“感觉更爽”。

## 9. 验证方式

### 9.1 代码与配置验证

- 静态检查连杀事件只由一个权威入口推进，击杀来源不会重复计数。
- 检查教学关、标准关、高潮关和无尽模式分别遵守 D-002 的时长、阶段、强化和 Boss 约束。
- 检查所有新增波次字段均通过 `waveShape.ts` 读取，且被 `validate.ts` 校验。
- 检查对象池在 `scene.shutdown`、暂停、抽卡、失败和重开后无残留活动对象。
- 检查现有保存结构对新增统计、奖励和构筑字段保持向后兼容；不能读取未知字段时不猜测替代字段。

### 9.2 必要逻辑用例

- 连杀在窗口内连续击杀、窗口超时、受伤打断和暂停/抽卡时间平移。
- 同一目标受到穿透、爆炸和环境连锁时只计一次击杀。
- 连杀达到 5、10、20、35 等现有里程碑时各触发一次对应奖励和反馈。
- 波次达到同屏上限时只暂停出生，不丢弃队列；敌人减少后继续生成。
- 高密度击杀下伤害数字、尸体、粒子和声音达到上限后仍保留关键反馈。
- 强化卡叠加、互斥/取最大值规则、非法配置和空效果卡均被拦截。

### 9.3 人工体验验收

使用同一垂直切片进行至少三轮体验记录：

1. 0-2 分钟是否能快速建立连续击杀。
2. 2-6 分钟是否出现明确的武器/强化流派。
3. 是否因出生空窗、弹药或目标稀少而频繁断连。
4. 高密度战斗中是否仍能看清玩家、敌人和危险区域。
5. 玩家能否说出一处具体的爽点和一处具体的重复点。
6. 是否愿意在结算后立即重开一局。

### 9.4 验收口径与入口

- 本文件的验证项**并入 `docs/execution/2026-09-07-unified-acceptance.md`**，不另开测试批次、不重复申请授权。
  该清单已定义命令批次、只读诊断接口和证据目录 `docs/execution/evidence/`。
