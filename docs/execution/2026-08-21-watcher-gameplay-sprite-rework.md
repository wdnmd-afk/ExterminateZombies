# 守望者关卡内精灵重做（图 B）

> 状态：产物已落地并通过量化门控，待实景复核
> 建立日期：2026-08-21
> 关联：`docs/design/CHARACTER_PORTRAIT_PROMPTS.md`、`docs/execution/2026-08-18-character-art-upgrade.md`
> 目标：解决守望者关卡内实机精灵「表现过差」，并让整条链路可复现、可门控

---

## 1. 根因

用户反馈：战前整备的立绘可以，**关卡内表现过差**。

排查结论是机位错了，不是滤波或缩放问题。`sprite-watcher-raw.png` 不是正俯视，
是高角度斜视图——画面里能看到脸、鼻、下巴、大腿和一整只从侧面看的靴子。

**为什么只有关卡内难看**：`src/entities/Player.ts` 用 `setRotation(aimAngle)` 让人物
按瞄准角连续旋转 360°。一个画着腿和靴子的竖长身体绕几何中心转，读作「一具躺平的
身体在打转」。战前页不旋转，所以同一张画风在那里没有暴露问题。这正好对应用户
「立绘可以、关卡内过差」的观察。

提示词里本来就写了 `straight 90 degree bird's eye`，模型没有遵守。这与
`scripts/generate_zombie_assets.mjs` 已记录的上游行为一致：**声明角度不足以约束机位**。

### 1.1 关键反证：管线本身没问题

`src/assets/processed/zombies/tank-boss-move-custom.png` 的帧是真正的正俯视
（只见背甲与外张四肢，无腿无脸，下三分之一质量 `0.279`）。说明现有僵尸管线能稳定
产出正确机位——问题是角色这条**没走同一条路**。因此本轮不新建一套，而是复用
Boss 那一路（单朝向朝右 + 运行时旋转，与 `Player` 的连续旋转完全同构）。

### 1.2 次级缺陷

1. **产物无法复现**。`scripts/process_character_assets.py` 此前**完全没有抠图与去色溢
   代码**（grep `magenta|despill` 命中 0），那张 PNG 不是任何脚本产出的。
2. **残留紫边**。1064 个不透明像素里有 128 个带洋红色调，深色战场上表现为紫边。
   根因就是没走 `process_zombie_sprites.py` 已验证的 `remove_magenta_background`。
3. **画幅不合规**。产物是 `64 x 64`，而既定规格是 `48 x 48`
   （`CHARACTER_PORTRAIT_PROMPTS.md` 第 20 行）。

## 2. 量化门控：本轮最重要的产出

新增 `scripts/inspect_character_candidates.py`。它存在的理由是一条实测教训：

> **纯几何判据拦不住斜视图。** 坏图的质量细长比是 `1.47`，而已验收的 Kenney
> hitman1 也是 `1.47`，两者完全相同；宽高比同样区分不开（`0.75` 对 `0.77`）。

真正有判别力的是「质量沿身体轴怎么分布」和「头部在主体里的相对位置」——相机不在
正上方时，透视会同时把头推离主体中心、把质量堆到上半部。

### 2.1 阈值标定

全部按**实测样本**标定，不是猜的。正确样本取在用的五张 Kenney 精灵与已验收的
tank_boss 帧，错误样本取 2026-08-18 的废图：

| 判据 | 正俯视基准 | 直立侧视 | 斜视废图 | 采用阈值 |
| --- | --- | --- | --- | --- |
| 下三分之一质量占比 | `0.279–0.343` | `0.190–0.292` | `0.161–0.163` | `>= 0.26` |
| 头部质心相对高度 | `0.489–0.515` | — | `0.309–0.335` | `0.42–0.58` |
| 拳心水平位置 | `0.807–0.905` | — | `0.833` | `0.78–0.94` |
| 拳心垂直位置 | `0.510–0.515` | — | `0.321` | `0.42–0.60` |
| 主体宽高比 | `0.74–0.87` | — | `1.26`（v01） | `0.62–1.02` |

两条注意事项，都来自本轮踩到的坑：

1. **拳心水平位置不是斜视图的判别项**（废图 `0.833` 落在合格区间内），真正抓住它的
   是垂直位置。水平项的作用是拦「手画在身体中央或超出前缘」这类横向错位。
2. **阈值必须按在用素材标定，不能按名义值。** 起初按提示词的名义值 `0.80` 给了
   `fistXMax: 0.88`，实测直接把 `survivor1` 判失败——那正是游戏当时在用的守望者
   精灵。一个对在用素材报错的门控会被绕过，也就失去了门控的意义。

### 2.2 门控双向验证

标定完成后先用已知样本验证门控本身，**再**去消耗生成额度：

| 用例 | 期望 | 实测 |
| --- | --- | --- |
| 2026-08-18 斜视废图 | 拦下 | 拦下，3 项失败（下三分之一、头部质心、拳心垂直） |
| 在用五张 Kenney 精灵 | 放行 | 全部放行 |

## 3. 生成迭代

`scripts/generate_character_assets.mjs` 走两步 I2I：先出身份参考图，再以它为参考出
精灵。机位改成三重约束——用相机物理位置描述、正面枚举「能看到什么」、负面枚举
「不能看到什么」，而不是只声明角度。

三个版本的实测轨迹，记录下来是因为它说明了两件事各自独立：

| 版本 | 下三分之一 | 头部质心 | 宽高比 | 结论 |
| --- | --- | --- | --- | --- |
| v01 | `0.343` | `0.534` | **`1.26`** | 机位对了，但人物被压成一个球，躯干与前缩的腿消失 |
| v02 | **`0.236`** | `0.433` | **`0.57`** | 加「4 单位高比 3 单位宽」后机位退回斜视，腿和整只靴子又出现 |
| v03 | `0.293` | `0.519` | `0.87` | 全部通过，采用 |

**教训**：「把相机搬到头顶」和「身体还有长度」是两件事，提示词和门控都必须分开说。
v01 暴露了门控只判机位、不判体型的盲区，宽高比判据是因此补上的；v02 说明用比例
数字表达长度会把「站着的人」这个概念带回来，改成按解剖顺序枚举轮廓（肩线→头顶→
背部 X 带→腰带→臀→靴尖短桩）才同时满足两者。

v03 的宽高比 `0.87` 紧邻在用 Kenney 素材的 `0.74–0.84`，体型与其余四人可比。

## 4. 后处理

`process_character_assets.py` 拆成两个子命令，原有行为保持默认：

- `portraits`（默认）：原有 Kenney 矢量切片，`npm run assets:characters` 不受影响。
- `sprite <id>`：新增，处理实机精灵候选。

键控、去色溢、`LANCZOS` 降采样与居中放置**直接 import 复用**
`process_zombie_sprites.py` 的现成函数，不重写：那套 BFS 去色溢带是按真实紫边样本
调过的，两处各写一份必然漂移。

写盘前把「残留洋红」变成硬失败而不是留给肉眼发现。实测产物洋红残留
**0 / 1042**（原产物 128）。

`targetSubject` 定为 `40` 而不是 `44`：复用的 `place_subject` 硬编码要求四边各留
`4px`，`44` 只能留 `2px`，实测直接抛「归一化主体越界：38x44 at (5, 2)」。

## 5. 代码接线

本轮进行期间，工作树上另一条并行工作已经把持枪手层与 `gripAnchor` 体系落地，
并且已经按 `48 x 48` 自生成精灵给出 `GENERATED_SPRITE_SCALE = 1.15`
——与本轮独立反算的值一致（主体 `40px` x `1.15` = `46` 逻辑像素，
对齐 Kenney 的 `43px` x `1.08` = `46.4`，差 1%）。因此代码侧只剩一处需要改：

| 文件 | 改动 |
| --- | --- |
| `src/config/characters.ts` | 守望者 `gripAnchor` 按 v03 产物重新实测：`{forward: 13, boreSide: -1}`（原值 `12.5 / -1.5` 是按旧 `64 x 64` 产物标定的） |
| `package.json` | 新增 `assets:characters-generate` 与 `assets:characters-inspect` |

### 5.1 一处计划内的改动已撤销

计划里写了「生成精灵改用 `LINEAR` 过滤」，实施时核对后**撤销**：该精灵在运行时是
**放大**（`1.15x`，高 DPI 档 `2.30x`）而不是降采样，`NEAREST` 才是正确选择，
改成 `LINEAR` 只会让它发虚。档案立绘用 `LINEAR` 是因为它按渲染倍率栅格化后始终是
降采样，两者情形相反。`GameAssetManager` 因此未改动。

## 6. 验证

### 6.1 已完成

1. 门控双向验证通过（见 2.2）。
2. v03 五项判据全部通过；参考图与精灵图的机位一致。
3. 产物 `48 x 48`，主体 `35 x 40`，宽高比 `0.88`，洋红残留 `0 / 1042`。
4. 四个旋转角（0°/90°/180°/270°）离线预览：任意角度都读作「从上方看一个人」，
   X 形黄带与前伸的拳头是稳定的身份标记，无「躺平旋转」观感。
5. `portraits` 子命令回归：五张 SVG 内容逐字节不变（`git diff` 仅 EOL 差异）。
6. `npm run typecheck`：**26 个错误，与 HEAD 基线的 26 个完全相同**，本轮零新增。
   既有错误集中在 `letterSpacing`（Phaser 版本不匹配）与两项无关项，
   均不在本轮触碰的文件内。
