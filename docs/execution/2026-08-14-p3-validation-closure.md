## 4. 实施建议

1. HUD 警报位置从左侧状态板右缘和固定间距推导，避免再次出现与军械槽数量或字体量度耦合的魔法坐标。
2. M79 判面使用 Arcade Physics `Body.prev` 与 `Body.center` 的同一坐标系；推离时只修正物理圆心，由 Phaser `postUpdate` 正常把本物理步位移回写给 GameObject。
3. M79 浏览器用例分开验证侧面、长边、角点和复用，记录碰撞前、反弹后、回收后三个时点；不能只看最终爆炸。
4. 正式掉落、许可和经济用例必须保持 `TESTING_FLAGS` 默认值，测试注入只允许用于 5/8 槽极限布局或单武器机制隔离，并在证据中标注。
5. 音频客观项读取缓存、解码/播放状态和曲目模式；响度、疲劳、方向感和好听与否只进入 V6。

## 6. 潜在风险分析

| 风险 | 影响 | 控制方式 |
| --- | --- | --- |
| M79 视觉坐标与 Arcade 刚体圆心不一致 | 推离后仍重叠，同一反弹被二次消费 | 全程使用刚体中心算反射/目标点，只修正 `Body.position` 并保留 Phaser 的正常回写 |
| 角点同时满足两条边 | 不同帧率下反射轴抖动 | 扫掠入口时间确定选择；相等时固定 x 轴入口（左右侧面）优先并用纯规则测试锁定 |

## 9. 当前 V0 发现

1. `D010-V4-VIS-001` 根因已确认：警报宽 520px 且以 `x=640` 居中，左边界 `x=380`；左侧面板右边界约为 `x=496`，横向重叠 116px。
2. M79 当前判面传入 `Bullet.lastPathX/Y`，该采样原本使用 GameObject 坐标；Arcade Physics 的碰撞发生在本步位置回写 GameObject 之前，因此判面会拿到滞后一帧或被场景 `tick()` 覆盖的采样。
3. M79 推离直接把 GameObject 坐标设为目标物理圆心并调用 `body.reset()`，但 Phaser Image 原点与 Arcade Body 圆心不保证重合，且 `reset()` 会抹掉本物理步位移，可能仍重叠并再次触发碰撞。
4. 该条为 2026-08-14 的历史快照；2026-08-17 已补齐无尽首 Boss 通过证据，最新结果见 §11。
5. 当前机器已安装 Chrome `147.0.7727.56` 与 Edge `151.0.4129.72`，未发现 Firefox；`node_modules` 已存在，Node.js `v22.16.0`、npm `10.9.2`，本轮无需安装新依赖。
