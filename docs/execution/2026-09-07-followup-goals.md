## 5. 潜在风险分析

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 首次编队流程改动影响旧存档 | 新旧存档无法进入战斗 | 保留 `SaveManager` 归一化，增加首次流程兼容分支 |
| 对象池提前清理 | `scene.stop()` 期间再次调用池方法抛异常 | 池方法和 destroy 方法做幂等保护 |
| 粒子资源缺失或尺寸不一致 | 运行时出现缺图或视觉比例漂移 | 先复用已加载资源，新增资源必须登记尺寸和回退 |
| 公共 UI 抽取扩大回归面 | 场景文本/交互层级改变 | 只抽取渲染壳，不移动业务状态 |
| 批量关卡修改放大数值风险 | 难度、掉落和性能无法归因 | 先建立模板，数值改动留到统一验证后 |
| 主观验收被代码结论替代 | 误报“完成” | 明确保留 V5/V6 待人工状态 |

## 6. 优化方案

- 用生命周期 token 取代对 pooled object 身份的隐式假设。
- 让 `ObjectPool` 的 active 查询在 group 已销毁时返回空集，destroy 重复调用安全返回。
- 用统一 `AccessibilitySettings` 读取入口减少场景与系统之间的设置漂移。
- 将粒子池与帧动画池分离，避免为单帧静态粒子修改已有动画契约。
- 组件层以“数据输入 + 事件回调”封装，场景继续拥有状态和路由。
