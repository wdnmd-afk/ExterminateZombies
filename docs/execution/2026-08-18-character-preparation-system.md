## 1. 目标

按已确认角色设计落地五名可玩角色、概率爆头系统、首页入口与战前整备页，使固定关卡和无尽模式都能先选择角色和当前编队内的首发武器，再进入战斗。

## 2. 范围

### 包含

1. 角色配置、素材、存档和战局状态。
2. 四项属性与五个被动的运行时接线。
3. 爆头取代暴击的配置、命中、反馈与结算语义。
4. 首页只读预设摘要和战前整备入口。
5. 战前整备场景的角色/武器选择与开战流程。
6. Game Over 重开与 Level Clear 下一关的流程调整。

### 不包含

1. 药品系统改革。
2. 角色成长、解锁、主动技能和完整剧情。
3. 完整编队编辑；继续由武器库负责。
4. 任何命令或浏览器测试。

## 4. 实施建议

1. 角色数据只从单一配置表读取，禁止在场景中复制数值。
2. 存档只保存 `preferredCharacterId`，运行时必须持有完整本局快照。
3. 角色被动的数学判断优先集中为纯规则函数，`GameScene` 只负责提供状态和执行反馈。
4. 爆头必须在命中感染体时判定，不继续沿用开火时预先决定整颗穿透弹结果的旧行为。
5. 主菜单只显示上次选择摘要，不在主菜单与整备页各维护一套可编辑控件。
6. 使用仓库已有 Kenney 角色素材与 UI 字体，不新增依赖或外部资源。

## 5. 潜在风险

1. 当前相关文件存在未提交的五武器编队与侧栏 HUD 改动，实施时必须基于当前内容增量修改，禁止回退。
2. `WeaponManager`、`Bullet` 与 `GameScene` 的爆头判定迁移会影响散弹、穿透、强化弹丸和反馈类型，必须逐引用核对。
3. 玩家来源爆炸与环境来源爆炸当前共用部分效果链，角色伤害倍率需要在生成武器/地雷效果时固化，不能在公共环境结算中无条件乘算。
4. 死亡保护会改变 Game Over 边界，必须先消费被动，再判断生命是否归零。
5. 新场景会改变挂起战局生命周期；进入整备页不能提前停止 sleeping 的战斗场景。

## 6. 优化方案

1. 通过稳定的 `CharacterDef` 和角色规则函数控制后续数值调整成本。
2. 战前整备使用名单 + 单详情区，避免五张完整大卡造成重复信息和文字溢出。
3. 角色纹理 key 与角色表显式绑定，角色实体不猜测素材名。
4. 结算数据显式携带 `characterId`、`starterWeaponId` 和 `headshots`，重开不读取可能已变化的偏好存档。

## 7. 验证方式

### 本阶段执行

5. 改动范围和未提交工作区保护检查。
