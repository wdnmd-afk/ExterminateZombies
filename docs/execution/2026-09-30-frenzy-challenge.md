# 狂潮挑战首版执行方案

> 日期：2026-09-30；状态：首版实现已落地，V1/V2 通过，V3-V6 待验；不视为最终验收。
> 授权：用户确认优先实现「限时猎杀 + 火力掠夺 + 首领斩杀」。
> 基线：3f0e70e；不提交、不发布、不添加依赖。

## 1. 目标与范围

在既有关卡、无尽之外新增独立 `frenzy` 模式。固定单屏地图、五分钟上限、三套成型预设、三个可自由排序的猎杀目标、三个现场拾取奖励、一个提前解锁的首领、本地分配置纪录。不做永久成长、联机、排行榜或新资产生产。

与无尽的区别：目标驱动而非清波推进；成型开局而非随机抽卡；击杀首领主动通关而非无限生存。任何配置、生命和计分数值均为首轮原型值，不宣称平衡已验证。

## 2. 优先级调整

用户本轮明确要求先做狂潮，因此覆盖爽感规划 v0.1 第 8/9 章「P2 与无尽深化后立项」的候选顺序，仅就狂潮首版提前实施。原 P2、实景边界、资产和许可待办不取消、不标为通过；长期关卡目标不变。决策同步总纲 D-011 与 main-goal 入口。

## 3. 架构预读与复用

- 项目无仓库 AGENTS.md；已读用户全局约束、TESTING_RULES.md、总纲、main-goal、package.json。
- Phaser 场景注册在 src/main.ts / constants.ts，无 Web 路由；状态在 GameState，持久化统一经 SaveManager。
- 无游戏后端 API；server 为图片生成代理，本轮不触碰。
- 复用 ui/components、ui/debrief、DisplayManager、BattlefieldRenderer、对象池、既有武器强化、敌人能力和声音。
- 已核对 GameScene 初始化、更新、击杀、掉落、暂停、挂起、结算和 shutdown；WeaponManager 弹匣、换弹与伤害链；HUD 与菜单入口。
- 狂潮规则独立纯逻辑模块，战场适配独立系统；不启动 WaveManager、不触发随机抽卡、不改写常规整备。

## 4. 锁定的原型规则

1. 预设绑定角色、主武器、辅助手枪和已存在强化。三套：霰弹冲阵、电链风暴、爆破工程。满有效弹匣和数个备用弹匣开局，无须长期解锁。
2. 地图三个区域同时存在猎杀目标和护卫；目标有驻守范围，不能开局全部挤到玩家出生点。目标标签始终可读，显示奖励与当前状态。
3. 三个目标对应弹药狂热、破阵强化、突击补给。死亡后原地掉落唯一核心，接近自动拾取；不占道具栏、不囤积。第三枚核心拾取后立即召唤首领。
4. 弹药狂热持续 12 秒：仅拾取时补满当前有限武器有效弹匣并中止原换弹；期间射击免弹匣消耗，但切枪不补弹、保留射速/散布/换弹要求、不增加备用弹。
5. 破阵强化持续 15 秒：武器伤害 1.5 倍，借助预设自带穿透/电链/爆炸兑现群伤；不永久改写武器定义、不叠乘狂潮奖励。突击补给一次恢复 35% 最大生命、补两弹匣与少量战术资源，受携带上限限制。
6. 普通尸潮不断补充，固定序列与生成位置保证同配置可比，场上数量受限；不要求清空杂兵。召唤子怪不能突破本模式总量预算。
7. 只累计实际战斗 delta；暂停和挂起不走倒计时及奖励时长。期限到达先判失败，期限前首领致死立即锁定成功，动画不能把成功拖成超时；同帧后续伤害不能推翻终态。
8. 计分：每枚核心 2000，通关 10000，剩余整秒 × 100；杂兵贡献最高 1000、最佳连杀贡献最高 1000。失败成绩展示但不写通关纪录，只有正式通关写当前挑战版本/预设的最佳分。调试作弊不记纪录。
9. 死亡、超时、主动重开均清理临时状态与核心对象；返回菜单挂起允许继续，同一次结算最多写入一次。
10. 计时公平性补充：狂潮正在战斗时不请求击杀/穿透慢动作，防止无障碍慢动作设置改变竞速成绩；首领致死锁定终态后保留终结慢动作。关卡与无尽不改动。

## 5. 清晰操作步骤

1. 建配置和纯规则：状态机、去重、时间、终态、计分、奖励与版本纪录校验。
2. 建战场适配：目标/护卫、固定刷新、核心拾取、标签、首领与敌人数上限。
3. 接 GameScene / WeaponManager：隔离初始化、掉落、增伤免耗、结算和生命周期；保持常规模式原行为。
4. 接菜单、预设页、HUD 与结算页；新增唯一存档键，并接入已有清档路径。
5. 增加规则、存档、武器及接线回归；定向检查后按常设授权执行全量测试、类型检查和构建。
6. 记录实景与真人待验项，不以代码或命令通过替代试玩。

## 6. 视觉与交互约束

- 视觉主张：沿用黑色战术台面、旧纸白文字与警戒黄，突出「五分钟猎杀」而非堆满卡片。
- 内容顺序：模式目标 → 三行预设选择 → 所选装备与独立纪录 → 开战。
- 交互重点：复用按钮悬停反馈；奖励拾取短时强调；首领入场沿用战斗播报。无新依赖、无高频闪烁装饰。
- HUD 复用模式/阶段文字区，持续显示剩余时间、核心进度及奖励剩余秒，不另盖一层巨大中央面板。

## 7. 风险与优化方案

| 风险 | 控制 |
| --- | --- |
| 无限模式逻辑串入 | 不启动波次；模式显式保护；不掉强化包；独立结算 |
| 奖励重复/池复用错绑 | 目标引用及时解绑；核心状态 alive/dropped/collected；终态幂等 |
| 所有精英挤中场 | 驻守范围；目标落点避开出生区；顺序由玩家决定 |
| 超时与死亡动画竞争 | 致死锁结果、单一终态；结果冻结后不继续战斗 |
| 弹药奖励切枪刷资源 | 当前弹匣一次性补充；无备用赠送；换弹 token 作废 |
| 存档污染 | 独立版本+预设计分；不解锁关卡/武器，不保存预设到编队 |
| 敌群过密掉帧 | 固定总量上限、每帧生成限额、无递归无限召唤 |
| 可玩但不好玩 | 试玩观察猎杀顺序、目标可读性、爆发兑现与三个预设的通关耗时，再调整数值 |

先保证完整可重开闭环，再调密度和机会，再改善反馈，最后扩地图和随机变体。

## 8. 验证方式与终止标准

- V1：规则去重、不同顺序、三核心才出首领、到时失败、提前通关、计分封顶、奖励到期与暂停、坏存档、版本隔离、清档、预设有效性。
- V2：现有测试、类型检查、构建；不能修改依赖或用跳过检查掩盖失败。
- V3/V4：实际菜单进入三套预设、未解锁也可开局、核心现场拾取、首领登场、超时/死亡/成功结算、原预设重开、暂停/挂起恢复、两旧模式回归，观察控制台与截图。
- V5：自然游玩三套预设各至少一局，无无敌、补弹和跳进度；核对通关耗时、压力与可读性。
- V6：真人判断是否比无尽更主动、能否描述猎杀顺序与火力奖励的作用、是否愿意重玩。
- 若浏览器工具仍不可用，不绕过已拒绝的启动机制；明确保留 V3-V6 未验，不宣称可上线。

### 9.1 已落地内容

- 菜单入口与独立预设页：快捷键 6 进入，1/2/3 选预设，Enter 开战；复用角色立绘与按钮组件。

- 独立版本/预设纪录，正常通关才写入；清进度与全清档包含狂潮纪录。旧编队、角色偏好、武器许可、无尽和关卡进度不被狂潮改写。

### 9.4 玩法业务链自动化收口

用户要求先收口玩法业务并继续自动测试。本批不扩展模式或视觉，按以下步骤执行：

1. 复用现有真实场景方法转译测试工具，抽入 tests/helpers，避免多份场景方法提取逻辑。
2. 串联真实 FrenzyDirector、WeaponManager、ItemManager、SaveManager 与 GameScene 奖励/结算方法，验证三预设 × 六种猎杀顺序。
3. 覆盖现场拾取、暂停时间冻结、三个奖励各一次、首领唯一召唤、成功存档与重开原预设；补死亡/超时失败不写通关记录。
4. 保留图形、物理实体和时间驱动为明确测试替身，不冒充浏览器端到端或自然试玩；不以测试注入得到的通关时间评估平衡。
5. 定向通过后执行全量测试与类型检查，保存新证据且不覆盖上一批记录。若发现业务缺陷先修生产代码并补回归，再汇报结果。
