# 角色美术升级实施追踪

> 状态：代码与产物已落地，待用户复核视角/画风取舍与实景验证  
> 建立日期：2026-08-18  
> 关联设计：`docs/playDesign/角色与战前整备系统.md`  
> 目标：解决战前整备把低分辨率实机精灵放大后观感粗糙的问题，并为后续实机角色替换建立许可与规格门槛

---

## 1. 目标

1. 为守望者、鹰眼、堡垒、疾行者、破阵者提供五张统一规格的专用角色档案立绘。
   实现路径已由 AI 生成调整为同包矢量源切片，理由见 3.6。
2. 战前整备页改用档案立绘，不再放大 `37×43` 左右的实机小精灵。
3. 确认一套包含至少五个角色、同规格、许可清晰的俯视角实机精灵包。
   结论是现有 Kenney 包已满足门槛，无需外部检索，见 3.5。
4. 在用户复核前保留当前 Kenney 实机素材作为战斗回退，不贸然改变枪械锚点、碰撞和旋转表现。

## 2. 范围

### 本轮包含

1. 五张角色档案立绘的视觉规格、生成、筛选、落盘和代码接入。
2. 实机角色素材包的来源、许可、角色数量、方向/动画和可接入性调查。
3. `characters.ts` 增加档案立绘纹理 key，`PreloadScene` 加载，`PreparationScene` 消费。
4. 资产台账、运行时清单和本追踪文档同步。

### 本轮暂不包含

1. 未经用户复核直接替换战斗中的五个角色小精灵。
2. 重新制作分武器持枪动画。
3. 修改玩家碰撞体、枪口锚点或角色旋转规则。
4. 混用五个不同作者或五个不同画风的实机角色素材。

## 3. 美术规格

### 3.1 统一视觉命题

**末日战地档案中的五名专业幸存者：硬朗、可信、具有职能差异；使用清晰的现代像素插画，而不是可爱卡通或低清放大。**

### 3.2 档案立绘规格

1. 五张图使用相同画幅、相同机位、相同光源方向和相同像素颗粒密度。
2. 构图为大腿上方或膝上半身，人物完整，不裁头、不裁武器主体。
3. 人物朝画面右前方约 20–30°，与当前游戏朝右瞄准方向建立联系。
4. 背景使用可稳定抠除的纯色键控底，不带文字、边框、UI、水印、地面阴影或复杂环境。
5. 最终输出为带透明通道 PNG；每张主体在画布中占比和底部基线一致。
6. 服装与装备按角色职能区分，但不使用现实军队徽标、品牌标识或版权角色特征。
7. 五张图必须能在战前整备约 `188×230` 的稳定显示区内清晰辨识。

### 3.3 五角色形象方向

| 角色 | 形象方向 | 主色提示 | 必须避免 |
| --- | --- | --- | --- |
| 守望者 | 可靠的城市幸存者，轻型护具和实用背带 | 警戒黄 + 深灰 | 过度英雄化、重甲 |
| 鹰眼 | 冷静精确的侦察射手，轻装、护目镜、精密装备 | 冷青 + 黑 | 巨型狙击镜遮脸 |
| 堡垒 | 厚重防护、宽肩轮廓、旧防爆装备 | 暗红 + 钢灰 | 科幻动力甲 |
| 疾行者 | 轻量机动、运动护具、短外套和便携装备 | 绿色 + 炭黑 | 忍者、超级英雄紧身衣 |
| 破阵者 | 高风险突击手，弹药带、破门工具和磨损护具 | 焦橙 + 深褐 | 夸张爆炸背景、裸露肌肉卖点 |

### 3.4 实机素材候选门槛

1. 必须来自同一作者或同一素材包，至少五个可区分人物。
2. 必须有明确的 CC0、CC-BY 或可用于游戏的商业许可，并能在仓库留存来源页和许可证。
3. 优先透明 PNG、32–64px 人物主体、统一画布和同一朝向/方向集。
4. 若为旋转单图，必须能与当前外置武器覆盖层对齐；若为方向动画，需要同时评估改造成本。
5. 不接受仅有宣传预览、无法获得原始文件、来源失效或 AI 来源声明不清的资源。

### 3.5 A2 结论：现有 Kenney 包已满足门槛，且自带矢量源

A2 原计划到站外检索新素材包，实际核对后结论是**不需要外部检索**：仓库内已归档的
`kenney-topdown-shooter/` 本身就通过 3.4 的全部五条门槛。

| 门槛 | 现有 Kenney 包实测 |
| --- | --- |
| 同包 ≥5 个可区分人物 | 通过，`PNG/` 下 9 个人形目录（Hitman 1、Man Blue、Man Brown、Man Old、Robot 1、Soldier 1、Survivor 1、Woman Green、Zombie 1），当前已用 5 个 |
| 许可清晰且可留档 | 通过，CC0 1.0，仓库已存 `License.txt` 与 `SOURCE.md` |
| 透明 PNG、统一画布与朝向 | 通过，全部 `43px` 高、统一朝右、同一姿态集（stand/hold/reload/gun/machine/silencer） |
| 可与外置武器覆盖层对齐 | 通过，当前实机已在用 `*_hold.png`，枪械锚点未改动 |
| 非宣传预览、来源可追溯 | 通过，原始 ZIP 与来源页均已归档 |

核对过程中还发现一项原方案未记录的关键资源：同包 `Vector/vector_characters.svg`
是这套人物的**矢量源**（CC0）。它由 54 个姿态组成 9 人物 x 6 姿态的规整网格，
全部姿态右边界对齐，每个姿态固定三层（俯视投影阴影 / 手臂底层 / 身体主体）。
这直接改变了 A3 的最优实现路径，见 3.6。

### 3.6 A3 路径调整：矢量源切片替代 AI 生成立绘

原 A3 计划用 AI 生成五张半身档案立绘。实际改为**从上述 Kenney 矢量源切出五张单角色
SVG，运行时按渲染倍率矢量栅格化**。调整原因、影响与代价如下。

**为什么调整**

1. 本轮执行环境不具备图像生成能力，原 A3 无法在本轮真正交付；矢量方案可以立即交付。
2. 矢量方案直接消除 6 节风险表的前四项：同源素材不存在风格漂移，无键控底因此不存在
   抠图色边，与实机同源因此不存在“角色变身”，继承 CC0 因此不存在许可不清。
3. 不引入任何新依赖：Phaser 3.90 的 `load.svg` 由浏览器原生矢量栅格化。
4. 立绘与实机精灵严格同源，服装主色、轮廓和职能特征天然一致，无需人工对齐。

**代价与取舍**

1. 档案立绘仍是**俯视角**，不是 3.2 原定的“大腿上方半身、朝右前方 20–30°”。
   规格 3.2 的第 2、3 条在本路径下不成立，其余条（统一画幅、统一光源、透明通道、
   统一基线、无水印边框、职能配色区分）全部满足。
2. Kenney 画风偏平滑卡通，不是 3.1 描述的“现代像素插画”。视觉命题因此从
   “末日战地档案插画”降级为“清晰、统一、可信的战术档案图示”。
3. 若之后仍要半身立绘，本轮成果不冲突：立绘走独立 `portraitTextureKey`，替换只需
   改产物与加载源，不触碰实机精灵、枪口锚点或战斗逻辑。

**结论**：本轮以矢量方案解决“放大粗糙”这一实际问题；是否追加半身立绘留待用户复核后决定。

### 4.1 A7 说明：矢量立绘降级为占位

用户对 A3 产物的复核结论是**观感不合格、五个角色缺少个人特色**。根因是 Kenney 这套人物
本身是同一体型模板换配色，矢量化只提升了清晰度，无法产生体型、年龄、姿态和面部特征上的
差异，个人特色的上限由源素材决定。

因此矢量立绘的定位从「A3 交付物」降级为**占位与回退**：

1. 战前页在新立绘到位前仍有清晰可用的角色图，不会退回放大位图，也不会缺图。
2. 生成脚本与产物保留，直到新立绘通过用户验收。
3. 替换只涉及产物与加载源，不触碰实机精灵、枪口锚点、碰撞体和战斗逻辑，因为
   `portraitTextureKey` 与 `textureKey` 已经分离。

## 5. 实施建议

1. 先以守望者确定母版画风和构图，再用同一骨架生成其余四人，避免五张图各自发挥。
2. AI 立绘只用于角色档案表现，不伪装成来源明确的第三方游戏素材；资产台账必须标记为项目生成。
3. 实机素材候选先记录，不在本轮未经复核替换，避免为“更好看”牺牲枪口对齐和战斗可读性。
4. 档案图使用独立 `portraitTextureKey`，不能复用 `textureKey`，确保战前与实机素材可分别替换。

## 6. 风险与优化

原风险表按 3.6 的路径调整重新评估；前四项已由“同源矢量素材”消除。

| 风险 | 影响 | 当前状态 |
| --- | --- | --- |
| 五张 AI 图人物风格漂移 | 像五个不同游戏的角色 | 已消除，五图取自同一作者同一矢量源同一姿态列 |
| 键控底残留色边 | 深色 UI 上出现绿边/紫边 | 已消除，矢量源本身带透明通道，无键控抠图环节 |
| 大立绘与实机小人差异过大 | 玩家感觉角色“变身” | 已消除，立绘与实机是同一图形的矢量版与位图版 |
| 第三方素材许可不清 | 无法安全发布 | 已消除，继承已归档的 Kenney CC0，无新增署名义务 |
| 立绘遮挡 UI | 属性或按钮不可读 | 仍需实景确认；统一画幅 `44 x 48` 居中，缩放上限仍为 `188 x 230` 展示框 |
| 立绘表现力弱于半身插画 | 角色辨识度提升有限 | 已知取舍，见 3.6；不阻塞本轮，后续可替换产物而不动战斗链 |
| 立绘纹理占用显存 | 低端设备内存压力 | 已按渲染倍率缩放：1x 档 `220 x 240`、2x 档 `440 x 480`，五张合计约 1.1–4.2 MB |
| 误用最近邻过滤 | 矢量立绘降采样出现锯齿 | 已在 `GameAssetManager` 单独对立绘设线性过滤，实机精灵仍走最近邻 |

## 7. 验证方式

### 7.1 本轮已完成

1. 图层定位：五个目标姿态经**颜色签名**与**姿态宽度签名**双向核对确认，不是按位置推测。
   9 行颜色分布与 `PNG/` 下 9 个人物的实际像素主色一一对应；`Woman Green` 与
   `Zombie 1` 的绿色签名重叠部分再用 `Zombie 1` 独有的 `#666666`、`#D26014` 区分。
2. 几何精度：`hold` 姿态主体实测 `36.38`、`34.63`、`36.98`、`34.63`、`34.63` x `43.00`，
   与 spritesheet 登记的 `37`、`35`、`38`、`35`、`35` x `43` 吻合（PNG 含抗锯齿边向外取整）。
3. 产物正确性：离线近似栅格化后与 Kenney 原始 PNG 对比，五张轮廓 IoU 均为 `0.980–0.984`，
   纯色主色重合 `7–10 / 10`；剩余差异来自验证脚本的折线近似与带洞路径填充，不是产物缺陷。
4. 画幅与居中：五张 SVG 内容边界实测 x `3.81–40.19`、y `2.50–45.50`，全部落在
   `44 x 48` 画幅内且居中，主体基线一致。
5. XML 合法性：生成脚本写盘前用 `ElementTree` 解析一次，避免拼接出结构非法的产物。
6. 结构精简：产物已内联 path，不含 `<defs>`/`<use>`/`xlink`，避免 `<img>` 受限上下文
   下的引用解析差异（Phaser 的 SVG 加载器会经 `Blob` 交给 `<img>`）。
7. 引用链静态核对：五个角色 ID → `portraitTextureKey` → `PreloadScene` 的 `load.svg`
   → `GameAssetManager` 线性过滤 → `PreparationScene` 消费，一一对应无遗漏。
8. 类型契约核对：`load.svg` 的第三参数 `SVGSizeConfig` 支持 `scale`，
   `vite/client` 已声明 `*.svg` 模块默认导出，接入不依赖新的类型声明。
