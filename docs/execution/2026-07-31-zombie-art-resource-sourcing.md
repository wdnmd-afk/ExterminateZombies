# 僵尸美术资源筛选与下载执行文档

> 日期：2026-07-31  
> 状态：已完成  
> 任务类型：外部美术资源调研、许可证核验与原始文件归档

## 1. 目标

为当前俯视角像素射击玩法寻找一套或少量几套能够统一僵尸视觉质量的资源，并将通过筛选的原始资源、来源信息和许可证记录归档到仓库，为后续制作僵尸美术垂直切片提供可靠输入。

本轮优先解决以下问题：

1. 当前僵尸同时混用 RPG 正侧面、俯视旋转和不同像素密度素材，视角与画风不统一。
2. 普通感染体缺少统一的轮廓、光源、比例和动画标准。
3. Boss 主要复用普通感染体贴图并放大换色，缺少独立视觉身份。
4. 外部资源必须具备明确的商业使用与修改许可，且来源能够长期追溯。

## 2. 范围

本轮包含：

1. 盘点仓库已有但未接入的 Kenney 俯视角色与僵尸素材。
2. 搜索 Kenney 与 itch.io 上适合俯视角射击的像素僵尸、感染体或人物资源。
3. 核验候选资源的视角、像素密度、动画覆盖、文件格式、许可证和署名要求。
4. 下载最合适的原始资源到 `src/assets/downloaded/`。
5. 为新增资源建立 `SOURCE.md`，保留资源包自带的许可证文件。
6. 解压后检查实际内容并生成候选结论。

本轮不包含：

1. 不直接替换当前运行时僵尸贴图。
2. 不修改敌人数值、能力、关卡或掉落配置。
3. 不批量下载只具备概念参考价值的资源。
4. 不购买付费资源，不绕过 itch.io 或作者设置的登录、支付与下载限制。
5. 不把无法确认授权范围的文件写入正式素材目录。

## 3. 筛选标准

候选资源按以下顺序评估：

1. **视角一致性**：必须是正交俯视或稳定的三分之四俯视，不能继续引入 RPG 正面/侧面人物。
2. **轮廓可读性**：在 `1280 x 720` 战场和约 40-64 逻辑像素显示尺寸下，基础、快速、远程和重装角色仍可区分。
3. **动画覆盖**：优先包含移动、攻击、受击和死亡；只有静态图或单一移动动画的资源只能作为概念候选。
4. **风格兼容**：像素轮廓、色板与现有真实枪械贴图和暗色战场不冲突，避免明显 Q 版或高饱和休闲风。
5. **生产可扩展性**：优先同一作者或同一系列中能继续扩充玩家、感染体、Boss 和环境物的资源。
6. **许可证清晰**：优先 CC0；可接受允许修改和商业使用的自定义许可、CC-BY 或 OGA-BY，但必须记录署名要求。
7. **源文件质量**：优先 PNG 精灵表、Aseprite 源文件或带 JSON 的纹理图集；不使用只能从网页预览图截取的资源。

## 4. 操作步骤

1. 列出仓库内 Kenney Topdown Shooter 等已下载包的全部人物和僵尸文件。
2. 查看代表性帧，确认现有包是否已经能够作为统一基底。
3. 搜索 Kenney 官方资源页，记录符合筛选标准的候选与许可证。
4. 搜索 itch.io，优先使用 `top-down`、`zombie`、`pixel art`、`animated` 等组合，并进入具体资源页核对说明。
5. 对每个候选记录：名称、作者、来源页、下载链接、价格、许可、动画、帧尺寸和适配结论。
6. 只下载综合评分最高且无需付费或额外授权确认的资源。
7. 将原始压缩包放入对应资源包目录，并保留原文件名。
8. 解压到同一目录，检查是否包含隐藏的许可限制、源文件和动画表。
9. 新建 `SOURCE.md`，记录下载日期、来源、许可证、文件哈希和建议用途。
10. 更新 `docs/ART_ASSET_REGISTRY.md`，初始状态标记为“已下载未接入”。
11. 对资源中的代表性图片进行本地预览，核对透明背景、帧方向、像素尺寸和美术一致性。

## 5. 实施建议

1. 首选能够同时覆盖玩家与僵尸的同系列资源，减少视角和像素密度漂移。
2. 若没有单包覆盖全部角色，先选择一套作为比例、光源和轮廓基准，其余资源只作为重绘参考。
3. 后续正式接入时先制作 `walker`、`runner`、`lurker`、`tank` 和一个 Boss，不一次替换全部感染体。
4. 外部包只提供基础时，可在统一模板上重绘服装、伤口和变异部位，最终导出项目自有的扁平精灵表。
5. AI 生成内容只用于概念和配色参考，不直接作为跨帧动画素材。

## 6. 潜在风险分析

1. **授权风险**：itch.io 的“免费”不等于允许商业使用或再分发，必须以资源页和包内许可为准。
2. **登录或付费限制**：部分 itch.io 资源需要账号、捐赠或购买；本轮不得绕过这些限制。
3. **预览误导**：网页截图可能包含未随下载包提供的角色或动画，必须检查实际归档内容。
4. **风格继续混用**：下载多个看似可用的包容易再次形成拼贴，因此最终只允许一个主基底。
5. **动画不足**：仅有行走帧的资源无法解决攻击和死亡反馈粗糙的问题。
6. **比例与碰撞偏差**：新资源尺寸可能明显大于现有实体碰撞半径，后续接入时需要独立校准视觉尺寸与物理体。
7. **仓库体积增长**：原始 ZIP、源文件和导出文件并存会增加仓库体积，只归档真正进入候选名单的资源。

## 7. 优化方案

1. 为候选建立统一评分表，避免凭单张预览图主观选择。
2. 使用 SHA-256 记录原始下载文件，保证来源与后续派生过程可追溯。
3. 后续采用统一帧尺寸或纹理图集导出，替代当前按不同来源手工切割的不等距帧。
4. 将视觉尺寸写入美术规范，避免运行时继续使用大量小数缩放修补素材差异。
5. 在正式接入前用单一关卡制作并排截图，对比现有素材与候选素材在真实战斗距离下的可读性。

## 8. 验证方式

1. 每个新增资源目录都有原始归档、解压内容、`SOURCE.md` 和许可证依据。
2. 来源页、作者、许可证和下载日期能够从台账追溯。
3. 压缩包可以正常解压，代表性 PNG 可以正常读取且不是网页缩略图。
4. 候选素材的视角与玩家俯视视角一致。
5. 候选至少具备可用移动动画；缺少攻击、受击或死亡时必须明确记录缺口。
6. 不运行全量构建；本轮仅进行文件完整性、哈希、图片尺寸和视觉检查。

### 9.3 计划偏离

原计划要求将通过筛选的资源归档到 `src/assets/downloaded/` 并更新美术台账。实际执行时发现免费候选虽然允许用于个人/商业游戏，但没有明确允许在公开源码仓库中再分发原始 `.aseprite` 文件，压缩包内也没有许可证副本。

为控制授权风险，本轮改为：

1. 原包只存放在 Git 忽略的本地候选目录。
2. 不更新 `ART_ASSET_REGISTRY.md` 的“已下载未接入”正式条目，因为资源尚未满足可入库条件。
3. 仅在本执行文档和候选目录 `SOURCE.md` 中记录来源、哈希和限制。

### 9.4 最终建议

1. 正式美术优先购买并试接 SmallScaleInt Top-Down Zombie Pack 2；它与当前俯视射击、像素武器和 18 类感染体结构最接近。
2. 免费 la.couenne 包可用于验证八方向动画管线和怪物角色分配，但需要 Aseprite 或兼容导出工具，并应先向作者确认公开仓库分发方式。
3. 不建议为了“已经下载”而接入 Kenney 小僵尸、24x24/16x16 僵尸或正侧面 RPG 素材，这些资源会延续当前质量问题。
4. 付费素材购买后应先在本地私有目录完成导出与运行时验证，再决定哪些派生 PNG 可以进入发布包及仓库。
