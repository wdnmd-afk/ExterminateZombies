# 首页怪物图鉴执行文档

## 目标

1. 在主菜单增加清晰可点击的“怪物图鉴”入口，并提供数字快捷键。
2. 新增独立怪物图鉴场景，完整展示当前配置中的 6 类僵尸与 Boss。
3. 图鉴中的生命、速度、伤害、攻击间隔、得分、掉落和出现关卡均从现有配置动态生成，避免展示数据与玩法数据漂移。
4. 复用已经加载并切帧的僵尸像素素材，在详情区播放真实方向动画，不新增重复素材处理逻辑。
5. 保持现有关卡、无尽模式、掉落、存档和战斗数值不变。

## 范围

本轮涉及：

1. 新增 `src/config/monsterLibrary.ts`：维护图鉴顺序、档案代号、定位、威胁等级和应对建议，并从现有配置派生玩法数据。
2. 新增 `src/scenes/MonsterLibraryScene.ts`：实现图鉴索引、动画预览、详情数据和返回交互。
3. 修改 `src/scenes/MainMenuScene.ts`：增加怪物图鉴按钮与快捷键，重新分配二级操作区。
4. 修改 `src/constants.ts`：增加怪物图鉴场景 key。
5. 修改 `src/main.ts`：注册怪物图鉴场景。
6. 更新本执行文档的执行与验证结果。

明确不修改：

1. `ZombieDef` 字段与 `ZOMBIES` 中的战斗数值、掉落概率。
2. `LEVELS` 的波次、Boss 和场景布局。
3. `GameScene`、`WaveManager`、`Zombie` 的运行时战斗逻辑。
4. `PreloadScene` 与 `GameAssetManager` 的素材加载、帧切分和动画注册逻辑。
5. 存档结构、关卡解锁规则和武器图鉴。
6. 本轮不执行 `npm run build`。

## 已确认的数据来源

1. 怪物全集与战斗数据：`src/config/zombies.ts`。
2. 怪物出现关卡：从 `src/config/levels.ts` 的固定波次与 Boss 配置动态检索。
3. 武器与道具掉落名称：分别从 `src/config/weapons.ts`、`src/config/items.ts` 获取。
4. 僵尸纹理、缩放、着色与方向动画：复用 `src/systems/GameAssetManager.ts` 的 `getZombieVisual` 和 `getZombieAnimationKey`。
5. 当前收录顺序：`walker`、`runner`、`tank`、`bomber`、`tank_boss`、`bomber_boss`。

## 视觉与内容方案

### 视觉主张

延续首页与武器库的“黑稿战地档案”视觉语言，以深色档案台、警戒黄色选中态和一只持续行走的像素怪物作为详情区唯一视觉焦点。

### 内容规划

1. 顶部：怪物图鉴标题、收录数量和返回入口。
2. 左侧：6 类感染体连续索引，展示编号、名称、定位与威胁等级，不使用卡片墙。
3. 右侧：当前感染体动画、精确战斗数值、出现关卡、死亡危险、掉落和应对建议。
4. 底部：展示档案数据同步状态，不堆叠操作教学文案。

### 交互主张

1. 场景进入时标题、索引、详情和底部信息依次淡入上移。
2. 鼠标悬停或点击索引时切换详情；列表行轻微右移，怪物动画短促显影回弹。
3. 支持方向键或 W/S 顺序浏览，ESC 和顶部返回按钮回到主菜单。

### 文案调整记录

界面不新增快捷键教学文案。方向键、W/S、ESC 和数字快捷键继续作为可用交互，但首页与图鉴底部只展示模块或数据状态，避免操作说明挤占档案内容层级。

## 操作步骤

1. 建立怪物图鉴展示配置，只保存无法从战斗表推导的展示内容。
2. 编写派生函数：
   - 从 `ZOMBIES` 读取精确战斗数值。
   - 从 `LEVELS` 读取实际出现关卡。
   - 从掉落表生成准确的掉落名称、数量和概率。
   - 从 `explodeOnDeath` 生成死亡爆炸危险说明。
3. 新增怪物图鉴场景，复用当前纹理与动画注册结果。
4. 在主菜单二级操作区加入怪物图鉴，快捷键调整为：`1` 关卡、`2` 无尽、`3` 武器库、`4` 怪物图鉴、`5` 设置。
5. 注册场景并执行类型检查。
6. 使用现有开发服务器验证首页入口、图鉴切换、动画纹理和返回链路。

## 实施建议

1. 图鉴配置以 `ZombieId` 作为唯一关联键，不复制生命、速度、伤害或掉落概率。
2. 未配置有效名称的掉落不做猜测式展示，直接标记为配置异常，便于发现真实数据问题。
3. 怪物预览使用固定展示区域和稳定缩放倍率，保留普通怪与 Boss 的相对体型差异，同时避免文字布局移动。
4. 详情文本对象复用并通过 `setText` 更新，切换怪物时不重复创建整套面板。
5. 图鉴场景继续调用统一高清适配函数，保证 1×/2× 渲染行为一致。

## 潜在风险分析

1. Boss 复用普通怪物纹理，仅依靠放大和着色区分；图鉴必须明确标记 Boss 身份，避免看起来像重复条目。
2. 僵尸原图尺寸较小，非整数缩放可能模糊；必须沿用最近邻纹理过滤，并使用稳定倍率。
3. 主菜单二级操作区由 3 个按钮增加到 4 个，需要缩短按钮文案并检查文字是否溢出。
4. Phaser 场景重复进入时若键盘监听未使用场景生命周期管理，可能重复触发；优先使用 `once` 或随场景销毁的输入监听。
5. 部分怪物只在 Boss 配置中出现，出现关卡检索必须同时检查普通波次和 `level.boss`。

## 优化方案

1. 只创建一个详情精灵并在切换时更新纹理、动画、缩放和着色，降低对象数量。
2. 所有数值和掉落展示在选中时即时派生，内容扩展后无需手动同步图鉴。
3. 左侧列表采用共享绘制逻辑与引用表，避免为每个怪物复制交互实现。
4. 场景只复用已经预加载的四张僵尸源图，不增加网络请求或首屏资源体积。

## 验证方式

1. 运行 `npm run typecheck`，必须零错误。
2. 首页确认存在“怪物图鉴”按钮，点击和数字 `4` 均可进入；数字 `5` 可进入设置。
3. 图鉴逐项检查 6 类感染体：名称、动画、数值、出现关卡、掉落和危险说明与配置一致。
4. 鼠标悬停/点击、方向键、W/S、ESC 和顶部返回按钮均可正常操作。
5. 在 `1280 × 720` 视口截图检查：文字不溢出、按钮不重叠、Boss 预览不遮挡详情。
6. 捕获浏览器运行时异常，确认场景进入和切换过程中无未处理错误。
7. 本轮不执行 `npm run build`；只有用户明确要求时再做全量构建。
