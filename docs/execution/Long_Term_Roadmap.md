# ExterminateZombies 可执行长期路线图

## 1. 文档定位

本文档是 [Long_Term_Goals.md](/E:/github/ExterminateZombies/docs/Long_Term_Goals.md) 的执行版。

它不再讨论“想做成什么”，而只回答四件事：

1. 当前版本已经具备哪些可确认能力。
2. 接下来先做什么，后做什么。
3. 每个阶段具体要改哪些模块、交付什么结果。
4. 做到什么程度，才算该阶段完成。

原则：

1. **近两阶段拆到任务级**，可以直接进入开发排期。
2. **更远阶段只保留里程碑级**，避免伪精确。
3. **每个阶段都必须以可玩的版本结束**，不允许中间态长期悬空。

---

## 2. 当前基线

## 2.1 已完成基线

当前仓库已经具备以下能力：

1. Phaser + Vite + TypeScript 基础架构已经稳定可运行。
2. 玩家移动、瞄准、射击、换弹、切枪、基础掉落已接通。
3. 僵尸追击、伤害、死亡、波次推进、关卡与无尽模式已接通。
4. 油桶、面粉桶、地雷、连锁爆炸、残留区已接通。
5. 关卡解锁、多关卡选择、设置改键、基础 HUD、暂停、波次提示已接通。
6. 已有初步战斗反馈：枪口闪光、命中火花、爆炸冲击、拾取提示、低血量危险边缘。

## 2.2 当前主要缺口

当前项目仍明显缺少以下内容：

1. **Boss 机制仍未整体定型**，巨型坦克已接入两阶段、震荡/冲锋、场景互动和动作帧，但缺浏览器试玩；其它 Boss 仍只有单一技能节奏。
2. **音效系统已接线但未完成主观混音**，八把武器、战斗、UI 和音乐均有文件音频，多浏览器听感仍待验收。
3. **美术仍以占位图形为主**，视觉语言已出雏形，但还没有统一的正式像素资产。
4. **关卡内容量不够**，虽然已能通关与解锁，但还不够支撑稳定复玩。
5. **没有正式试玩门槛**，缺少版本级验收清单、构建门槛和性能观察基线。

## 2.3 当前判断

项目已经不适合继续“广撒网扩系统”，下一步应该按以下顺序推进：

1. 先把核心战斗打透。
2. 再做一个高质量垂直切片。
3. 再扩内容量。
4. 最后准备公开试玩。

## 3. 路线图总览

| 里程碑 | 状态 | 建议周期 | 目标 |
|---|---|---:|---|
| M0 当前基线固化 | 已基本完成 | 0.5 周 | 统一当前可玩版本，补最小回归清单 |
| M1 核心战斗定型 | 进行中 | 2-3 周 | 把战斗手感、Boss 机制、声音反馈打到“值得反复开局” |
| M2 垂直切片 | 高优先级后续 | 3-4 周 | 做出 1-2 关接近正式品质的代表内容 |
| M3 内容扩展 | 中期 | 4-6 周 | 扩充关卡、敌人、武器和无尽事件池 |
| M4 公开试玩准备 | 中后期 | 1-2 周 | 把项目打到可发给外部试玩的水平 |
| M5 发布候选 | 远期 | 2-3 周 | 形成第一个可正式发布的版本 |

说明：

1. 周期按单人或小团队节奏估算。
2. 如果中间发现核心战斗仍不稳定，优先回退到 M1，不继续推进后续里程碑。

---

## 4. 执行规则

所有阶段统一遵守以下规则：

1. 阶段开始前必须确认：
   - 目标
   - 范围
   - 不做项
   - 验收标准
   - 最小验证方式
2. 阶段中新增需求必须先判断：
   - 是否改变当前阶段目标
   - 是否需要新文档
   - 是否会推迟当前阶段完成
3. 阶段结束时必须至少交付：
   - 可运行版本
   - 验收结果
   - 剩余风险列表

## 5. 近两阶段可执行拆解

## 5.1 M1 核心战斗定型

### 目标

把当前“已经能玩”的版本，打磨到“愿意重复开局”的水平。

### 本阶段完成定义

满足以下全部条件，M1 才算完成：

1. Boss 不再只是数值放大版，至少有两种可识别技能节奏。
2. 玩家可以仅凭视觉和声音判断：
   - 开火是否成功
   - 命中是否有效
   - 爆炸是否危险
   - 弹药是否吃紧
3. 关卡模式连续打 2-3 关时，不会因为数值或资源曲线明显失衡而失去节奏。
4. 有一套固定的手动验收清单，至少可用于每次大改后回归。

### 不做项

本阶段不做：

1. 正式全量美术替换
2. 大规模新关卡扩张
3. 在线排行榜
4. 账号、云存档、联机

### 任务清单

#### M1-T01 Boss 机制化

状态：`tank_boss` 垂直切片代码已接线，待第二关浏览器试玩与参数校准；其它 Boss 不在本轮范围。

目标：

- 让 `tank_boss` 和 `bomber_boss` 不再只是高血高伤，而是有明确攻击节奏。

建议修改范围：

- [zombies.ts](/E:/github/ExterminateZombies/src/config/zombies.ts)
- [Zombie.ts](/E:/github/ExterminateZombies/src/entities/Zombie.ts)
- [GameScene.ts](/E:/github/ExterminateZombies/src/scenes/GameScene.ts)
- 必要时新增 `systems/BossBehavior.ts` 或等价抽象

实施步骤：

1. 为 Boss 补充技能描述字段或行为标识。
2. 给 `tank_boss` 增加至少一个重击/冲锋型技能。
3. 给 `bomber_boss` 增加至少一个范围预警/投掷型技能。
4. 为技能补充可读前摇和视觉预警。
5. 在 Boss 波开始时加强 HUD/Banner 提示。

交付物：

1. 两种 Boss 有不同压迫方式。
2. Boss 技能有前摇和危险提示。

验收标准：

1. 玩家在第一次遇到 Boss 时，能在 10 秒内理解其主要危险动作。
2. Boss 战不再等价于“把普通僵尸血量调大”。

验证方式：

1. `npm run typecheck`
2. 手动打 `level_2` 与 `level_3` Boss 波各至少 2 次

#### M1-T02 音效骨架接入

状态：统一播放入口、文件音效、菜单/战斗循环与音量设置已接线，待主观混音和多浏览器验收。

目标：

- 为战斗链路补最小但有效的声音层。

建议修改范围：

- [PreloadScene.ts](/E:/github/ExterminateZombies/src/scenes/PreloadScene.ts)
- [GameScene.ts](/E:/github/ExterminateZombies/src/scenes/GameScene.ts)
- [HUDScene.ts](/E:/github/ExterminateZombies/src/scenes/HUDScene.ts)
- 必要时新增 `src/audio/` 或 `systems/SoundManager.ts`

实施步骤：

1. 确定最小音效清单：
   - 手枪/步枪/霰弹枪/冲锋枪开火
   - 命中
   - 爆炸
   - 拾取
   - UI 点击
   - 低血量或空弹提示
2. 建立统一音量层级和播放入口。
3. 避免单帧高频音效叠爆。
4. 为暂停和菜单预留 BGM 接口，但本阶段可只接一条短循环底音。

交付物：

1. 最小战斗音效集
2. 统一播放入口

验收标准：

1. 战斗时至少能靠声音区分开火、命中、爆炸和拾取。
2. 不出现明显炸耳、重复叠音、暂停后继续响的问题。

验证方式：

1. `npm run typecheck`
2. 浏览器内完整打一局并检查暂停/结算时声音状态

#### M1-T03 战斗 UX 校正

目标：

- 把目前已有 HUD、波次提示、拾取提示进一步校正成“信息够用但不乱”。

建议修改范围：

- [HUDScene.ts](/E:/github/ExterminateZombies/src/scenes/HUDScene.ts)
- [GameScene.ts](/E:/github/ExterminateZombies/src/scenes/GameScene.ts)

实施步骤：

1. 增加空弹、换弹、Boss 技能前摇等关键状态提示。
2. 调整提示停留时间和优先级，避免屏幕上同时出现过多信息。
3. 明确 HUD 信息层级：
   - 核心状态常驻
   - 波次状态短暂出现
   - 拾取提示短暂出现
   - 危险提示仅在危险时出现
4. 修正当前可能存在的文案重复和视觉拥挤。

交付物：

1. 更稳定的 HUD 信息层级
2. 更明确的关键状态提示

验收标准：

1. 玩家在战斗中不需要盯着所有角落找信息。
2. 关键危险提示不会被拾取提示或普通文本覆盖。

验证方式：

1. `npm run typecheck`
2. 手动完成一局关卡模式与一局无尽模式，观察 HUD 负担

#### M1-T04 第一轮数值平衡

目标：

- 把武器、掉落、波次、资源曲线拉到合理区间。

建议修改范围：

- [weapons.ts](/E:/github/ExterminateZombies/src/config/weapons.ts)
- [zombies.ts](/E:/github/ExterminateZombies/src/config/zombies.ts)
- [levels.ts](/E:/github/ExterminateZombies/src/config/levels.ts)
- [GameState.ts](/E:/github/ExterminateZombies/src/systems/GameState.ts)

实施步骤：

1. 校正初始弹药和掉落频率。
2. 校正 `level_1 ~ level_3` 的波次数量和出怪节奏。
3. 校正无尽模式前 10 波难度曲线。
4. 校正不同武器在当前敌人池里的职责边界。

交付物：

1. 第一轮数值表
2. 一份“当前平衡假设”记录

验收标准：

1. 玩家不会在前 2-3 分钟频繁陷入无弹可打。
2. 不同武器在至少一种场景下各有优势。
3. 无尽模式前期不会过慢，中期不会突然断崖。

验证方式：

1. `npm run typecheck`
2. 手动记录：
   - `level_1` 首通时间
   - `level_2` 首次 Boss 波所需资源
   - 无尽模式前 10 波平均生存时间

#### M1-T05 回归清单与构建门槛

目标：

- 给后续大改建立最低质量护栏。

建议修改范围：

- 新增 `docs/execution/M1_Checklist.md`
- 必要时调整 `package.json`

实施步骤：

1. 建立一份固定回归清单，至少覆盖：
   - 启动
   - 关卡模式
   - 无尽模式
   - 改键
   - 暂停
   - 结算
2. 约定每次大改后的最低验证命令：
   - `npm run typecheck`
   - 浏览器手动验收
3. 若用户认可，再把 `npm run build` 作为 M1 尾声的里程碑级检查项。

交付物：

1. 固定回归清单
2. 固定里程碑验证规则

验收标准：

1. 后续每轮大改都有同一套基础回归方式。
2. 不再靠记忆式人工想到哪测到哪。

验证方式：

1. 文档自检
2. `npm run typecheck`

## 5.2 M2 垂直切片

### 目标

做出一个“可以代表最终成品方向”的高质量小版本。

### 本阶段完成定义

满足以下全部条件，M2 才算完成：

1. 至少 1-2 个关卡达到接近正式品质的视觉与玩法完成度。
2. 玩家、基础僵尸、关键场景物、核心 HUD 不再主要依赖几何占位。
3. 有一场 Boss 战在视觉、技能、节奏上都能代表项目特色。
4. 菜单、关卡开始、战斗、结算形成统一风格，不再像不同阶段拼接的页面。

### 不做项

本阶段不做：

1. 大规模扩到 5-8 关
2. 在线服务系统
3. 联机玩法

### 任务清单

#### M2-T01 正式视觉基线建立

目标：

- 用少量但高频的正式资产替换占位图形，建立统一视觉语言。

建议修改范围：

- `src/assets/`
- [Player.ts](/E:/github/ExterminateZombies/src/entities/Player.ts)
- [Zombie.ts](/E:/github/ExterminateZombies/src/entities/Zombie.ts)
- [Prop.ts](/E:/github/ExterminateZombies/src/entities/Prop.ts)
- [Pickup.ts](/E:/github/ExterminateZombies/src/entities/Pickup.ts)
- [HUDScene.ts](/E:/github/ExterminateZombies/src/scenes/HUDScene.ts)

实施步骤：

1. 先替换高频资产：
   - 玩家
   - `walker`
   - 油桶/面粉桶
   - 核心拾取物
2. 统一描边、阴影、色板和字体规则。
3. 确定菜单海报与 HUD 主视觉样式。

交付物：

1. 一套固定视觉基线
2. 高频对象的正式表现

验收标准：

1. 玩家 10 秒内能感知“统一像素风”而不是“占位开发版”。
2. 新旧素材混搭不会明显撕裂。

#### M2-T02 代表关卡重做

目标：

- 选 1-2 个关卡打磨到代表最终质量的程度。

建议修改范围：

- [levels.ts](/E:/github/ExterminateZombies/src/config/levels.ts)
- [GameScene.ts](/E:/github/ExterminateZombies/src/scenes/GameScene.ts)
- 相关场景与资产文件

实施步骤：

1. 选定 `level_1` 作为教学型关卡，`level_2` 或 `level_3` 作为高压型关卡。
2. 重做场景物布局和波次节奏。
3. 加入更清晰的开局引导和关卡节奏变化。

交付物：

1. 一关“教学型”代表关卡
2. 一关“高压型”代表关卡

验收标准：

1. 两关的体验记忆点明显不同。
2. 玩家打完后能描述出各自特点。

#### M2-T03 Boss 战垂直切片

目标：

- 把一场 Boss 战打磨到能当项目宣传重点的程度。

建议修改范围：

验收标准：

## 6. 中远期里程碑（保持里程碑级，不做伪精确拆解）

## 6.1 M3 内容扩展

目标：

1. 关卡扩到 5-8 个
2. 敌人扩到 6-10 类
3. 武器扩到 6 把以上
4. 无尽模式加入事件、精英波、小 Boss

完成标准：

1. 不再依赖单一武器或单一敌人池撑完整游戏。
2. 不同关卡之间具备明显内容差异。

## 6.2 M4 公开试玩准备

目标：

1. 建立试玩包
2. 补试玩说明
3. 补反馈入口
4. 修正首次体验中最明显的问题

完成标准：

1. 外部试玩者可独立完成一局。
2. 外部反馈开始聚焦于平衡和偏好，而不是理解障碍。

## 6.3 M5 发布候选

目标：

1. 完成首个正式发布候选版本
2. 固定质量清单
3. 清理主要粗糙项

完成标准：

1. 形成完整小型作品，而不是若干 Demo 拼接。

## 7. 当前建议执行顺序

如果现在继续开发，建议严格按以下顺序进入：

1. 做 `M1-T01 Boss 机制化`
2. 做 `M1-T02 音效骨架接入`
3. 做 `M1-T03 战斗 UX 校正`
4. 做 `M1-T04 第一轮数值平衡`
5. 做 `M1-T05 回归清单与构建门槛`
6. M1 通过后，再进入 M2

不要跳过 M1 直接做正式美术，因为：

1. 手感和节奏不稳定时，正式资产很容易浪费。
2. Boss 和数值逻辑没定，后面视觉资源会反复返工。

---

## 8. 每次迭代必须更新什么

每完成一个里程碑或一个大任务，必须更新：

1. 当前执行文档
2. 本路线图中的状态
3. 当前剩余风险
4. 当前已知不做项

如果路线图被新需求打断，必须先判断：

1. 该需求属于哪个里程碑
2. 它会不会改变当前优先级
3. 它是否值得提前

如果回答不清楚，就不要开做。
