# 战前整备、弹药经济与军械可见性设计

> 文档状态：已确认 v1.0，主实现与 V0-V5 客观验收已完成；V6 真人验收待回填
> 确认日期：2026-08-14
> 对应决策：`PROJECT_MASTER_PLAN.md` D-010
> 对应 Goal：G2-8（弹药与战前整备）、G4-7（战场军械带）
> 设计原则：弹药压力用于推动切枪和临场决策，不能让玩家因掉落类型错误而被迫只用无限弹手枪

---

## 1. 目标

本方案同时解决四个已经从当前实现和试玩反馈中确认的问题：

1. 每关固定从沙漠之鹰重新开始，重复消耗低强度开局时间。
2. 弹药类型与感染体掉落表静态绑定，关卡敌群偏向某些类型时会持续掉落与当前军械无关的弹药。
3. 高敌人数关卡的弹药压力主要由随机掉落决定，可能出现有多把武器却没有可持续使用武器的负反馈。
4. HUD 只展示当前武器，玩家不能在战斗中快速判断自己拥有哪些武器、哪一把还能开火。

目标体验：

- 第二关起，玩家可以直接用已解锁的偏好主武器进入战斗。
- 有限弹药始终有压力，但补给必须与当前已持有武器相关。
- 当前武器打空后，玩家在 0.5 秒内能看出还有哪些武器可用。
- 弹药不足推动切枪、拾取和风险决策，而不是迫使玩家长期退回无限弹手枪。

## 2. 范围与不做项

### 2.1 本方案范围

1. 武器许可解锁与战前主武器选择。
2. 四类现有弹药的自适应掉落规则。
3. 低弹药保底和高库存抑制规则。
4. 新武器、重复武器与阶段奖励的弹药语义。
5. HUD 军械带、武器可用状态和切枪行为。
6. 固定关卡与无尽模式的统一补给口径。
7. 存档迁移、配置校验和验证指标。

### 2.2 本轮不做

1. 不新增第五种弹药，不把四类弹药拆成八把武器各自独立的备用弹池。
2. 不增加永久伤害、生命或射速成长。
3. 不重做八把武器的伤害和射速数值。
4. 不引入商店、货币、背包重量或局外刷材料系统。
5. 不强制限制玩家最多持有四把武器；当前最多八把的局内持有能力继续保留。
6. 不在弹药经济稳定前实施重复武器的临时超载效果。

## 3. 当前实现事实与根因

### 3.1 已确认事实

1. `createInitialState()` 默认只把 `pistol` 写入 `ownedWeapons`，四类备用弹全部从 0 开始。
2. 沙漠之鹰使用轻型弹药配置，但 `infiniteAmmo:true`，实际换弹不消耗轻型备用弹。
3. 备用弹当前按 `light / heavy / shell / explosive` 四类共享，而不是按武器分别存储。
4. 普通感染体中有 7 类固定掉轻型弹药，只有 3 类掉重型弹药、2 类掉霰弹、2 类掉爆炸弹药；关卡敌群结构会直接决定补给结构。
5. 武器与弹药来源有错配：例如血污屠夫掉落 AK-47，却固定掉霰弹；毁灭爆破者掉落 SPAS-12，却固定掉爆炸弹药。
6. 拾取新武器只获得一个满弹匣，不附带备用弹；重复拾取同一武器才增加一个弹匣量的备用弹。
7. 第二关通过阶段奖励定向发放 MP5、SPAS-12、M4A1 和对应弹药，但其它关卡仍主要依赖随机掉落。
8. HUD 只展示当前武器的弹匣和其弹药类型的共享备用量；`ownedWeapons` 中其它武器的可用状态不可见。
9. 鼠标滚轮会遍历全部已持有武器，不会跳过弹匣与备用弹均为 0 的武器。

### 3.2 根因判断

问题不应通过单纯提高所有弹药掉率解决。当前主要矛盾是“掉落内容由敌人类型决定”，而不是“由玩家当前军械和缺口决定”。继续提高固定掉率只会制造更多无效轻型弹药，并让地面拾取物数量膨胀。

## 4. 已确认的核心机制

### 4.1 军械许可与战前整备

1. 第一关保留教学例外：以沙漠之鹰开始，并在设计固定节点提供首把有限弹药武器，避免新玩家一开始面对完整军械选择。
2. 第二关起，玩家可从已解锁武器中选择一把主武器；沙漠之鹰继续作为无限备用弹的保底副武器。
3. 武器首次在战场拾取后永久解锁“军械许可”。许可只增加后续关卡的开局选择，不增加武器基础属性。
4. 所选主武器入场时获得一个满弹匣和一个弹匣量的备用弹，确保它可以立刻形成战斗节奏，但仍需要后续补给。
5. 记录玩家上一次选择的主武器；下一关默认选中它，但不会未经确认自动开始。
6. 新存档仍只解锁沙漠之鹰；第一关的固定武器教学负责建立第一个可选主武器。

### 4.2 自适应弹药补给

### 基本规则

1. 保留 `light / heavy / shell / explosive` 四类弹药和当前共享备用弹模型。
2. 感染体配置只负责决定“是否触发一次弹药补给”，不再为常规随机补给固定最终弹药类型。
3. 补给生成时只考虑玩家已经持有、且不是无限弹药的武器所使用的弹药类型。
4. 不为尚未持有的武器掉落弹药；玩家只有沙漠之鹰时暂停常规弹药掉落，避免制造看似有用、实际暂时无法消费的拾取物。
5. 固定关卡的剧本奖励可以继续显式指定武器和弹药，用于教学、阶段收束和 Boss 前整备；它不参与随机自适应算法。

### 缺口计算

每种候选弹药计算一个缺口分数：

```text
当前库存 = 该类型共享备用弹 + 所有已持有同类武器的弹匣余量
目标库存 = 已持有同类武器中的最大弹匣容量 × 目标弹匣数
缺口比例 = clamp(1 - 当前库存 / 目标库存, 0, 1)
```

约束：

1. 初始目标弹匣数统一取 2，后续只能根据完整试玩记录调整。
2. 当前武器对应弹药不足一个弹匣时，其缺口权重乘以 1.5。
3. 按缺口权重选择最终弹药类型；不是永远只补当前武器，避免其它武器长期饿死。
4. 所有候选类型都达到目标库存时，本次随机弹药掉落被抑制，不生成无意义补给。

### 初始单次补给量

| 弹药类型 | 单次补给 | 设计理由 |
| --- | ---: | --- |
| 轻型 | 30 | MP5 高射速，约为基础弹匣的 60% |
| 重型 | 12 | 同时服务 M4A1、AK-47、Barrett，避免一次补给让 Barrett 获得过多弹匣 |
| 霰弹 | 6 | 等于 SPAS-12 一个基础弹匣，支持逐发装填决策 |
| 爆炸 | 2 | 足够形成一次清场机会，但不能连续无成本轰炸 |

这些数值是实施首版参数，不是最终平衡结论。

### 4.3 低弹药保底与高库存抑制

1. 玩家持有有限弹药武器，且所有有限弹药武器都无法开火或换弹时，下一次符合条件的击杀必定触发相关弹药补给。
2. 所有有限弹药武器的合计库存低于各自一个弹匣目标时，随机弹药触发权重翻倍。
3. 低弹状态连续 10 次符合条件的击杀没有获得弹药时，第 11 次强制触发，随后重置计数。
4. 所有已持有有限弹药类型都达到两弹匣目标时，随机弹药触发概率降低 70%。
5. 保底只保证“有武器能继续打”，不保证当前最强武器永远有弹。
6. 状态计算必须是纯逻辑规则，并提供固定随机种子或可注入随机函数，保证测试可复现。

### 4.4 武器拾取与阶段补给

1. 首次拾取武器：武器满弹匣，并追加一个基础弹匣量的备用弹，同时写入永久军械许可。
2. 重复拾取武器：为该武器所属弹药池追加一个基础弹匣量的备用弹，不强制切换当前武器。
3. 第二关现有阶段奖励继续保留确定性，但奖励量需要按本方案统一为“满弹匣 + 明确备用量”，不能同时叠加随机武器掉落绕过节奏。
4. Boss 前的固定补给只补当前武器和最缺弹药类型，不把全部武器一次补满。
5. “重复武器触发 8-12 秒专属超载”保留为后续爽感扩展，必须在基础弹药经济通过 V5/V6 后单独实施，避免补给和平衡同时变化。

### 4.5 战场军械带

### 位置与结构

1. 军械带固定附着在左上状态板下方，与当前武器、弹药和生命信息保持同一视线区域。
2. 使用现有左上面板的 472px 宽度，内部采用 4 列 × 2 行固定槽位，最多展示 8 把已持有武器。
3. 每个槽位使用稳定尺寸，不因武器名、弹药数、选中或空弹状态改变布局。
4. 中央战场、底部操作提示、右上关卡信息和顶部 Boss 区域不被军械带占用。
5. 复用现有八把处理后武器贴图作为识别主体，不用纯文本列表代替武器视觉。

### 每个槽位显示

1. 武器小图。
2. 固定槽位序号；前四槽对应现有数字键 1-4，其余武器继续通过滚轮访问。
3. `弹匣 / 备用`；无限备用弹显示 `∞`。
4. 当前武器、可用武器、空弹武器三种明确状态。

### 状态规则

```text
可用 = infiniteAmmo || ammoInMag > 0 || 对应 ammoReserve > 0
```

1. 当前武器：高对比描边和底部强调线，不改变槽位尺寸。
2. 非当前但可用：正常亮度，弹药数字清晰可读。
3. 空弹：降低整体亮度，弹药数字使用危险色；武器仍保留在军械带中，不能直接隐藏，否则玩家会误以为武器丢失。
4. 换弹中：在当前槽位显示短进度条，不重复显示大段说明文字。
5. 弹药拾取使空弹武器重新可用时，对对应槽位做一次短促高亮。
6. 当前武器彻底打空时，只高亮可用替代武器，不自动替玩家切枪。

### 切枪规则

1. 鼠标滚轮默认跳过弹匣和备用弹均为 0 的有限弹药武器。
2. 数字键选择空弹武器时不切换，并复用现有空弹警报提示原因。
3. 如果除沙漠之鹰外没有可用武器，滚轮直接回到沙漠之鹰，避免在多个空仓武器间循环。
4. 武器槽位顺序在单局内固定，拾取新武器只追加到末尾，禁止因弹药变化重新排序。

## 5. 完整玩家流程

1. 玩家首次进入第一关，以沙漠之鹰完成基础射击教学。
2. 关卡固定节点发放第一把有限弹药武器，同时提供满弹匣和一个备用弹匣，并永久解锁许可。
3. 第二关开始前，玩家在关卡简报区域选择已解锁主武器。
4. 战斗中，军械带持续展示全部已持有武器及其真实弹药状态。
5. 常规感染体只触发通用补给机会，实际弹药类型由当前军械缺口决定。
6. 当前武器打空时，军械带高亮可用替代武器；玩家主动切换继续输出。
7. 首次拾取新武器会解锁后续开局选择；重复拾取则补充对应弹药。
8. 结算战报记录各武器使用占比、空弹次数和补给结构，为下一轮平衡提供依据。

## 6. 数据与调用链设计

以下字段名属于已确认的实施设计，不代表当前代码已经存在；编码前仍需在执行文档中冻结最终类型。

### 6.1 配置与状态

1. `DropDef` 增加明确的固定/自适应弹药模式，禁止继续用“缺少 ammoType”隐式猜测语义。
2. 新增纯配置入口保存四类补给量、目标弹匣数、低弹阈值和保底击杀数。
3. `GameState` 增加本局弹药保底计数和补给统计；现有四类 `ammoReserve` 结构保持不变。
4. `SaveManager` 增加已解锁武器许可与上次主武器选择，并升级存档版本、补齐旧存档迁移。
5. 关卡配置增加明确的开局策略：第一关使用教学配发，其余关卡使用战前选择。

### 6.2 系统边界

1. 新建纯逻辑 `AmmoSupplyRules`，负责候选类型、缺口权重、保底与抑制，不直接创建 Phaser 对象。
2. `GameScene.spawnDrops()` 只负责把掉落结果实例化，不继续承载弹药决策细节。
3. `WeaponManager` 继续负责弹匣、备用弹、拾取和切枪，但增加统一的“武器是否可用”查询供 HUD 与输入共用。
4. `HUDScene` 只消费已确认的武器可用状态和真实弹药，不自行复制判断规则。
5. 战前主武器选择优先整合进现有关卡简报区域，不新增独立场景，避免一次选择增加额外场景跳转。

### 6.3 统计项

战报和调试记录至少增加：

1. 四类弹药实际掉落次数与数量。
2. 自适应补给命中的目标弹药类型。
3. 低弹保底触发次数。
4. 每把武器空弹次数和可用时长。
5. 有限弹药武器全部不可用的累计时长。
6. 每把武器使用占比。

## 7. 实施步骤与优先级

### P0：先完成当前基线验证

在本方案开始编码前，先按 `HANDOVER.md` 收口最新武器、音频、M79 与构建验证，避免把既有回归混入弹药改造。

### P1：补给正确性

1. 建立自适应弹药纯规则和配置校验。
2. 把常规感染体固定弹药掉落迁移为通用补给触发。
3. 接入低弹保底、高库存抑制和首次武器备用弹。
4. 保留第二关剧本奖励，并明确区分固定补给与随机补给。

### P2：战场军械可见性

1. 增加固定 4×2 军械带。
2. 接入当前、可用、空弹、换弹和重新激活状态。
3. 修改滚轮循环和数字键空弹反馈。
4. 完成 `1280 × 720`、1×/2× 渲染和最长武器名/最大弹药数布局验收。

### P3：战前整备

1. 增加武器许可存档与迁移。
2. 在关卡简报中加入主武器选择。
3. 第一关接入固定教学武器节点。
4. 第二关起使用“主武器 + 沙漠之鹰”开局。

### P4：爽感扩展

在 P1-P3 完成完整试玩后，再单独评估重复武器超载；不得与基础补给规则同批上线。

## 8. 实施建议

1. 先建立纯函数和统计，再修改掉率；没有统计就无法判断“弹药仍不够”是数量问题还是类型问题。
2. 自适应算法只读取已持有武器和真实弹药，不读取未来波次或暗改武器伤害。
3. 固定剧情奖励保持可预测，自适应补给只负责填补随机经济。
4. HUD 军械带与切枪必须读取同一个可用性函数，避免画面显示可用但输入跳过，或画面显示空弹却仍能换弹。
5. 第一版只调整弹药类型选择和保底，不同时改武器伤害、敌人生命和波次数量。
6. 所有概率验证使用固定随机源，失败样本需要保留首次结果，禁止靠重复运行直到通过。

## 9. 潜在风险与优化方案

| 风险 | 影响 | 优化方案 |
| --- | --- | --- |
| 自适应掉落过于明显 | 玩家感觉系统在暗中放水 | 使用加权随机而非永远补当前武器；只在全空和连续低弹时硬保底 |
| 弹药过多 | 切枪和掉落失去意义 | 两弹匣目标以上抑制 70%，并以战报库存曲线调整单次补给量 |
| 重型弹药共享失衡 | Barrett 可能从为自动步枪准备的补给中获得过多射击次数 | 首版把重型单次补给压到 12；若完整试玩仍失衡，再单独评估重型弹药子类型或武器弹药消耗倍率 |
| 军械带遮挡战场 | 高密度战斗可视面积下降 | 固定附着左上已有信息区，使用 4×2 紧凑槽位，不占中央和底部 |
| 只显示可用武器造成误解 | 玩家以为空弹武器被丢弃 | 展示全部已持有武器，空弹只降级显示，不隐藏 |
| 自动切枪夺走控制 | 玩家在高压时被切到不想用的武器 | 只提示和高亮，不自动切换 |
| 存档字段变化 | 旧存档读取失败或许可丢失 | 提升存档版本，缺失字段使用明确默认值并增加迁移测试 |
| 第二关剧本奖励与随机补给叠加 | 切片弹药显著过量 | 固定奖励不参与随机保底计数，逐段统计后单独校准 |

## 10. 验证方式

### V0 静态审阅

1. `AmmoType`、武器配置、掉落配置、状态、拾取、HUD 和存档调用链一致。
2. 所有常规弹药触发都有明确模式，不允许继续依赖可选字段猜测。
3. HUD 与输入使用同一武器可用性规则。

### V1 自动化

1. 只有沙漠之鹰时不生成无效随机弹药。
2. 只持有 SPAS-12 时不会选择轻型、重型或爆炸弹药。
3. 同时持有多种武器时，低库存类型获得更高权重。
4. 全部有限武器空弹时下一次符合条件击杀触发保底。
5. 连续 10 次低弹未掉落后，第 11 次强制触发。
6. 高库存抑制、固定奖励豁免和随机源可复现。
7. 旧存档迁移后至少保留沙漠之鹰许可，非法许可 ID 被过滤。
8. 滚轮跳过空弹武器，仍能稳定回到沙漠之鹰。

### V2 工程门槛

按 `TESTING_RULES.md` 的授权门禁执行类型检查和必要构建，重点覆盖 `DropDef`、存档和输入契约变化。

### V3/V4 浏览器实景

1. 军械带在 `1280 × 720`、1×/2× 渲染下无溢出、遮挡和跳位。
2. 依次验证 1、4、5、8 把已持有武器时的两行布局。
3. 开火、换弹、打空、拾取、切枪后槽位状态与真实弹药同步。
4. 当前武器打空后，可用替代武器在 0.5 秒内可识别，滚轮不会停在空弹武器。

### V5 完整试玩

1. 第一关完整教学流程。
2. 第二关三阶段与 Boss 完整流程。
3. 至少一局无尽模式推进到首个 Boss。
4. 记录每类弹药掉落、全部有限武器空弹时长、各武器使用占比和保底触发次数。

### V6 真人验收

1. 弹药是否仍有压力，但不再频繁被迫长期使用手枪。
2. 玩家是否会因为补给和可见性主动切枪。
3. 军械带是否能在高压战斗中一眼读懂，而不会造成视觉负担。
4. 战前主武器是否减少重复开局疲劳，同时保留局内获得新武器的兴奋感。

## 11. 完成标准

1. 随机弹药只会分配给当前已持有的有限弹药武器类型。
2. 有有限弹药武器时，全部有限武器不可用的连续时间不超过 10 秒或 10 次有效击杀，以先达到者为准。
3. 完整第二关样本中，至少两把有限弹药武器在 70% 以上的战斗时段可供切换。
4. 玩家能从 HUD 同时识别全部已持有武器、当前武器和空弹武器。
5. 第二关起可以选择已解锁主武器，沙漠之鹰继续承担保底而不是默认主输出。
6. 自动化、类型、浏览器客观验证完成；弹药压力与爽感最终结论由 V6 真人验收给出。
