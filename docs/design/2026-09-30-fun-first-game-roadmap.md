# 消灭僵尸：爽感优先游戏规划

> 版本：v0.1 设计草案
> 日期：2026-09-30
> 当前代码参考：`3f0e70e`
> 本次交付：游戏设计与分阶段推进规划，不包含业务实现。
> 决策边界：爽感优先已是项目既有方向；本文件中的新增玩法、数值与模式规则均为建议，不能因文档落盘就视为已批准、已实现或已验证。

## 1. 一页结论

> 2026-09-30 后续决策：用户已批准优先实现狂潮挑战「限时猎杀 + 火力掠夺 + 首领斩杀」。本文原第 8/9 章立项条件和排序保留为历史建议，新模式以[首版执行方案](../execution/2026-09-30-frenzy-challenge.md)及总纲 D-011 为准；其余建议未自动获批。

**把游戏做成主动操作驱动的高密度爽射：让玩家用走位、聚怪和射击创造爆发，而不是始终绕圈磨血，也不是全程自动清屏。**

两种现有模式承担不同体验：

| 模式 | 玩家来这里获得什么 | 核心设计方向 |
| --- | --- | --- |
| 关卡模式 | 亲手打出可以复述的战斗名场面 | 有意编排的压力、环境机会、反击与首领收束 |
| 无尽模式 | 让这局构筑越来越强，挑战自己的极限 | 稳定获得成长方向、连杀爆发、章节变化与可兑现的阶段成果 |
| 狂潮挑战，候选新模式 | 开局就火力成型，痛快打几分钟 | 3～5 分钟短局、连续战斗、个人得分挑战；暂不作为第三条独立产品线 |

**推荐顺序：现有问题复验 → 第二关爽感样板 → P2 真人门槛 → 无尽与构筑深化 → 评估狂潮挑战 → 内容生产和公开试玩。**

第一批不增加武器数量、地图数量或永久养成，只回答一个问题：

> 玩家能不能通过一次主动选择，把正在逼近自己的尸潮变成一场值得重开的清场？

### 2.3 当前最需要验证的设计判断

目前不应武断地说游戏“不好玩”。更准确的问题是：

1. 现有系统是否在同一段战斗中形成了足够强的协同？
2. 玩家能否主动制造高潮，还是只能等待随机掉落和偶然连锁？
3. 强化之后是否明显改变开火方式、站位或目标选择？
4. 爽点之间有没有追尾怪、等刷新、弹药断档等不必要空窗？

这些问题需要真实操作和真人反馈回答，不能从配置数量推导结论。

## 3. 体验目标与设计红线

### 3.1 核心循环

```text
敌群形成压力
    ↓
玩家识别路线、目标与环境机会
    ↓
通过走位、聚怪、集火或反打制造优势
    ↓
连续击杀，获得技能或火力爆发
    ↓
主动向前清场，兑现构筑
    ↓
短暂整理，接入更有变化的下一轮压力
```

希望玩家从“又来一群，我该往哪逃”逐渐转变为“再来一群，正好试试我的这套打法”。但仍须保留威胁、选择和失误代价。

### 3.2 三个必须能被记住的体验

1. **一枪改变局面**：轰开缺口、贯穿一列、引爆一片，结果在战场上清楚可见。
2. **我的操作创造机会**：聚怪、骗招、反打和利用地形，比原地持续开火更有回报。
3. **这局有自己的打法**：中段已经能用一句话描述构筑，不只是“伤害比刚才高”。

### 3.3 不做什么

- 不通过所有敌人一起加血来制造后期难度。
- 不把每次击杀都做成震屏、慢动作和中央大字。
- 不让自动连锁无限触发自身，形成无法理解的清屏循环。
- 不用日常任务、复杂装备品质或永久数值养成替代战斗本身。
- 不为新模式先投入专属地图、整套美术、联机或在线排行榜。
- 不因玩家变强就立即等比例增强所有敌人，抹掉成长兑现。
- 不在 P2 门槛未过时继续批量扩关。

## 4. 核心战斗改造

### 4.1 敌群分工：杂兵提供收割，特殊敌人提供选择

首轮可用约 **75% 杂兵、20% 战术敌人、5% 精英**作为普通战斗段的配比起点。比例按该段生成数量理解，不适用于 Boss 段，也不是最终配置。

| 类别 | 体验职责 | 设计约束 |
| --- | --- | --- |
| 杂兵 | 形成可穿透、扫射和爆炸收割的群体 | 不靠高血量拖时间；威胁主要来自密度、接近和占位 |
| 战术敌人 | 迫使玩家换站位、换优先级或利用环境 | 同一时刻少量明确职责，避免多个远程威胁同时淹没信息 |
| 精英 | 在短时间内改变局势 | 有清楚动作与弱点，不能每只都是只会追人的血包 |
| Boss | 检验玩家操作和本局成长 | 压力与可争取的输出窗口交替，不能全程磨血 |

优先调整敌群组合、出生方向和段落间隔，**不先提高同屏硬上限**。新敌人从可识别的边界进入，禁止贴脸凭空生成。

### 4.2 连续战斗：消除无意义空窗，保留必要喘息

- 大部分敌人已被清除时，可以提前预告或准备下一段，但必须遵守原有阶段奖励、存活上限和清关条件。
- 不直接把剩余敌人删除，也不在未清完时重复发放阶段奖励。
- 对卡在远处或遮挡后的尾怪，优先改善路径、目标提示和出生布局，而不是让玩家无目的找怪。
- 整理窗口要有用途：补给、换位、选强化、观察下一段；避免单纯站着等倒计时。
- 每轮小循环可先观察 20～40 秒的压力与释放节奏；整关时长依据现有三阶段加 Boss 的实测，不强行统一到一个数字。

### 4.3 关卡连杀：更多主动操作，而不是无限增伤

保留已有冷却返还方向。先验证返还后是否能在有意义的时机再次使用技能，再决定是否调整数值。

约束：返还不能超过技能当前剩余冷却；不能形成没有空档的无敌或位移循环；暂停、抽卡和进入下一关不额外产生充能。

### 4.4 无尽过载：临时无限弹匣体验，作为候选增强

**建议试验，不是已确认功能：**在现有过载框架中加入短时弹匣免消耗，先只在过载 II/III 验证，过载 I 保留当前较轻的奖励。

候选原型规则：

1. 达到对应里程碑后，沿用当前过载档位、伤害倍率与时长，不再加第二条进度槽。
2. 启动免耗弹效果时，补满当前有限弹药武器的弹匣，不增加备用弹；该武器正在换弹时必须正确结束原换弹状态，不能留下重复回调。
3. 持续期间有限武器开火不扣弹匣；仍保留各武器射速、蓄力、散布、攻击方式和冷却约束。
4. 切换武器不额外补满新武器、不重置过载时长；空弹匣武器仍按正常规则准备开火。
5. 同一连杀里程碑只触发一次；活跃过载不因低档重复触发而无限刷新；高档覆盖而非倍率叠乘，剩余时间不得超过既有最高档时长。
6. 结束后恢复正常耗弹，不追加一轮补给；暂停冻结，死亡、退出和模式切换清理状态。
7. 无限弹手枪不获得额外弹药奖励；关卡模式不继承这项无尽效果。

第一轮只验证这个体验包，不同时增加射速翻倍、无限道具和无限技能。如果爆发很难出现，先检查敌群密度、成长速度和断连原因，不能只提高伤害掩盖问题。

### 4.5 反馈：让空间结果比数字更抢眼

| 行为 | 应突出的结果 | 应限制的干扰 |
| --- | --- | --- |
| 霰弹近距命中 | 前排明显受压，形成可以继续推进的缺口 | 每颗弹丸都独立强震屏 |
| 穿透射击 | 连续命中顺序与倒下的线路可读 | 巨大数字遮住后排目标 |
| 爆炸连锁 | 爆炸沿战场传播，最后留下明确安全区域 | 同帧堆满闪光，无法辨别危险边缘 |
| 精彩反打 | 来袭变返弹、命中源目标、弱点窗口三个阶段清楚 | 只有文字播报，没有弹体/目标反馈 |
| 大清场与 Boss 终结 | 短暂、明显、有收尾的高潮 | 连续慢放使玩家失去操作节奏 |

现有震动、闪光、血液和慢动作设置继续生效。弱化效果不能改变命中、伤害、掉落或判定；对象池容量不足时先降低装饰性表现，不吞掉关键危险预警。

## 5. 构筑规划：少数流派，尽早成形

### 5.1 成长节奏

- 前两次成长应让玩家看出可继续追求的方向。
- 中段至少有一次明显改变攻击方式或目标选择的质变。
- 后续成长主要强化这条打法，或提供解决其短板的工具。
- 先整理现有强化的组织和出现机会，不以新增卡牌数量作为交付指标。

### 5.2 第一批聚焦三个方向

| 方向 | 玩家体验 | 复用基础 | 候选新增或需要深化的部分 |
| --- | --- | --- | --- |
| 霰弹冲阵 | 贴近、轰开缺口、继续顶上去 | 霰弹武器、近距反馈、角色技能 | 击杀续航与风险回报，具体补弹/充能方式需试验，不能一开始全给 |
| 电链风暴 | 聚怪后一次放电贯穿群体 | 电弧、链式闪电、现有终点爆炸强化 | 提高构筑可获得性，限制重复链式触发和无目标视觉噪声 |
| 爆破工程 | 布置与引导，让一次引爆改变战场 | 广播、油桶、爆炸武器、危墙 | 让机会布局与流派成长配套，而不是额外造一套布防系统 |

保留现有六槽整备和必带手枪规则。主武器承担构筑身份，其他武器作为工具和补充；不要求玩家为了有效成长不断更换所有武器。

### 5.3 强化选择规则

- 优先保证选项中存在可作用于当前编队的有效方向，但不每次强制送同一张核心卡。
- 已成型流派可以继续强化，也应偶尔出现补足短板的选择；避免纯粹用概率制造长时间“没抽到就没法玩”。
- 维持已有互斥、上限和满编队许可规则，不把解锁许可误报为当局获得武器。
- 卡面说明优先回答“下一场战斗能怎么打”，数值变化作为支持，不作为唯一卖点。
- 确认现有暂停抽卡体验是否过于频繁后，再讨论节奏调整；本轮不擅自改成边战斗边选卡。

## 6. 关卡模式：每关一个招牌名场面

### 6.1 第二关作为第一张品质样板

主题集中在 **广播聚怪与环境连锁**，不要求第二关展示所有新机制。

| 段落 | 玩家状态与行动 | 导演设计重点 | 验证重点 |
| --- | --- | --- | --- |
| 入场 | 学会处理基础追击和少量战术威胁 | 清楚的射线与第一轮连续击杀机会 | 不需要先读大段规则也能开始战斗 |
| 蓄压 | 敌群占据空间，玩家开始考虑位置 | 广播与爆炸走廊可见，但仍有其他可行路线 | 压力可理解，不靠贴身刷怪逼迫操作 |
| 主动破局 | 玩家选择启动广播、引导敌群、找引爆时机 | 保证机会存在，不自动替玩家引爆 | 同一次玩家选择带来清楚可见的战场变化 |
| 收割兑现 | 连杀返还技能，玩家能够向前清场 | 接上适量可处理目标，让优势有用武之地 | 不在刚拿到奖励时进入长空窗 |
| 首领收束 | 运用走位与输出窗口完成一局 | 展示首领职责，不重复拖长血条 | 完整流程可独立完成，奖励与结算准确 |

安全约束：至少保留一条可读的撤离路线；广播使用有反应窗口；未用好环境不应立即宣告整局失败；失败后能说清是哪次判断出了问题。

### 6.2 第二关样板完成后，再深化第三关

第三关突出 **危墙改变路线与炮弹反打**：

- 开始时墙体限制射线与通路，中段通过玩家主动破坏改变战场。
- 炮弹是危险，也是可以争取的反击资源；不能把反打做成必须查攻略才能发现的隐藏机制。
- 来袭、击返、源 Boss 弱点窗口必须有可识别的反馈。
- 先完成现有射程、贴身、同帧命中、源 Boss 生命周期和红圈边界验证，再把它升级为关卡核心记忆点。

其他关卡暂不一起重做。样板获得真人认可后，再将“主题—机会—压力—收束”的模板用于后续内容批次。

## 7. 无尽模式：构筑兑现，而非血量耐力赛

### 7.1 保留十波章节结构，强化每章任务

| 章节位置 | 主要任务 | 不应出现的体验 |
| --- | --- | --- |
| 章初 | 建立或补强当前流派，让玩家知道接下来追求什么 | 长时间用弱配置等待第一张有意义的卡 |
| 章中 | 给构筑一个大显身手的敌群，再加入少量针对性威胁 | 所有波次都是同一组敌人按数量放大 |
| 高潮段 | 让连杀与过载形成短暂主动压制 | 玩家刚爆发就被无提示强制打断 |
| 章节 Boss | 检验输出方式、站位和关键资源使用 | 玩家已经成型，但所有伤害都像没有变化 |
| 章间 | 看清成长结果，决定是否承受下一章压力 | 没有阶段成果，只能一直打到死亡 |

后期难度优先增加组合变化、进攻角度与行动要求；血量和伤害缩放仍可存在，但不能成为唯一变化。

### 7.2 候选规则：章节结算与继续挑战

章节 Boss 完成且当前奖励处理结束后，提供继续挑战或结束本局的清晰入口。

- 主动结束记录本局真实分数与已完成波次，不视为关卡通关，不解锁固定关卡内容。
- 不新增货币、装备掉落或永久数值奖励。
- 不在战斗、抽卡或未交付奖励时触发结算，避免重复领奖。
- 继续挑战沿用当前局内构筑；结束后按既有局内资源规则清理。
- 新增纪录维度前先明确与现有最佳波次的关系，不能静默覆盖旧存档。

这项功能的目的，是让玩家可以带着满足感结束一局，而不是让无尽必须以疲劳或死亡收尾。

## 8. 候选新模式：狂潮挑战

### 8.1 定位

**“我现在只想痛快打几分钟。”** 原型时长建议 3～5 分钟，先固定一个配置，不立即增加模式选择菜单和专属内容库。

### 8.2 最小规则

- 开局使用固定、已成型的武器与强化预设；不修改玩家长期许可和已保存编队。
- 局内不频繁暂停抽卡，保留移动、瞄准、切枪、技能和环境利用。
- 主要敌人为可快速处理的杂兵，加入少量明确职责的特殊目标。
- 连杀驱动爆发，挑战价值来自更好的走位、目标选择和清场效率。
- 到时或死亡即结算；个人成绩按挑战配置版本区分，避免规则变化后旧纪录失去可比性。
- 首版只做本地个人纪录，不接账号、网络排行榜或反作弊服务。

计分原则：同一次死亡只计一次；只对真实清场与完成的目标计分；不能通过无限召唤、反复停留或重复结算刷分。详细计分公式在模式获准进入原型时另行冻结。

### 8.3 立项条件

只有同时满足以下条件才进入实现：

1. P2 与核心战斗已有真人反馈支持，现有模式不会因为新模式被搁置。
2. 无尽的连杀爆发和流派玩法已可稳定复现。
3. 短时预设挑战确实提供不同体验，而不是把无尽截短并换一个名字。
4. 现有资源可承载原型，不需要先生产新地图或大量美术。

若条件未满足，将此模式保留为内部试验方案，不作为近期必交付项。

## 9. 分阶段实施路线

| 阶段 | 实际交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| R0：恢复可信基线 | 现有奖励提示实景复验、第二关自然流程记录、修正后的反打边界证据、固定测试环境 | 现有明确缺陷与关键边界有结论，能稳定完成基线试玩 |
| R1：第二关爽感样板 | 敌群组合与段落节奏调优；广播/连锁的机会布局；关键反馈分级 | 玩家能主动制造清场，空窗与混乱没有因调优恶化 |
| R2：P2 真人门槛 | 外部试玩记录、三个记忆点、理解/操作阻断问题收口 | 满足原总纲 P2 门槛，不以命令结果代替 |
| R3：无尽与构筑深化 | 少数明确流派、过载候选效果试验、章节成长兑现；评估章间结束本局 | 成长可感知、爆发可控，长局稳定，模式与存档隔离通过 |
| R4：狂潮挑战评估 | 满足立项条件后制作一个固定预设短局原型 | 重玩价值与现有模式明显不同，新增维护成本可控 |
| R5：内容与公开试玩 | 按样板逐批生产正式关卡，包体/加载治理、许可交付、外部反馈闭环 | 遵循总纲 P3～P6 原有门槛；30 关长期目标不因本草案被取消或提前凑数 |

以上是推荐顺序，不是已经批准的开发排期。先按验收批次承诺交付，缺少试玩环境与外部参与者时，不虚报日历工期。

### 9.1 第一批具体操作步骤

1. 核对已确认规则与当前源码，冻结基线、设备、分辨率、难度、编队和测试前置。
2. 不带无敌、补敌、补弹等前置，自然玩第二关，记录压力、连杀、空窗、弹药、关键环境操作和结算。
3. 从记录中选一个最影响体验的问题；一次只改变一组主要变量，不同时改敌人血量、玩家伤害、刷新速度和补给。
4. 优先修改已有配置、机会布局或表现层；确需新系统时先写独立执行文档，说明类型、状态、输入和生命周期影响。
5. 执行定向回归、全量、类型检查及所需构建，再重复同条件实景；失败保留证据，不覆盖上一轮记录。
6. 让外部玩家自然体验，收集原话和实际行为，不先告诉玩家“这里应该很爽”。
7. 将保留/回退的改动、验证范围、剩余风险回填 main-goal；确认样板后再拓展范围。

## 10. 验证与观察指标

### 10.1 先记录定义，再判断好坏

以下为原型观察方向，不是当前实测结果，也不是用来代替真人门槛的机械指标。

| 指标 | 记录方式 | 判断用途 |
| --- | --- | --- |
| 首次有效爽点时间 | 从获得战斗控制权到第一次由玩家主动制造的明显多杀/破局 | 判断开局是否等待过久；不能只把第一次弹字当作爽点 |
| 战斗空窗 | 记录战斗段内无有效目标、找尾怪、等待出生的时段；排除菜单、抽卡和主动整理 | 区分必要喘息与无意义等待 |
| 连杀断点 | 记录断连前后的目标、距离、弹药与阶段状态 | 判断断连来自玩家失误还是刷新/资源不连贯 |
| 普通目标击杀时间 | 按武器、敌种和成长阶段，从首次有效命中到死亡分别统计 | 找出不该拖时间的血包，避免只看总 DPS |
| 爆发兑现 | 记录过载/技能收益出现时是否还有合适目标，玩家是否主动推进 | 判断奖励是否只是图标，或确实改变行动 |
| 构筑可描述性 | 中段让玩家用一句话描述这局打法 | 判断成长是否形成身份，而不只是加数值 |
| 主动环境利用 | 记录是否自行发现并使用广播、连锁、危墙、反打 | 区分有意识的操作与偶然触发 |
| 失败可解释性 | 结束后记录玩家认为的主要失败原因，再与录像/状态对照 | 查找不可读伤害与操作误解 |
| 性能与可读性 | 固定设备记录帧时间、FPS、池峰值、capHits，并查看高密度画面 | 保证高潮不以掉帧、遮挡和输入延迟为代价 |

首轮可把“普通战斗段较少出现连续超过 2 秒的无目标空窗”作为调优参考，但必须标明例外段落。性能先与同机基线比较；不能将历史带测试前置的 150 敌压力结果当作所有设备保证。

### 10.2 真人验收

- 建议先邀请 3～5 名非开发参与者，分别记录，不能把多人各说一个点合并成“某位玩家说出三个记忆点”。
- P2 仍要求外部试玩者独立完成一局，并能说出至少三个具体项目记忆点。
- 优先收集“哪段最想再打一次”“哪次强化改变了打法”“哪次死亡没看懂”的原话。
- 若主要反馈仍是找不到操作、看不清危险或不知道为何变强，先修理解与操作问题，不继续加内容。
- 混音、视觉舒适度、手感和重玩意愿必须真人判断，Agent 不代签。

### 10.3 工程验收

- 沿用 V0～V6：静态审阅、规则回归、类型/构建、实景状态、画面、完整流程、真人评价各自留证。
- 自然体验与带前置的边界测试分开；测试前置能够证明边界，不证明正常玩家的成长节奏。
- 覆盖暂停/恢复、抽卡、切枪、死亡、重试、回菜单、下一关与模式切换。
- 新过载必须检查弹药不为负、无重复换弹回调、档位不叠乘、时长不无限刷新、关卡模式不串效果。
- 新结算必须检查奖励只交付一次、纪录不会错误覆盖、旧存档继续可读。
- 浏览器工具受限时保留未验状态，不绕过环境策略，不用源码推断或单张截图伪造流程通过。

## 12. 风险与优化策略

| 风险 | 预警信号 | 控制方式 |
| --- | --- | --- |
| 全程过载导致麻木 | 过载几乎没有结束，常态和爆发无法区分 | 不叠乘、限制刷新，保留可读的常态与爆发差异 |
| 杂兵太脆导致无聊 | 无须走位和选择，只要原地开火 | 用少量战术职责与进攻角度提供威胁，不把全部杂兵重新加厚 |
| 弹药免消耗破坏经济 | 切枪刷满所有弹匣，过载外也不再需要补给 | 只补触发时当前弹匣、不补备用、切枪不重复发放，记录完整弹药变化 |
| 连锁无限放大 | 一次操作长期自动清场，池压力持续上升 | 为派生效果设计明确触发边界，不让每层都获得完整递归收益 |
| 构筑过度保底 | 每局同一组卡，没有选择价值 | 保证有效方向，不保证完全相同的核心组件和顺序 |
| 特效遮挡或掉帧 | 高潮阶段反而最难操作 | 关键预警优先，普通命中降噪，遵守池预算与无障碍设置 |
| 关卡脚本剥夺主动性 | 不操作也自动出现同样的清屏结果 | 提供机会而非代操作，允许替代路线与失败后恢复 |
| 新模式分散资源 | 三套内容均缺完整试玩 | 先验证差异化，只做一个预设原型，不开独立内容生产线 |
| 试验破坏老进度 | 解锁、纪录或六槽编队跨模式串联 | 保留明确模式边界，复核 SaveManager 和完整场景生命周期 |
| 文档再度领先事实 | 配置已存在就被标记“已完成” | 每批记录实现、命令、实景、真人四类状态，未验项目保持未验 |

优化顺序：先移除无意义等待和信息噪声，再强化主动机会，再调整数值，最后才增加系统或内容。不得通过降低危险可读性、无提示伤害或强制无敌门槛来压回玩家成长。

## 13. 批准前需要明确的事项

本草案推荐以下取舍，但不因本次写文档自动生效：

1. 第一批限定第二关样板，不同步改造全部关卡。
2. 保留现有六槽整备；构筑优先围绕主武器形成身份，不先重做装备体系。
3. 无尽过载的免耗弹效果属于后续候选原型，不能直接套用到关卡。
4. 章节主动结算只处理本局分数和纪录，不引入永久数值养成。
5. 狂潮挑战是条件性候选，而非必须立即上线的第三模式。
