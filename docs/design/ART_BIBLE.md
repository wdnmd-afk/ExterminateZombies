# Exterminate Zombies 美术圣经

> 版本：1.0 · 2026-08-12
> 适用范围：P2 垂直切片及后续正式关卡

## 1. 总原则

项目采用统一的俯视像素风。美术资产服务于可读性、反馈和战术判断；不为了填充画面引入未经核对的素材。

## 2. 逻辑像素与缩放

- 游戏逻辑画布：`1280 x 720`。
- 角色、敌人、拾取和场景物使用最近邻采样，禁止双线性缩放。
- 唯一例外是战前整备的角色档案立绘：它由矢量源按渲染倍率栅格化，到画面上始终是降采样，此时最近邻会丢采样点产生锯齿，因此单独使用线性过滤（`GameAssetManager` 内已隔离）。战斗实机精灵不适用本例外。
- 运行时缩放优先使用整数倍；非整数显示由画布 FIT 处理，不改变逻辑碰撞尺寸。
- 推荐源尺寸：角色 32-64px 高、场景物 16-64px、弹体 8-16px；Boss 为普通敌人的 1.8-2.8 倍视觉高度。
- 贴图锚点必须与碰撞体和枪口/受击中心分别核对，不能以视觉中心猜碰撞中心。

## 3. 显示高度白名单

| 类别 | 逻辑显示高度 | 轮廓要求 |
| --- | ---: | --- |
| 玩家 | 38-48px | 头部、持枪手臂与武器三层可辨 |
| 普通感染体 | 28-48px | 身体轮廓与攻击类型有稳定差异 |
| 重装/精英 | 48-64px | 外轮廓厚重，不能遮挡脚下危险区 |
| Boss | 68-96px | 血条、阶段标识、技能预警必须独立可见 |
| 场景物 | 24-64px | 视觉边界与碰撞矩形基本一致 |

## 4. 色彩与阵营

- 玩家与友方弹：明亮黄/青，使用轮廓和弹道区分，不只依赖颜色。
- 敌人：低饱和绿、黄、灰；特殊攻击使用独立预警形状。
- 危险：红、橙和斜纹；Boss 预警允许使用暖红，但不能覆盖 HUD。
- 补给：金黄；强化：青色；生命：红色；地雷：红色状态灯。
- 场景底色保持低对比，为角色、弹体、掉落和警报留出明度差。

## 5. 反馈规则

- 受击闪白只作用于活体主体，不改变武器识别色。
- 暴击使用金色弹体/枪口和金色伤害数字。
- 处决使用红橙色数字、血液粒子和 A 级反馈。
- 穿透使用橙色 `PIERCE` 标签和轨迹，避免与普通霰弹穿透混淆。
- 尸体残影压暗并与活体解耦，不能阻塞波次清场。
- 爆炸、粉尘和危险区使用形状、动画、声音与颜色联合表达。

## 6. UI 与字体

- 战报式布局保留；面板边角保持克制，不引入美漫矢量卡片。
- 中文 UI 使用项目已配置的中文字体回退链；新字体必须通过许可证和缺字检查。
- 字段变长时优先换行或增加行高，不允许覆盖 HUD、按钮或战场。
- 关键提示优先级：玩家受伤/Boss > 武器反馈/爆炸 > 普通击杀/拾取 > 移动/UI。

## 7. 资源治理

- 外部资源必须同时具备来源页、作者、直接下载地址和许可证原文。
- 原始文件放入 `src/assets/downloaded/<type>/<pack>/`，附 `SOURCE.md`、许可证和 SHA-256。
- 派生文件只由 `scripts/` 生成，输出到 `src/assets/processed/`。
- CC-BY/OGA-BY/OFL 资源必须同步 `ATTRIBUTION.md` 与 Credits 页。
- CC-BY-SA/GPL、禁商用、禁修改或来源不明资源默认排除。

## 8. 验收门槛

1. `1280 x 720`、1x/2x 画面中角色、弹体、预警、掉落和 HUD 无明显错位或遮挡。
2. 任何新增场景物都必须同时核对外观、碰撞、阴影和掉落层级。
3. 正式关卡不直接混用未经调色和比例归一的多作者资产。
4. 资产变更必须同步 `docs/ART_ASSET_REGISTRY.md`，并在对应 Goal 执行文档记录验证结果。
