# questions —— 疑难问题排查记录

这个目录放**具体故障的排查过程**，不是功能设计文档，也不是执行记录。

## 为什么单独建这个目录

`docs/execution/` 记录「我们做了什么」，按功能组织；
这里记录「某个 bug 为什么发生、怎么定位到它、修复凭什么算成立」，按故障组织。
两者读者不同：执行文档给的是结论，本目录给的是**可复用的排查路径**。

## 怎么用

再次遇到相似症状时：

1. 按症状找到对应文档，先读「症状」和「判据」两节，确认是不是同一个问题。
2. 是同一个：直接照「怎么复现」跑一遍。**如果照着跑复现不出来，
   或者按文档的修复位置去看代码发现修复还在、症状却依旧存在
   —— 那就说明这份文档的方案对当前故障无效**，别在原方案上打补丁，
   回到「排查过程」一节看当时排除了哪些方向，从没排除的方向重新查。
3. 不是同一个：新建一份文档，别往旧文档里塞第二个故障。

## 每份文档必须包含

| 小节 | 内容 |
| --- | --- |
| 症状 | 玩家侧可观察的现象，以及最初的线索（截图、报错） |
| 判据 | 一句能机器判定的「卡住/正常」表达式，后续回归靠它 |
| 排查过程 | **按时间顺序**，包括走错的方向和排除它的依据 |
| 根因 | 精确到文件、函数、为什么会这样 |
| 修复 | 分层列出，每层解决什么、代价是什么 |
| 验证 | 实测数据，以及「修复前会怎样」的对照 |
| 失效信号 | 什么现象说明这份方案不再管用 |
